Bài 3: Tổng quan các Software Layer chính

Trong kiến trúc AUTOSAR Classic, phần mềm của ECU được tổ chức thành nhiều lớp với trách nhiệm khác nhau. Việc phân chia này giúp tách phần mềm ứng dụng khỏi phần mềm nền tảng và phần cứng bên dưới.

Ở bài này, chúng ta chỉ tập trung vào vai trò tổng quan của các Software Layer và mối quan hệ giữa chúng. Các thành phần bên trong từng layer sẽ được học chi tiết ở những bài sau.

Lưu ý: Bài này chỉ nhằm xây dựng bức tranh tổng thể. Chưa cần ghi nhớ chi tiết từng module, API hay cơ chế giao tiếp bên trong các layer.

1. Các Software Layer chính

Ở mức tổng quan, kiến trúc AUTOSAR Classic có thể được nhìn theo cấu trúc:

Có thể hiểu đơn giản rằng:

  • Application Software: thực hiện chức năng mà ECU cần cung cấp.
  • RTE: tạo môi trường trung gian giữa Application Software và phần mềm nền tảng.
  • Basic Software: cung cấp các dịch vụ nền tảng và khả năng truy cập phần cứng.
  • Hardware: là vi điều khiển và các phần cứng mà phần mềm điều khiển.

2. Application Software Layer

Application Software Layer là nơi chứa logic thực hiện các chức năng của ECU.

Ví dụ, tùy loại ECU, Application Software có thể thực hiện các chức năng như:

  • Điều khiển cửa xe.
  • Điều khiển đèn.
  • Điều khiển cửa sổ.
  • Giám sát trạng thái của hệ thống.
  • Xử lý dữ liệu từ các cảm biến.

Trong AUTOSAR, Application Software được tổ chức thành các Software Component (SWC).

Chi tiết về SWC, Port, Interface, Runnable và Event sẽ được trình bày trong bài học riêng về Application Layer và SWC.

3. Runtime Environment - RTE

RTE (Runtime Environment) nằm giữa Application Software và Basic Software. Nó cung cấp môi trường giao tiếp để các thành phần phần mềm có thể sử dụng các chức năng và dữ liệu mà chúng cần.

Vì vậy, Application Software không cần phải trực tiếp quan tâm đến cách phần mềm nền tảng hoặc phần cứng bên dưới được triển khai.

Có thể hình dung RTE giống như một lớp trung gian giúp kết nối Application Software với phần còn lại của hệ thống.

RTE là một khái niệm quan trọng của AUTOSAR Classic. Cơ chế hoạt động và Virtual Function Bus sẽ được học ở bài riêng sau.

4. Basic Software - BSW

Basic Software (BSW) là phần mềm nền tảng của AUTOSAR. BSW cung cấp những chức năng chung mà Application Software cần sử dụng.

Ở mức tổng quan, BSW bao gồm nhiều nhóm chức năng như:

  • Quản lý hệ thống.
  • Giao tiếp giữa ECU và các ECU khác.
  • Quản lý bộ nhớ.
  • Chẩn đoán.
  • Quản lý vi điều khiển.
  • Truy cập các thiết bị phần cứng.

BSW có thể tiếp tục được chia thành các nhóm lớn như Services Layer, ECU Abstraction, MCAL và Complex Drivers.

Ở bài này chỉ cần hiểu BSW là phần mềm nền tảng. Các thành phần bên trong BSW sẽ được học ở các bài "Chi tiết..." tương ứng.

5. Microcontroller và Hardware

Ở dưới cùng của kiến trúc là Microcontroller và các phần cứng liên quan của ECU.

Microcontroller cung cấp các tài nguyên phần cứng để phần mềm có thể thực hiện công việc, chẳng hạn như:

  • CPU.
  • RAM và Flash.
  • Timer.
  • CAN Controller.
  • ADC.
  • GPIO.
  • Các peripheral khác.

AUTOSAR sử dụng các lớp phần mềm bên trên để hạn chế việc Application Software phải phụ thuộc trực tiếp vào những đặc điểm cụ thể của microcontroller.

6. Mối quan hệ giữa các Layer

Có thể nhìn mối quan hệ giữa các tầng theo hướng từ trên xuống: 

Application Software
        ↓
       RTE
        ↓
Basic Software (BSW)
        ↓
Microcontroller / Hardware

Mỗi tầng có một trách nhiệm chính và cung cấp một mức trừu tượng khác nhau cho tầng phía trên.

Layer Vai trò tổng quan
Application Software Thực hiện chức năng của ECU.
RTE Làm lớp trung gian kết nối Application Software với hệ thống bên dưới.
BSW Cung cấp các dịch vụ nền tảng và khả năng truy cập phần cứng.
Hardware Cung cấp tài nguyên vật lý để ECU thực hiện chức năng.

7. Tại sao cần nhiều Layer?

Việc chia phần mềm thành nhiều layer giúp mỗi phần tập trung vào một trách nhiệm nhất định thay vì để toàn bộ phần mềm phụ thuộc trực tiếp vào phần cứng.

Nếu không phân lớp Khi sử dụng kiến trúc phân lớp
Application dễ phụ thuộc vào hardware. Application được tách khỏi hardware.
Thay đổi hardware có thể ảnh hưởng nhiều code. Các lớp bên dưới có thể thay đổi mà application ít bị ảnh hưởng hơn.
Khó phân chia trách nhiệm giữa các module. Mỗi layer có trách nhiệm rõ ràng hơn.
Khó tái sử dụng phần mềm. Dễ hướng tới việc tái sử dụng các thành phần phần mềm.

8. Ví dụ tổng quan: Điều khiển một chức năng của ECU

Giả sử ECU cần thực hiện một chức năng điều khiển đèn. Ở mức tổng quan, luồng xử lý có thể được hình dung như sau: 

Application Software
        ↓
       RTE
        ↓
       BSW
        ↓
      MCAL
        ↓
     Hardware
        ↓
       Đèn

Application Software quyết định ECU cần làm gì. Các layer bên dưới đảm nhiệm phần hỗ trợ thực hiện chức năng đó và giao tiếp với phần cứng.

Đây chỉ là mô hình khái niệm. Các bước và module thực tế nằm giữa Application và Hardware sẽ được học trong những bài chuyên sâu sau.

9. Ví dụ tổng quan với CAN

Với giao tiếp CAN, có thể hình dung đường đi của dữ liệu ở mức tổng quan: 

Application Software
        ↓
       RTE
        ↓
   CAN Communication
        ↓
      CAN Driver
        ↓
   CAN Controller
        ↓
      CAN Bus

Điều quan trọng ở bài này là nhận ra rằng CAN communication nằm trong phần mềm nền tảng của AUTOSAR, thay vì phải xử lý trực tiếp trong Application Software.

Các module cụ thể của CAN Stack sẽ được học ở những bài chuyên biệt sau.

10. Các ý chính cần nhớ

Khái niệm Cần nhớ
Application Software Chứa logic và chức năng của ECU.
RTE Lớp trung gian giữa Application Software và BSW.
BSW Cung cấp các dịch vụ nền tảng cho ECU.
MCAL Là phần của BSW có vai trò trừu tượng hóa và truy cập các chức năng của microcontroller.
Hardware Cung cấp tài nguyên vật lý cho ECU.

Tóm tắt

Kiến trúc AUTOSAR Classic tổ chức phần mềm ECU thành các tầng chính: Application Software, RTE và Basic Software, bên dưới là Microcontroller/Hardware. Application tập trung vào chức năng của ECU, RTE đóng vai trò trung gian, BSW cung cấp các dịch vụ nền tảng, còn Hardware cung cấp tài nguyên vật lý. Việc phân lớp giúp giảm sự phụ thuộc giữa Application Software và phần cứng, đồng thời tạo ra kiến trúc dễ tổ chức và tái sử dụng hơn.
