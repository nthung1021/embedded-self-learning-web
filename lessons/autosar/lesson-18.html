Bài 18: ECU State và System Services

Một ECU không chỉ cần Application Software, Communication Stack hay Memory Stack. ECU còn cần một nhóm dịch vụ nền để quản lý toàn bộ vòng đời hoạt động của hệ thống.

ECU phải biết khi nào khởi động, khi nào Application được phép chạy, khi nào Communication được bật, khi nào cần chuyển sang Sleep và khi nào phải thực hiện Shutdown. Trong quá trình đó, các System Services như OS, Watchdog, Diagnostic và các dịch vụ quản lý hệ thống cung cấp nền tảng để ECU hoạt động ổn định.

Phạm vi bài học: Bài này đi sâu vào ECU State, ECU State Management và các System Services quan trọng trong AUTOSAR Classic. Trọng tâm là vòng đời ECU, quan hệ giữa ECU State và BSW/Application, cùng cách các System Services hỗ trợ hệ thống. Chưa đi sâu vào API hoặc cấu hình ARXML cụ thể.

1. ECU State là gì?

ECU State mô tả trạng thái hoạt động hiện tại của ECU. Tùy kiến trúc hệ thống, ECU có thể trải qua nhiều trạng thái khác nhau trong vòng đời của nó.

Một mô hình đơn giản: 

Power Off
    |
    v
Startup
    |
    v
Run
    |
    +---------> Sleep
    |             |
    |             v
    |          Wake-up
    |             |
    |             v
    +---------- Run
    |
    v
Shutdown
    |
    v
Power Off

Điều quan trọng là Application không tự ý quyết định toàn bộ vòng đời của ECU. Các thành phần System/ECU Management phối hợp để điều khiển những chuyển đổi trạng thái này.

2. Vì sao ECU cần State Management?

Một ECU có rất nhiều Software Component và BSW module. Nếu mỗi module tự quyết định khi nào được khởi động hoặc dừng, hệ thống sẽ rất khó kiểm soát.

Ví dụ: 

Application
     |
     +---- Communication
     |
     +---- Memory
     |
     +---- Diagnostic
     |
     +---- Watchdog
     |
     +---- OS

Tất cả các thành phần này cần được khởi tạo và điều phối theo một trình tự phù hợp.

ECU State Management giúp tạo ra một trạng thái hệ thống thống nhất để các thành phần biết ECU đang ở giai đoạn nào.

   +---- Memory
   |

Vì vậy khi phân tích ECU startup, cần nhìn toàn bộ Software Stack thay vì chỉ nhìn Application.

8. Run State

Run là trạng thái ECU đang thực hiện các chức năng chính. 

+-----------------------------+
|            RUN              |
|                             |
| Application                 |
| Communication              |
| Diagnostics                |
| Memory Services            |
| OS Tasks                   |
| Watchdog                   |
+-----------------------------+

Trong trạng thái này, các SWC và BSW module được thực thi theo cấu hình và yêu cầu của hệ thống.

9. Sleep State

Với một số ECU, khi không cần hoạt động đầy đủ, hệ thống có thể chuyển sang trạng thái Sleep hoặc Low Power.

Mục tiêu chính là giảm mức tiêu thụ năng lượng. 

RUN
 |
 | No longer needed
 v
Sleep
 |
 | Reduced activity
 v
Low Power

Trong Sleep, không phải tất cả Software Component đều tiếp tục hoạt động giống như khi Run.

10. Wake-up

ECU có thể cần thức dậy khi xảy ra một sự kiện.

Ví dụ:

  • Nhận tín hiệu từ CAN.
  • Thay đổi trạng thái hệ thống.
  • Tín hiệu từ một Hardware input.
  • Timer hoặc sự kiện hệ thống.
Sleep
  |
  | Wake-up Event
  v
Wake-up Handling
  |
  v
Initialize / Restore
  |
  v
Run

11. Shutdown

Shutdown là quá trình ECU chuyển từ trạng thái hoạt động sang trạng thái không hoạt động hoặc chuẩn bị mất nguồn. 

Run
 |
 v
Shutdown Request
 |
 +---- Stop Application activities
 |
 +---- Finish required Communication
 |
 +---- Save persistent data
 |
 +---- Stop Services
 |

Power Off / Sleep

Shutdown không đơn giản là tắt CPU ngay lập tức. Một số dữ liệu hoặc trạng thái có thể cần được xử lý trước.

14. ECU State và RTE

RTE là cầu nối giữa Application và BSW. Vì vậy trạng thái của ECU ảnh hưởng đến khả năng hoạt động của Application.

Một SWC chỉ nên thực hiện các chức năng phù hợp với trạng thái hệ thống hiện tại.

15. System Services là gì?

System Services là nhóm dịch vụ nền cung cấp các chức năng dùng chung cho nhiều thành phần trong ECU.

Một số nhóm quan trọng:

  • Operating System.
  • Watchdog.
  • ECU State Management.
  • Diagnostic Services.
  • Communication Services.
  • Memory Services.
  • Time-related Services.
  • Development / Error Handling Services.

16. Tại sao cần System Services?

Nếu mỗi Application tự triển khai các chức năng nền như scheduling, watchdog, memory management và error handling, phần mềm sẽ bị trùng lặp và khó quản lý. 

Without System Services:

SWC A -> Own Timer
SWC B -> Own Scheduler
SWC C -> Own Error Handling
SWC D -> Own Watchdog Logic

        |
        v

Complexity tăng

System Services cung cấp các chức năng dùng chung: 

             System Services
                    |
       +------------+------------+
       |            |            |
       v            v            v
      SWC A        SWC B        SWC C

17. Operating System

OS là một trong những System Services quan trọng nhất trong AUTOSAR Classic.

OS cung cấp nền tảng để quản lý việc thực thi các Task, scheduling, timing và các cơ chế đồng bộ.

                  |
       +----------+----------+
       |          |          |
       v          v          v
    Task A     Task B     Task C
       |          |          |
       v          v          v
     SWC /      SWC /      BSW /
     BSW        BSW        Services

20. OS và Priority

Khi nhiều Task cần chạy, hệ thống cần có cơ chế quyết định Task nào được thực thi trước. 

Task A   Priority = High
Task B   Priority = Medium
Task C   Priority = Low

Priority là một phần quan trọng của scheduling. Task quan trọng hoặc có yêu cầu thời gian nghiêm ngặt có thể cần được ưu tiên phù hợp.

21. Timing và OS

Embedded System thường có yêu cầu timing rõ ràng.

Ví dụ: 

Runnable A -> every 10 ms
Runnable B -> every 100 ms
Runnable C -> event triggered

OS và các cơ chế timing giúp đảm bảo các hoạt động này được kích hoạt theo kiến trúc của hệ thống.

22. Watchdog

Watchdog là cơ chế giúp phát hiện trường hợp Software không còn hoạt động đúng như mong đợi.

Ý tưởng đơn giản: 

Software
   |
   | Periodically alive
   v
Watchdog
   |
   +---- Alive -> Continue
   |
   +---- No response -> Fault Handling

Nếu phần mềm bị treo hoặc không thực hiện được một hoạt động cần thiết, Watchdog có thể phát hiện tình trạng bất thường và hệ thống có thể thực hiện một hành động phục hồi phù hợp.

38. Debugging khi ECU không vào Run State

Nếu ECU không thể chuyển sang Run, có thể kiểm tra theo thứ tự:

  1. Power và Hardware có hoạt động không?
  2. MCU có khởi động không?
  3. MCAL có initialize thành công không?
  4. OS có start không?
  5. Các BSW Services quan trọng có sẵn sàng không?
  6. Communication có initialize thành công không?
  7. Memory initialization có thành công không?
  8. RTE có sẵn sàng không?
  9. Application có được phép chạy không?
  10. ECU State Management có nhận được điều kiện chuyển trạng thái không?

49. Tóm tắt

ECU State và System Services chịu trách nhiệm tạo ra nền tảng vận hành cho toàn bộ ECU. ECU không chỉ đơn giản là chạy Application liên tục mà phải quản lý nhiều trạng thái như Startup, Run, Sleep, Wake-up và Shutdown.

Một flow đơn giản: 

Power On
    -> Startup
    -> Run
    -> Sleep
    -> Wake-up
    -> Run
    -> Shutdown
    -> Power Off

Trong quá trình đó, ECU State Management phối hợp với nhiều System Services: 

                    ECU State Management
                             |
       +---------------------+---------------------+
       |          |          |          |          |
       v          v          v          v          v
      OS      Watchdog   Diagnostic  Memory   Communication
       |          |          |          |          |
       +----------+----------+----------+----------+
                             |
                             v
                        Application

Ba ý quan trọng cần nhớ:

  • ECU State Management điều phối vòng đời và trạng thái hoạt động của ECU.
  • System Services cung cấp các chức năng nền dùng chung như OS, Watchdog, Diagnostic, Memory, Communication và Timing.
  • Các System Services không thay thế Application Logic; chúng cung cấp nền tảng để Application và BSW hoạt động đúng, ổn định và có tổ chức.

Khi phân tích một ECU, hãy luôn đặt câu hỏi: ECU đang ở State nào, State tiếp theo là gì, điều kiện chuyển State là gì và những System Services nào tham gia vào quá trình đó.
