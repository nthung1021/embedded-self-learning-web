Bài 9: Tổng quan Communication Stack

Trong một ECU, Application Software không chỉ xử lý dữ liệu nội bộ mà còn cần trao đổi dữ liệu với các ECU khác thông qua mạng xe như CAN, LIN hoặc Ethernet.

Để thực hiện việc truyền và nhận dữ liệu một cách có cấu trúc, AUTOSAR sử dụng một nhóm các software module được gọi chung là Communication Stack.

Phạm vi bài học: Bài này chỉ tập trung vào khái niệm và cấu trúc tổng quan của Communication Stack trong AUTOSAR Classic. Các module cụ thể như COM, PduR, CanIf, CanTp và CAN Driver sẽ được tìm hiểu chi tiết ở các bài sau.

1. Communication Stack là gì?

Communication Stack là tập hợp các software module chịu trách nhiệm hỗ trợ việc trao đổi dữ liệu giữa ECU với các phần khác trong hệ thống.

Dữ liệu có thể được truyền theo hai hướng:

  • Transmit (TX): ECU gửi dữ liệu ra mạng.
  • Receive (RX): ECU nhận dữ liệu từ mạng.

Communication Stack tạo ra một chuỗi xử lý trung gian giữa Application Software và phần cứng giao tiếp của ECU.

2. Communication Stack nằm ở đâu?

Communication Stack chủ yếu nằm trong tầng Basic Software (BSW).

Nhìn ở mức tổng quan, luồng giao tiếp có thể hình dung như sau: 

+--------------------------------------+
|       Application Software           |
|              SWC                     |
+------------------+-------------------+
                   |
                   | RTE
                   v
+--------------------------------------+
|       Communication Stack            |
|                                      |
|   COM / PduR / Interface / Driver    |
+------------------+-------------------+
                   |
                   v
+--------------------------------------+
|       Communication Hardware         |
|       CAN / LIN / Ethernet           |
+--------------------------------------+

Vì vậy, Application Software không cần trực tiếp điều khiển CAN Controller hoặc các phần cứng giao tiếp.

3. Tại sao cần Communication Stack?

Nếu Application Software phải trực tiếp xử lý phần cứng mạng, mỗi ứng dụng sẽ phải biết rất nhiều chi tiết về giao tiếp. Điều này làm phần mềm khó phát triển, khó bảo trì và khó tái sử dụng.

Communication Stack giúp tách Application Software khỏi các chi tiết của communication hardware.

Một số lợi ích chính:

  • Tách Application Software khỏi phần cứng giao tiếp.
  • Chuẩn hóa cách các software module trao đổi dữ liệu.
  • Hỗ trợ nhiều loại communication protocol.
  • Giúp các software module có thể được tái sử dụng dễ dàng hơn.
  • Phân chia rõ trách nhiệm giữa Application và BSW.

4. Các nhóm thành phần chính

Ở mức tổng quan, Communication Stack có thể được chia thành nhiều lớp hoặc nhóm module khác nhau.

Đây là cách nhìn đơn giản hóa để hiểu hướng đi của dữ liệu. Không phải mọi loại communication đều sử dụng chính xác cùng một tập module.

5. Communication Services

Ở phía trên của Communication Stack là các thành phần cung cấp communication services cho Application Software.

Một thành phần quan trọng là COM. Ở mức tổng quan, COM giúp Application Software trao đổi dữ liệu thông qua các cơ chế communication của AUTOSAR thay vì phải trực tiếp làm việc với CAN Controller hoặc hardware.

Có thể hiểu đơn giản: 

Application
     |
     |  "Tôi muốn gửi dữ liệu"
     v
    RTE
     |
     v
    COM
     |
     v
Communication Stack
     |
     v
Network

Các khái niệm chi tiết như Signal, I-PDU và cách COM xử lý dữ liệu sẽ được tìm hiểu riêng ở các bài chuyên sâu hơn.

6. PDU Router

PduR (PDU Router) có vai trò định tuyến dữ liệu giữa các communication module.

Có thể hình dung PduR như một điểm trung gian quyết định dữ liệu cần được chuyển tiếp đến module communication nào. 

       COM
        |
        v
      +-----+
      | PduR|
      +-----+
       /   \
      /     \
     v       v
  CanIf     LinIf

Nhờ đó, các module phía trên không cần phải phụ thuộc trực tiếp vào từng communication interface cụ thể.

7. Communication Interface

Communication Interface nằm giữa các thành phần communication phía trên và communication driver phía dưới.

Ví dụ với CAN, một interface quan trọng là CanIf. 

       Communication Services
                 |
                 v
                PduR
                 |
                 v
               CanIf
                 |
                 v
              CanDrv
                 |
                 v
           CAN Controller

Interface giúp các tầng phía trên không cần trực tiếp làm việc với các chi tiết thấp của CAN Controller.

Tương tự, các communication technology khác có thể có interface tương ứng.

8. Communication Driver

Communication Driver là phần mềm nằm gần phần cứng giao tiếp hơn trong stack.

Ví dụ:

  • CAN Driver: giao tiếp với CAN Controller.
  • LIN Driver: giao tiếp với LIN Controller.
  • Ethernet Driver: hỗ trợ giao tiếp với phần cứng Ethernet.

Ở mức tổng quan, driver chịu trách nhiệm cung cấp cách thức software giao tiếp với communication hardware.

Các chi tiết như Controller, Transceiver, HTH, HRH hay các API của CAN Driver sẽ được tìm hiểu trong các bài học chuyên sâu.

9. Luồng truyền dữ liệu TX

Khi Application muốn gửi dữ liệu đến một ECU khác, dữ liệu có thể đi qua Communication Stack theo hướng từ trên xuống.

    COM

Mỗi thành phần thực hiện một phần trách nhiệm khác nhau. Application tập trung vào chức năng của hệ thống, trong khi Communication Stack xử lý việc đưa dữ liệu ra communication network.

Application chỉ nhận dữ liệu ở mức phù hợp với chức năng của nó, thay vì phải trực tiếp xử lý các chi tiết của CAN Controller.

11. Communication Stack và nhiều loại Network

Một ECU có thể sử dụng nhiều communication technology khác nhau. Ví dụ:

  • CAN
  • LIN
  • Ethernet

Ở mức kiến trúc, Application có thể vẫn giữ được sự tách biệt tương đối với communication hardware. 

                 Application
                      |
                     RTE
                      |
             Communication Layer
                      |
          +-----------+-----------+
          |           |           |
        CAN          LIN      Ethernet
          |           |           |
       CAN HW      LIN HW    Ethernet HW

Đây là một trong những ý tưởng quan trọng của AUTOSAR: tách chức năng ứng dụng khỏi chi tiết triển khai phần cứng và communication.

Giả sử một ECU cần nhận thông tin tốc độ xe từ một ECU khác thông qua CAN.

Ở mức tổng quan, luồng dữ liệu có thể được mô tả:

  |  Speed data

CAN Driver

  v

Application SWC cuối cùng có thể sử dụng thông tin tốc độ để thực hiện một chức năng khác, ví dụ điều khiển hiển thị hoặc xử lý logic của ECU.

Application không cần biết toàn bộ chi tiết về cách dữ liệu được truyền qua CAN Bus.

13. Communication Stack và kiến trúc AUTOSAR

Communication Stack là một ví dụ rõ ràng cho cách AUTOSAR phân chia trách nhiệm giữa các tầng. 

+--------------------------------------+
|        Application Software          |
|              SWC                     |
+--------------------------------------+
                 |
                 v
+--------------------------------------+
|                 RTE                  |
+--------------------------------------+
                 |
                 v
+--------------------------------------+
|      Communication Stack             |
|                                      |
| COM → PduR → Interface → Driver      |
+--------------------------------------+
                 |
                 v
+--------------------------------------+
|        Communication Hardware       |
|        CAN / LIN / Ethernet          |
+--------------------------------------+

Nhìn theo hướng này, ta có thể thấy:

  • Application: thực hiện chức năng của ECU.
  • RTE: cung cấp môi trường giao tiếp giữa Application và BSW.
  • Communication Stack: xử lý việc trao đổi dữ liệu qua network.
  • Hardware: thực hiện việc truyền và nhận tín hiệu vật lý.

14. Communication Stack cần nhớ những gì?

Khi mới học AUTOSAR, không cần ghi nhớ ngay tất cả các module và API. Trước tiên nên hiểu các ý chính sau:

  • Communication Stack nằm chủ yếu trong BSW.
  • Nó tạo cầu nối giữa Application và communication hardware.
  • Dữ liệu TX đi từ Application xuống hardware.
  • Dữ liệu RX đi từ hardware lên Application.
  • COM, PduR, Communication Interface và Communication Driver có những trách nhiệm khác nhau trong stack.
  • Application không nên phụ thuộc trực tiếp vào chi tiết của CAN/LIN/Ethernet hardware.
  • Communication Stack giúp kiến trúc phần mềm có tính module hóa và dễ tái sử dụng hơn.

15. Tóm tắt

Communication Stack là nhóm các software module trong AUTOSAR BSW hỗ trợ ECU truyền và nhận dữ liệu qua các communication network.

Luồng dữ liệu tổng quát có thể hình dung: 

Application
    ↕
   RTE
    ↕
   COM
    ↕
   PduR
    ↕
Communication Interface
    ↕
Communication Driver
    ↕
Communication Hardware
    ↕
 CAN / LIN / Ethernet Network

Điều quan trọng nhất cần nhớ là Communication Stack giúp tách Application Software khỏi các chi tiết của communication hardware, đồng thời chia quá trình truyền nhận dữ liệu thành các tầng có trách nhiệm rõ ràng.
