Bài 17: Chi tiết Memory Stack

Trong một ECU automotive, phần mềm không chỉ cần xử lý dữ liệu trong RAM mà còn phải lưu giữ những thông tin cần thiết qua các lần reset hoặc tắt nguồn. Ví dụ như cấu hình, trạng thái, dữ liệu học được hoặc thông tin cần được giữ lại sau khi ECU khởi động lại.

Memory Stack trong AUTOSAR cung cấp kiến trúc phần mềm để Application và các BSW module có thể truy cập bộ nhớ một cách có tổ chức, đồng thời giảm sự phụ thuộc trực tiếp vào loại memory và hardware cụ thể.

Phạm vi bài học: Bài này tập trung vào kiến trúc Memory Stack, sự khác nhau giữa RAM và non-volatile memory, vai trò của NVRAM Manager, Memory Abstraction và Memory Hardware Abstraction, cùng với luồng đọc/ghi dữ liệu. Chưa đi sâu vào API cụ thể, cấu hình module hoặc ARXML.

1. Memory Stack là gì?

Memory Stack là tập hợp các lớp và module phần mềm giúp hệ thống AUTOSAR quản lý việc lưu trữ dữ liệu trong bộ nhớ.

Có thể hình dung đơn giản: 

Application / BSW
        |
        v
   Memory Services
        |
        v
 Memory Abstraction
        |
        v
   Memory Driver
        |
        v
     Hardware

Mục tiêu quan trọng của kiến trúc này là Application không cần trực tiếp biết chi tiết phần cứng memory đang được sử dụng.

2. Vì sao ECU cần Memory Stack?

ECU cần lưu trữ nhiều loại dữ liệu khác nhau. Một số dữ liệu chỉ cần tồn tại trong thời gian ECU đang chạy, trong khi một số dữ liệu phải tồn tại sau khi ECU mất nguồn.

Ví dụ:

  • Biến runtime.
  • Trạng thái hệ thống.
  • Cấu hình ECU.
  • Giá trị calibration.
  • Dữ liệu học được.
  • Thông tin diagnostic cần lưu lại.
  • Thông tin lỗi hoặc trạng thái hệ thống.

Nếu tất cả dữ liệu đều chỉ được lưu trong RAM, dữ liệu sẽ mất khi ECU mất nguồn. 

ECU đang chạy
     |
     v
    RAM
     |
     X
Power Off
     |
     v
Dữ liệu runtime mất

Vì vậy hệ thống cần non-volatile memory để giữ lại những dữ liệu cần thiết.

3. Volatile và Non-Volatile Memory

Đây là sự phân biệt cơ bản nhất khi học Memory Stack.

Loại Đặc điểm Dữ liệu sau Power Off
Volatile Memory Cần nguồn để giữ dữ liệu Thông thường mất
Non-Volatile Memory Có thể giữ dữ liệu không cần nguồn liên tục Được giữ lại

RAM thường được sử dụng cho dữ liệu runtime, trong khi Flash hoặc EEPROM có thể được sử dụng cho dữ liệu cần lưu trữ lâu dài.

4. RAM là gì?

RAM là bộ nhớ được sử dụng rất nhiều trong quá trình ECU đang hoạt động.

Ví dụ: 

ECU Running

Application
    |
    v
Runtime Variable
    |
    v
RAM

Các biến runtime, buffer và dữ liệu tạm thời thường được đặt trong RAM.

Khi ECU bị mất nguồn, nội dung RAM thông thường không được đảm bảo sẽ còn nguyên.

5. ROM và Flash

ROM là khái niệm dùng để chỉ bộ nhớ không mất dữ liệu khi mất nguồn. Trong ECU hiện đại, Flash thường được sử dụng rộng rãi để lưu chương trình và dữ liệu không mất nguồn.

Flash có thể được sử dụng cho:

  • Firmware.
  • Calibration data.
  • Cấu hình.
  • Dữ liệu persistent.

Tuy nhiên, cách sử dụng cụ thể phụ thuộc vào kiến trúc ECU và loại memory hardware.

6. EEPROM

EEPROM cũng là một loại non-volatile memory. Nó có thể được sử dụng để lưu dữ liệu cần giữ lại sau khi ECU mất nguồn.

Ví dụ: 

ECU Configuration
       |
       v
    EEPROM
       |
       | Power Off
       v
    Data remains

Trong các hệ thống khác nhau, EEPROM có thể tồn tại dưới dạng memory riêng hoặc được mô phỏng bằng một vùng Flash.

7. NVRAM là gì?

NVRAM là khái niệm quan trọng trong AUTOSAR. NVRAM có thể hiểu là vùng dữ liệu cần được duy trì qua các lần reset hoặc mất nguồn.

Ví dụ: 

ECU chạy
   |
   v
Persistent Data
   |
   v
NVRAM
   |
   X
Power Off
   |
   v
ECU Restart
   |
   v
Persistent Data được khôi phục

Trong AUTOSAR, việc quản lý dữ liệu non-volatile thường được thực hiện thông qua các module thuộc NVRAM Manager và các lớp Memory Abstraction phía dưới.

9. NVRAM Manager - NvM

NvM, hay NVRAM Manager, là một module quan trọng ở phía trên của Memory Stack.

Nó cung cấp cơ chế quản lý các dữ liệu cần được lưu trữ trong non-volatile memory. 

Application / BSW
        |
        v
       NvM
        |
        v
     MemIf
        |
        v
 Memory Driver
        |
        v
     NVRAM

Application không nhất thiết phải trực tiếp điều khiển Flash hoặc EEPROM.

10. NvM Block

Một khái niệm rất quan trọng là NvM Block.

Dữ liệu được quản lý bởi NvM thường được tổ chức thành các block logic. 

                NvM
                 |
       +---------+---------+
       |         |         |
       v         v         v
    Block A   Block B   Block C

    Config    Counter    Learned Data

Mỗi block có thể đại diện cho một nhóm dữ liệu cần được quản lý và lưu trữ.

11. Vì sao cần NvM Block?

Nếu Application trực tiếp quản lý toàn bộ memory address, phần mềm sẽ trở nên phụ thuộc mạnh vào Hardware.

Thay vào đó, Application có thể nghĩ theo logic: 

"Tôi cần lưu dữ liệu cấu hình"
              |
              v
          NvM Block
              |
              v
       Memory Stack
              |
              v
       Physical Memory

Điều này giúp tách dữ liệu logic khỏi địa chỉ vật lý của memory.

12. RAM Block và ROM Block

Khi làm việc với NvM, có thể gặp khái niệm dữ liệu RAM, ROM và NV liên quan đến một block. 

             NvM Block
                 |
        +--------+--------+
        |        |        |
        v        v        v
      RAM      ROM       NV
    Runtime   Default   Persistent
    copy      value     storage

Có thể hiểu đơn giản:

  • RAM: bản dữ liệu đang được sử dụng trong runtime.
  • ROM: giá trị mặc định hoặc giá trị khởi tạo.
  • NV: dữ liệu được lưu trong non-volatile memory.

15. MemIf là gì?

MemIf là Memory Abstraction Interface. Nó nằm giữa NvM và các lớp memory abstraction phía dưới. 

        NvM
         |
         v
       MemIf
       /   \
      v     v
    Fee     Ea
     |       |
     v       v
   Flash   EEPROM

MemIf giúp NvM không cần phụ thuộc trực tiếp vào một loại memory abstraction cụ thể.

16. Fee là gì?

Fee là Flash EEPROM Emulation. Nó cung cấp một abstraction để sử dụng Flash theo cách phù hợp với mô hình EEPROM-like storage.

Có thể hình dung: 

          NvM
           |
           v
         MemIf
           |
           v
          Fee
           |
           v
      Flash Driver
           |
           v
         Flash

Điều này đặc biệt hữu ích khi ECU không có EEPROM vật lý nhưng cần cơ chế lưu dữ liệu non-volatile giống EEPROM.

17. Ea là gì?

Ea là EEPROM Abstraction. Nó cung cấp lớp abstraction cho EEPROM phía dưới. 

          NvM
           |
           v
         MemIf
           |
           v
           Ea
           |
           v
     EEPROM Driver
           |
           v
         EEPROM

Vì vậy, Fee và Ea đều có thể nằm bên dưới MemIf, nhưng phục vụ các loại memory khác nhau.

18. Fee và Ea khác nhau

Module Vai trò Memory phía dưới
Fee EEPROM Emulation Flash
Ea EEPROM Abstraction EEPROM

Đây là một distinction quan trọng khi đọc Memory Stack của một ECU.

Persistence có nghĩa là dữ liệu tiếp tục tồn tại sau khi ECU restart hoặc mất nguồn, tùy theo yêu cầu của hệ thống.

24. Runtime Data và Persistent Data

Runtime Data Persistent Data
Thường nằm trong RAM Được lưu trong non-volatile memory

Ví dụ: temporary state Ví dụ: learned configuration

25. Khi nào không nên ghi Flash liên tục?

Non-volatile memory không phải là nơi nên ghi dữ liệu liên tục cho mọi thay đổi nhỏ.

Ví dụ không hợp lý: 

Sensor update: mỗi 10 ms
        |
        v
Write Flash
        |
        v
Write Flash
        |
        v
Write Flash
        |
       ...

Việc ghi quá thường xuyên có thể gây vấn đề về hiệu năng và endurance của memory.

Vì vậy kiến trúc thực tế cần cân nhắc:

  • Tần suất ghi.
  • Khi nào dữ liệu thực sự cần persistent.
  • Chiến lược lưu dữ liệu.
  • Endurance của memory.
  • Thời gian ghi.

27. Data Consistency

Một vấn đề khác là dữ liệu phải nhất quán.

Nếu không có cơ chế phù hợp, dữ liệu có thể bị hỏng hoặc không còn ở trạng thái mong muốn.

Vì vậy thiết kế Memory Stack cần quan tâm đến các vấn đề như:

  • Data integrity.
  • Consistency.
  • Default value.
  • Recovery.
  • Invalid data detection.

49. Tóm tắt


            


                

                    Memory Stack là phần kiến trúc AUTOSAR giúp quản lý việc
                    lưu trữ dữ liệu từ Application/BSW xuống Memory Hardware.
                    Nó đặc biệt quan trọng đối với các dữ liệu cần tồn tại
                    qua reset hoặc power cycle.
                


                

                    Luồng ghi dữ liệu cơ bản:
                


                
Application / BSW
    -> NvM
    -> MemIf
    -> Fee / Ea
    -> Memory Driver
    -> Flash / EEPROM



                

                    Luồng đọc dữ liệu:
                


                
Flash / EEPROM
    -> Memory Driver
    -> Fee / Ea
    -> MemIf
    -> NvM
    -> Application / BSW



                

                    Ba điểm quan trọng cần nhớ:
                


                
    
                    
  • 
                        NvM quản lý dữ liệu persistent ở mức logical
                        thông qua các NvM Block.
                    
    • 
                    
  • 
                        MemIf và Fee/Ea tạo abstraction giữa
                        NVRAM management và loại memory cụ thể.
                    
    • 
                    
  • 
                        Memory Driver nằm gần Hardware và chịu
                        trách nhiệm giao tiếp với Flash hoặc EEPROM.
                    
    • 
                


                

                    Khi debug Memory Stack, hãy xác định dữ liệu thuộc loại nào,
                    đi qua block nào, qua từng abstraction layer nào và cuối cùng
                    có thực sự được ghi hoặc đọc đúng từ Memory Hardware hay không.
