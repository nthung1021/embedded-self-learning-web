Bài 4: Tổng quan tầng Application Software

Application Software Layer là tầng nằm trên cùng trong kiến trúc AUTOSAR Classic. Đây là nơi chứa các phần mềm thực hiện những chức năng nghiệp vụ của ECU.

Nếu ở Bài 3 chúng ta nhìn toàn bộ kiến trúc từ trên xuống dưới, thì bài này tập trung riêng vào câu hỏi: Application Software là gì, chứa những gì và đóng vai trò như thế nào?

Lưu ý: Bài này chỉ tập trung vào tổng quan. Các khái niệm như SWC, Port, Interface, Runnable và Event sẽ được tìm hiểu chi tiết ở các bài chuyên sâu sau.

1. Application Software là gì?

Application Software là phần mềm chứa logic chức năng của ECU. Nó quyết định ECU cần thực hiện chức năng gì dựa trên dữ liệu đầu vào và trạng thái của hệ thống.

Ví dụ, một ECU thân xe có thể chứa các chức năng:

  • Điều khiển đèn.
  • Điều khiển khóa cửa.
  • Điều khiển cửa sổ.
  • Giám sát trạng thái cửa.
  • Xử lý trạng thái đánh lửa.
  • Giám sát một số điều kiện của xe.

Như vậy, Application Software tập trung vào “ECU cần làm gì”, thay vì tập trung vào “phần cứng thực hiện nó như thế nào”.

2. Application Software nằm ở đâu?

Application Software nằm ở phía trên của kiến trúc AUTOSAR Classic:

Application Software không nằm trực tiếp trên phần cứng. Nó sử dụng các lớp bên dưới để giao tiếp với phần còn lại của ECU.

3. Application Software được tổ chức như thế nào?

Trong AUTOSAR, Application Software không được tổ chức thành một khối duy nhất. Nó được chia thành các Software Component (SWC).

Có thể hình dung: 

Application Software
        │
        ├── Software Component A
        │
        ├── Software Component B
        │
        └── Software Component C

Mỗi SWC có thể đảm nhiệm một chức năng hoặc một phần chức năng của hệ thống. Cách tổ chức này giúp phần mềm được chia thành những thành phần có trách nhiệm tương đối rõ ràng.

SWC là một trong những khái niệm quan trọng nhất khi học Application Layer. Cấu trúc bên trong SWC sẽ được học chi tiết ở bài sau.

4. Ví dụ về các Software Component

Giả sử một ECU điều khiển thân xe có các chức năng liên quan đến cửa:

Software Component Chức năng tổng quan
Door Control SWC Xử lý logic điều khiển cửa.
Window Control SWC Xử lý chức năng điều khiển cửa sổ.
Door Status SWC Xử lý thông tin trạng thái cửa.
Lighting Control SWC Xử lý logic điều khiển đèn.

Đây chỉ là ví dụ minh họa. Cách chia SWC thực tế phụ thuộc vào thiết kế của hệ thống và yêu cầu của dự án.

5. Application Software nhận và sử dụng dữ liệu như thế nào?

Application Software thường cần dữ liệu từ nhiều nguồn khác nhau để thực hiện chức năng. Ví dụ, một SWC có thể cần thông tin về:

  • Trạng thái công tắc.
  • Tốc độ xe.
  • Trạng thái cửa.
  • Thông tin nhận từ mạng CAN.
  • Dữ liệu từ cảm biến.

Ở mức tổng quan, Application Software không cần biết tất cả dữ liệu này được lấy trực tiếp từ phần cứng bằng cách nào. Các tầng bên dưới và RTE cung cấp môi trường để Application Software sử dụng dữ liệu. 

Input / Network / Sensor
          ↓
     Software Layer
          ↓
         RTE
          ↓
 Application Software
          ↓
   ECU Function

6. Application Software và RTE

Application Software giao tiếp với các thành phần khác thông qua RTE (Runtime Environment).

Vì vậy, Application Software có thể được nhìn ở mức tổng quan như sau: 

+-----------------------------+
|    Application Software     |
|                             |
|   SWC A    SWC B    SWC C   |
+-------------↓---------------+
              |
             RTE
              |
+-------------↓---------------+
|      Basic Software         |
+-------------↓---------------+
|          Hardware           |
+-----------------------------+

RTE tạo ra ranh giới giữa phần Application và phần mềm nền tảng. Điều này giúp Application Software không phải trực tiếp phụ thuộc vào cách các module BSW được triển khai.

7. Application Software không trực tiếp điều khiển Hardware

Một đặc điểm quan trọng của kiến trúc AUTOSAR là Application Software được tách khỏi Hardware.

Ví dụ, khi Application cần bật một thiết bị: 

Application
     ↓
    RTE
     ↓
    BSW
     ↓
   MCAL
     ↓
  Hardware

Application chỉ tập trung vào logic chức năng, trong khi các tầng bên dưới đảm nhiệm việc cung cấp dịch vụ và truy cập phần cứng.

Đây chính là một trong những ý tưởng quan trọng của kiến trúc AUTOSAR: tách chức năng ứng dụng khỏi việc triển khai phần cứng.

8. Application Software và khả năng tái sử dụng

Việc tách Application Software khỏi Hardware giúp phần mềm ứng dụng có khả năng được tái sử dụng tốt hơn trong những hệ thống có kiến trúc phần cứng khác nhau.

Thiết kế trực tiếp với Hardware Thiết kế theo AUTOSAR
Application phụ thuộc nhiều vào phần cứng. Application được tách khỏi phần cứng thông qua các lớp bên dưới.
Thay đổi hardware có thể ảnh hưởng application. Các thay đổi bên dưới được giới hạn trong các layer liên quan.
Khó tái sử dụng logic. Dễ tổ chức logic thành các Software Component.

9. Ví dụ tổng quan về một chức năng

Giả sử hệ thống cần bật đèn khi nhận được một điều kiện phù hợp. Application Software có thể được hình dung như sau: 

Input:
Trạng thái điều kiện
       ↓
Lighting Control SWC
       ↓
Kiểm tra logic
       ↓
Yêu cầu bật đèn
       ↓
       RTE
       ↓
      BSW
       ↓
    Hardware
       ↓
      Đèn

Điểm quan trọng là Lighting Control SWC chỉ tập trung vào logic điều khiển đèn. Nó không cần chứa toàn bộ code xử lý phần cứng.

10. Những khái niệm cần nhớ

Khái niệm Ý nghĩa tổng quan
Application Software Phần mềm thực hiện các chức năng của ECU.
Software Component (SWC) Đơn vị tổ chức chức năng trong Application Software.
RTE Lớp trung gian giúp Application giao tiếp với hệ thống bên dưới.
Application Logic Logic quyết định ECU cần thực hiện chức năng gì.
Hardware Independence Giảm sự phụ thuộc của Application Software vào phần cứng cụ thể.

Tóm tắt

Application Software Layer là tầng chứa logic chức năng của ECU. Trong AUTOSAR, Application Software được tổ chức thành các Software Component (SWC). Application tập trung vào việc ECU cần thực hiện chức năng gì, trong khi RTE và các tầng BSW bên dưới cung cấp môi trường để thực hiện những chức năng đó. Việc tách Application khỏi Hardware giúp kiến trúc rõ ràng hơn và hỗ trợ khả năng tái sử dụng phần mềm.
