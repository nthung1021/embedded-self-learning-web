Bài 23: AUTOSAR Configuration và ARXML

Trong các bài trước, chúng ta đã tìm hiểu kiến trúc AUTOSAR, Software Component, RTE, BSW, MCAL, Interface và Dependency. Tuy nhiên, kiến trúc đó không tự động trở thành một ECU có thể chạy được.

Các thành phần của AUTOSAR cần được mô tả, kết nối và cấu hình. Đây là vai trò của AUTOSAR Configuration. Một trong những định dạng quan trọng được sử dụng để trao đổi và lưu trữ thông tin cấu hình là ARXML.

Phạm vi bài học: Bài này tập trung giải thích AUTOSAR Configuration và ARXML ở mức kiến trúc và thực tế dự án: configuration dùng để làm gì, ARXML chứa loại thông tin nào, quan hệ giữa ARXML và toolchain, cách configuration đi tới generated code, cũng như cách đọc và debug configuration. Chưa đi sâu vào toàn bộ schema AUTOSAR, từng XML tag hoặc cấu hình cụ thể của một vendor tool.

1. AUTOSAR Configuration là gì?

AUTOSAR Configuration là quá trình xác định các thông tin cần thiết để các thành phần trong hệ thống AUTOSAR biết chúng phải hoạt động và kết nối với nhau như thế nào.

Có thể hiểu đơn giản: 

Architecture
    +
Configuration
    +
Implementation
    ↓
ECU Software có thể chạy

Architecture trả lời câu hỏi "hệ thống được thiết kế như thế nào?", còn Configuration trả lời nhiều câu hỏi cụ thể hơn như "component nào kết nối với component nào?", "driver nào được sử dụng?" và "các thông số hoạt động là gì?"

2. Vì sao AUTOSAR cần Configuration?

Một ECU AUTOSAR có rất nhiều thành phần:

  • Software Components.
  • Interfaces.
  • RTE.
  • BSW Modules.
  • Communication Stack.
  • Memory Stack.
  • Diagnostic Stack.
  • MCAL Drivers.
  • Operating System.
  • Microcontroller và hardware.

Nếu mỗi thành phần tự quyết định cách kết nối với các thành phần khác, hệ thống sẽ rất khó quản lý.

Configuration giúp biến kiến trúc tổng quát thành một cấu hình cụ thể cho một ECU hoặc một project.

3. Configuration không phải là Source Code

Đây là một điểm quan trọng. Configuration mô tả hệ thống phải được cấu hình như thế nào, trong khi source code mô tả logic được thực hiện như thế nào. 

Configuration
      |
      | defines
      v
System structure / parameters
      |
      | used by tools
      v
Generated Code / Runtime Configuration

Source Code
      |
      | implements
      v
Application / Driver Logic

Hai phần này liên quan chặt chẽ nhưng không phải là một.

4. ARXML là gì?

ARXML là định dạng XML được sử dụng trong AUTOSAR để mô tả và trao đổi các thông tin liên quan đến hệ thống AUTOSAR.

Có thể xem ARXML như một dạng machine-readable description của hệ thống. 

AUTOSAR Model / Configuration
            |
            v
          ARXML
            |
            v
       AUTOSAR Tools
            |
            v
 Generated Configuration / Code

5. ARXML có phải là code không?

Không. ARXML là dữ liệu cấu hình và mô hình hóa, không phải application source code.

Ví dụ một đoạn ARXML có thể mô tả một component, interface hoặc một tham số cấu hình. Tool sẽ đọc thông tin đó và sử dụng nó trong quá trình configuration hoặc generation. 

ARXML
  ↓
Tool đọc model
  ↓
Configuration
  ↓
Generated files
  ↓
Compiler
  ↓
ECU Software

6. XML là gì?

XML là một định dạng dữ liệu có cấu trúc, trong đó thông tin được biểu diễn bằng các element và attribute. 

<Example>
    <Name>Temperature</Name>
    <Value>80</Value>
</Example>

ARXML sử dụng XML làm nền tảng, nhưng bổ sung cấu trúc và các quy tắc riêng của AUTOSAR.

7. ARXML chứa những gì?

ARXML có thể chứa rất nhiều loại thông tin tùy theo mục đích và giai đoạn của project.

  • Software Components.
  • Ports.
  • Interfaces.
  • Data types.
  • System information.
  • ECU configuration.
  • Communication information.
  • BSW configuration.
  • Hardware-related configuration.

Vì vậy không nên nghĩ rằng "một ARXML chỉ chứa một loại cấu hình".

8. Một project có thể có nhiều ARXML

Trong project thực tế, rất hiếm khi chỉ có một file ARXML duy nhất. Hệ thống có thể được chia thành nhiều file phục vụ các mục đích khác nhau.

Port xác định điểm kết nối của một SWC. Configuration cần xác định port đó sử dụng interface nào và nó thuộc loại cung cấp hay yêu cầu.

18. Configuration Parameter

Configuration parameter là một giá trị hoặc lựa chọn dùng để xác định behavior của module. 

Module
 |
 +-- Parameter A = ...
 +-- Parameter B = ...
 +-- Parameter C = ...
 +-- Parameter D = ...

Không phải mọi parameter đều có ý nghĩa giống nhau. Một số có thể liên quan đến timing, một số liên quan đến communication, một số liên quan đến hardware.

19. Configuration Class

Trong AUTOSAR, một số configuration có thể được phân loại dựa trên thời điểm và cách chúng được xác định.

Ở mức khái niệm, cần phân biệt:

  • Cấu hình được xác định trước khi build.
  • Cấu hình được đưa vào generated code.
  • Cấu hình liên quan đến initialization/runtime.

Chi tiết từng configuration class có thể khác nhau tùy module, vì vậy khi làm project thực tế cần xem specification của module đó.

20. Static Configuration

Một phần lớn configuration của ECU được xác định trước khi phần mềm được build và flash vào ECU. 

Configuration
      ↓

      ↓

Điều này phù hợp với đặc tính của embedded automotive software, nơi nhiều behavior của hệ thống được xác định trước.

21. Configuration và Generated Code

Một trong những lý do quan trọng khiến configuration tồn tại là để tool có thể generate một phần code cần thiết.

22. Generated Code không nên sửa tùy tiện

Trong project AUTOSAR, một số file được generate tự động. Nếu sửa trực tiếp generated code, thay đổi có thể bị mất trong lần generate tiếp theo. 

Configuration
      ↓

      ↓
Generated Code

Nếu sửa trực tiếp:

Generated Code
      ↓

      ↓
Thay đổi có thể bị ghi đè

Vì vậy nên sửa configuration hoặc source code đúng nơi thay vì patch trực tiếp generated output nếu workflow của project không cho phép.

Một lợi ích quan trọng của ARXML là hỗ trợ trao đổi thông tin AUTOSAR giữa các công cụ và các bên tham gia project.

25. ARXML không phải lúc nào cũng là file "configuration"

Đây là một điểm dễ gây nhầm lẫn. ARXML là format dùng để biểu diễn thông tin AUTOSAR, trong đó có nhiều loại thông tin khác nhau.

Vì vậy: 

ARXML
  ≠ chỉ có BSW Configuration

ARXML có thể chứa:
- SWC description
- Interface description
- System description
- ECU configuration
- Communication information
- Các model/configuration khác

30. Configuration không thay thế Application Logic

"Temperature được kết nối vào Warning SWC"

"Nếu Temperature > Threshold
 → bật Warning"

Đây là hai trách nhiệm khác nhau.

31. Configuration và Runnable

Runnable là đơn vị thực thi logic của một SWC. Configuration có thể xác định các event hoặc cơ chế khiến runnable được kích hoạt.

     |
     v

Vì vậy khi một runnable không chạy, vấn đề có thể không nằm trong code của runnable mà nằm ở configuration hoặc event mapping.

39. Configuration Consistency

Một hệ thống AUTOSAR cần configuration nhất quán. Nếu một component yêu cầu interface nhưng không có provider phù hợp, hệ thống sẽ có vấn đề.

40. Configuration Validation

Toolchain thường có các bước kiểm tra configuration trước khi generate hoặc build. 

Configuration
      ↓
Validation
      |
      +---- Error → Fix
      |
      +---- Valid
              ↓
           Generate

Validation giúp phát hiện lỗi càng sớm càng tốt, trước khi chúng trở thành runtime problem.

41. Configuration Error và Runtime Error

Đây là hai loại lỗi cần phân biệt.

Loại lỗi Ví dụ
Configuration Error Port không được map đúng
Configuration Error Module parameter không hợp lệ

Runtime Error Communication timeout khi ECU đang chạy

42. Debug Configuration Error

Khi gặp lỗi configuration, có thể kiểm tra theo thứ tự:

  1. Đọc error message của tool.
  2. Xác định module liên quan.
  3. Kiểm tra parameter.
  4. Kiểm tra dependency.
  5. Kiểm tra interface hoặc mapping.
  6. Kiểm tra consistency với module liên quan.
  7. Regenerate configuration.
  8. Build lại.

43. Đọc ARXML có khó không?

ARXML thực tế có thể rất dài và khó đọc trực tiếp vì cấu trúc của AUTOSAR khá lớn.

Tuy nhiên không cần đọc từ đầu đến cuối. Cách hiệu quả hơn là xác định trước mình đang tìm thông tin gì. 

Cần tìm:
"Temperature Interface"

        ↓

        ↓

        ↓

        ↓

Provider / Consumer

44. Cách đọc một file ARXML

  1. Xác định file thuộc loại model/configuration nào.
  2. Tìm package hoặc element liên quan.
  3. Tìm tên component hoặc interface.
  4. Kiểm tra reference.
  5. Trace sang object được reference.
  6. Kiểm tra relationship với các thành phần khác.

71. Những nhầm lẫn thường gặp

ARXML = Source Code

Sai. ARXML là một định dạng mô tả/model/configuration.

ARXML = Chỉ Configuration

Không hoàn toàn đúng. ARXML có thể chứa nhiều loại thông tin AUTOSAR.

Configuration = Application Logic

Không. Configuration xác định structure, relationship và parameters; application logic thực hiện behavior của chức năng.

Generated Code = Source of Truth

Không nhất thiết. Trong nhiều workflow, configuration/model mới là nguồn tạo ra generated code.

Chỉ cần sửa Generated Code

Thường không nên. Cần tìm configuration hoặc source tương ứng để thay đổi đúng nơi.

77. Các khái niệm cần nhớ

  • AUTOSAR Configuration: xác định structure, relationship và parameter của hệ thống.
  • ARXML: định dạng XML dùng để mô tả và trao đổi thông tin AUTOSAR.
  • Model: biểu diễn các object và relationship của hệ thống.
  • Configuration Tool: công cụ tạo, chỉnh sửa, kiểm tra hoặc generate configuration.
  • Generated Code: code được tạo dựa trên model/configuration.
  • Reference: liên kết một object với object khác.
  • Mapping: xác định cách các thành phần/data được liên kết xuyên qua hệ thống.
  • Validation: kiểm tra configuration có hợp lệ và nhất quán hay không.
  • Source of Truth: nguồn chính dùng để tạo ra output configuration/generated code.
  • Traceability: khả năng theo dõi thông tin từ requirement đến architecture, configuration và software.

78. Tóm tắt

AUTOSAR Configuration là quá trình xác định cách các thành phần trong ECU được tổ chức, kết nối và hoạt động.

ARXML là một định dạng dựa trên XML dùng để mô tả và trao đổi thông tin AUTOSAR. ARXML có thể chứa thông tin về SWC, Interface, Data Type, System, Communication và nhiều loại configuration khác.

Configuration có thể được đưa vào toolchain để validation, generate RTE hoặc BSW configuration, sau đó build thành ECU software. Vì vậy khi debug một vấn đề configuration, không nên chỉ nhìn generated code mà cần trace ngược về Configuration → ARXML/Model → Generator → Generated Code.

Khi học ARXML, không cần cố nhớ tất cả XML tag. Quan trọng hơn là biết xác định: Object → Reference → Relationship → Dependency → Generated Result.
