Bài 5: Tổng quan tầng Runtime Environment

Runtime Environment (RTE) là tầng trung gian trong kiến trúc AUTOSAR Classic, nằm giữa Application Software và Basic Software (BSW).

Nếu Bài 4 tập trung vào Application Software và Software Component, thì bài này tập trung vào câu hỏi: Application Software giao tiếp với các thành phần khác thông qua đâu?

Lưu ý: Bài này chỉ tập trung vào tổng quan về RTE. Các khái niệm chi tiết như Port, Interface, Runnable, Event, RTE API, Sender-Receiver và Client-Server sẽ được tìm hiểu ở các bài chuyên sâu sau.

1. Runtime Environment là gì?

RTE là một lớp phần mềm nằm giữa Application Software và Basic Software.

Vai trò tổng quan của RTE là cung cấp môi trường để các Software Component trong Application Software có thể giao tiếp với nhau và sử dụng các dịch vụ cần thiết từ hệ thống bên dưới.

Có thể hiểu đơn giản: RTE giúp Application Software giao tiếp với phần còn lại của hệ thống mà không cần trực tiếp xử lý các chi tiết bên dưới.

2. RTE nằm ở đâu trong kiến trúc AUTOSAR?

Vị trí của RTE trong kiến trúc AUTOSAR Classic có thể hình dung như sau:

Vì nằm giữa Application Software và BSW, RTE đóng vai trò như một cầu nối giữa phần mềm ứng dụng và môi trường AUTOSAR bên dưới.

3. Tại sao cần RTE?

Nếu Application Software phải trực tiếp giao tiếp với từng module bên dưới, phần mềm ứng dụng sẽ dễ trở nên phụ thuộc vào cách hệ thống được triển khai.

RTE giúp tạo ra một ranh giới rõ ràng: 

Application Software
        │
        │  Giao tiếp thông qua RTE
        ↓
       RTE
        │
        │  Kết nối với hệ thống bên dưới
        ↓
       BSW
        │
        ↓
    Hardware

Nhờ đó, Application Software có thể tập trung vào logic chức năng thay vì phải xử lý toàn bộ các chi tiết liên quan đến nền tảng phần mềm và phần cứng.

4. RTE kết nối các Software Component

Application Software trong AUTOSAR được chia thành nhiều Software Component (SWC).

Các SWC có thể cần trao đổi dữ liệu hoặc yêu cầu chức năng từ những thành phần khác. Ở mức tổng quan, RTE cung cấp môi trường để những giao tiếp này được thực hiện. 

+-------------------+       +-------------------+
|     SWC A         |       |      SWC B        |
|                   |       |                   |
|  Function A       |       |  Function B       |
+---------+---------+       +---------+---------+
          \                         /
           \                       /
            +-------- RTE --------+
                     │
                     ↓
               Basic Software

Ví dụ, một Software Component xử lý trạng thái cửa có thể cung cấp thông tin cho một Software Component khác đang xử lý đèn hoặc khóa cửa.

Cách dữ liệu được trao đổi giữa các SWC và các loại Interface được sử dụng sẽ được trình bày chi tiết trong các bài học sau.

5. RTE kết nối Application với BSW

Không chỉ kết nối các Software Component, RTE còn giúp Application Software sử dụng những dịch vụ được cung cấp bởi Basic Software.

Ví dụ ở mức tổng quan, Application Software có thể cần:

  • Thông tin về trạng thái hệ thống.
  • Dữ liệu nhận từ mạng truyền thông.
  • Dịch vụ liên quan đến thời gian.
  • Các dịch vụ nền tảng khác do BSW cung cấp.

Application không cần trực tiếp đi xuống từng module BSW để xử lý những chức năng này. RTE đóng vai trò trung gian trong kiến trúc. 

Application SWC
       │
       ↓
      RTE
       │
       ↓
   BSW Services
       │
       ↓
 Hardware / Communication / System

6. RTE và Virtual Function Bus

Trong AUTOSAR, khái niệm Virtual Function Bus (VFB) được sử dụng để mô tả môi trường giao tiếp giữa các Software Component ở mức kiến trúc.

Có thể hình dung VFB như một môi trường giao tiếp logic: 

        Software Component A
                  │
                  ↓
        +-------------------+
        |   Virtual Function|
        |       Bus (VFB)   |
        +-------------------+
                  │
                  ↓
        Software Component B

Ở mức thiết kế hệ thống, VFB giúp mô tả cách các chức năng phần mềm giao tiếp với nhau mà không cần tập trung ngay vào cách chúng được triển khai trên một ECU cụ thể.

Khi hệ thống được triển khai trên ECU, RTE là thành phần quan trọng giúp hiện thực môi trường giao tiếp này trong AUTOSAR Classic.

VFB và RTE có liên quan chặt chẽ nhưng không nên xem chúng là cùng một khái niệm. VFB là cách nhìn ở mức kiến trúc về môi trường giao tiếp, còn RTE là phần được triển khai trong ECU để hỗ trợ việc giao tiếp và thực thi của Application Software.

7. Ví dụ tổng quan về luồng dữ liệu

Giả sử một ECU nhận thông tin trạng thái cửa và cần sử dụng thông tin đó để quyết định trạng thái đèn.

Ở mức tổng quan, luồng xử lý có thể hình dung: 

Thông tin trạng thái cửa
          ↓
     Software Component
       Door Status
          ↓
         RTE
          ↓
     Lighting Control
          ↓
     Software Component
          ↓
         RTE
          ↓
     Hệ thống bên dưới
          ↓
         Đèn

Điểm cần nhớ là Application Software tập trung vào logic chức năng, trong khi RTE cung cấp môi trường giao tiếp giữa các thành phần.

8. RTE giúp giảm sự phụ thuộc của Application

Một mục tiêu quan trọng của kiến trúc AUTOSAR là giảm sự phụ thuộc trực tiếp giữa Application Software và các chi tiết triển khai bên dưới.

Không có lớp trung gian Có RTE
Application dễ phụ thuộc vào các thành phần bên dưới. Application giao tiếp thông qua một lớp trung gian.
Khó tách biệt logic chức năng và nền tảng. Logic Application được tách khỏi phần mềm nền tảng rõ hơn.
Việc tái sử dụng có thể khó hơn. Hỗ trợ tổ chức Application thành các Software Component.

9. RTE trong một ví dụ ECU đơn giản

Giả sử một ECU có hai chức năng: Door Status và Lighting Control. 

+---------------------------------------+
|        Application Software           |
|                                       |
|  +---------------+  +---------------+ |
|  | Door Status   |  | Lighting      | |
|  | SWC           |  | Control SWC   | |
|  +-------+-------+  +-------+-------+ |
|          \                  /          |
+-----------\----------------/-----------+
             \              /
              +---- RTE ----+
                     │
                     ↓
             +---------------+
             |      BSW      |
             +---------------+
                     │
                     ↓
                 Hardware

Khi trạng thái cửa thay đổi, thông tin có thể được sử dụng bởi Lighting Control SWC thông qua môi trường giao tiếp do AUTOSAR cung cấp.

Như vậy, RTE giúp các Software Component được tổ chức độc lập hơn và hỗ trợ việc kết nối chúng thành một hệ thống hoàn chỉnh.

10. Những khái niệm cần nhớ

Khái niệm Ý nghĩa tổng quan
RTE Lớp trung gian giữa Application Software và Basic Software.
Software Component Thành phần phần mềm thực hiện một chức năng hoặc một phần chức năng.
VFB Môi trường giao tiếp logic giữa các chức năng Software Component ở mức kiến trúc.
Application ↔ RTE Application sử dụng RTE để giao tiếp với các thành phần khác.
RTE ↔ BSW RTE hỗ trợ Application sử dụng môi trường và dịch vụ của hệ thống bên dưới.
Hardware Independence RTE góp phần tách Application khỏi các chi tiết triển khai phần cứng.

Tóm tắt

Runtime Environment (RTE) là tầng trung gian quan trọng trong AUTOSAR Classic, nằm giữa Application Software và Basic Software. RTE cung cấp môi trường để các Software Component giao tiếp với nhau và sử dụng các dịch vụ của hệ thống bên dưới. Ở mức kiến trúc, khái niệm Virtual Function Bus (VFB) giúp mô tả môi trường giao tiếp giữa các chức năng phần mềm. Nhờ RTE, Application Software được tách khỏi nhiều chi tiết của nền tảng và Hardware.
