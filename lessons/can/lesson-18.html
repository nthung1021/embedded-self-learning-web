Bài 18: State Machine

Trong CAN Driver, State Machine là cơ chế mô tả các trạng thái mà CAN Driver hoặc CAN Controller có thể đang ở, cũng như cách chúng chuyển từ trạng thái này sang trạng thái khác.

Hiểu State Machine rất quan trọng vì nhiều API của AUTOSAR CAN Driver chỉ được phép gọi khi module đang ở một trạng thái phù hợp. Ví dụ, một controller phải được khởi tạo trước khi có thể sử dụng để truyền hoặc nhận dữ liệu.

Ý chính: State Machine trả lời ba câu hỏi: đang ở trạng thái nào?, sự kiện nào xảy ra? và sau sự kiện đó sẽ chuyển sang trạng thái nào?

1. State Machine là gì?

State Machine (máy trạng thái) là một mô hình dùng để mô tả hành vi của một hệ thống dựa trên trạng thái hiện tại và sự kiện hoặc điều kiện xảy ra.

Một State Machine cơ bản có thể được hiểu như sau: 

Current State
      +
      |
      | Event / Condition
      v
Transition
      |
      v
Next State

Ví dụ đơn giản, một thiết bị có thể có ba trạng thái:

Trạng thái Ý nghĩa
UNINIT Module chưa được khởi tạo.
READY Module đã được khởi tạo và sẵn sàng hoạt động.
STOPPED Controller đang ở trạng thái không truyền/nhận CAN bình thường.

2. Tại sao CAN Driver cần State Machine?

CAN Driver không chỉ đơn giản là một tập hợp các hàm đọc và ghi thanh ghi. Driver phải quản lý trạng thái của controller và đảm bảo các thao tác được thực hiện đúng thời điểm.

Ví dụ: 

Can_Init()
     |
     v
Driver đã được initialize
     |
     v
Controller được cấu hình
     |
     v
Controller có thể chuyển sang trạng thái hoạt động
     |
     v
Can_Write() / CAN communication

Nếu chương trình cố gọi một API yêu cầu driver đã được khởi tạo trong khi driver vẫn đang ở trạng thái UNINIT, thao tác đó có thể không hợp lệ.

State Machine giúp phần mềm biết API nào được phép sử dụng trong từng thời điểm và giúp tránh các sequence sai trong quá trình vận hành.

3. State và Transition

Có hai khái niệm quan trọng nhất trong State Machine:

Khái niệm Ý nghĩa Ví dụ trong CAN
State Trạng thái hiện tại của hệ thống. UNINIT, STOPPED, STARTED
Event Sự kiện khiến hệ thống cần xử lý. Init, SetControllerMode, DeInit
Transition Quá trình chuyển từ state này sang state khác. STOPPED → STARTED
Condition Điều kiện để transition được phép xảy ra. Driver đã initialized

5. Driver State và Controller State

Đây là một điểm rất dễ nhầm khi học AUTOSAR CAN. Trạng thái của CAN Driver và trạng thái của CAN Controller không hoàn toàn giống nhau.

Đối tượng State Machine dùng để mô tả
CAN Driver Driver đã được initialize hay chưa.
CAN Controller Controller đang ở trạng thái vận hành nào.
CAN Interface / upper layer Trạng thái quản lý communication ở tầng phía trên.
Không nên đồng nhất: Can_Init() với việc controller ngay lập tức ở trạng thái STARTED. Init là lifecycle của driver; controller mode là một khái niệm khác.

6. Driver State: UNINIT

UNINIT có thể hiểu là trạng thái driver chưa được khởi tạo. Đây là trạng thái thường tồn tại trước khi Can_Init() được thực hiện. 

ECU Startup
     |
     v
CAN Driver
     |
     v
UNINIT
     |
     | Can_Init()
     v
INITIALIZED

Khi đang ở trạng thái này, những API yêu cầu driver đã được initialize không nên được sử dụng như thể driver đã sẵn sàng.

7. Driver State: INITIALIZED

Sau khi Can_Init() hoàn thành, driver đã có configuration và internal state cần thiết để phục vụ các thao tác tiếp theo.

Có thể hình dung: 

Configuration
      |
      v
Can_Init()
      |
      +--> Driver configuration
      +--> Controller configuration
      +--> Hardware Object configuration
      +--> Interrupt / polling configuration
      +--> Internal driver state
      |
      v
Driver initialized

Tuy nhiên, controller có được phép truyền/nhận ngay hay không còn phụ thuộc vào controller mode và sequence của hệ thống.

8. Controller State

Bên cạnh lifecycle của driver, mỗi CAN Controller còn có trạng thái vận hành. Ở mức khái niệm, các trạng thái thường được nhắc tới là:

Controller State Ý nghĩa
STOPPED Controller chưa hoạt động truyền/nhận CAN bình thường.
STARTED Controller đang hoạt động và có thể tham gia communication.
SLEEP Controller được đưa vào trạng thái low-power theo thiết kế hệ thống.

Tên state và chi tiết transition cần được đọc theo AUTOSAR release và implementation cụ thể.

9. STOPPED và STARTED

Hai trạng thái này rất quan trọng khi làm việc với CAN Controller. 

                 SetControllerMode(STARTED)
        +--------------------------------------+
        |                                      v
   +----------+                         +-----------+
   | STOPPED  |                         |  STARTED  |
   +----------+                         +-----------+
        ^                                      |
        |                                      |
        +--------------------------------------+
                 SetControllerMode(STOPPED)

Có thể hiểu đơn giản:

  • STOPPED: controller chưa tham gia communication bình thường.
  • STARTED: controller có thể tham gia truyền và nhận CAN.
Điểm phỏng vấn: Can_SetControllerMode() dùng để yêu cầu thay đổi controller mode; nó không thay thế cho Can_Init().

10. State Transition là gì?

State Transition là quá trình hệ thống chuyển từ một trạng thái sang trạng thái khác khi một event hoặc condition phù hợp xảy ra.

Ví dụ: 

Current State: STOPPED

Event:
SetControllerMode(STARTED)

Condition:
Driver initialized
Hardware/configuration valid

Result:
STARTED

Nếu điều kiện không hợp lệ, transition có thể không được thực hiện thành công hoặc hệ thống sẽ xử lý lỗi tùy implementation.

11. Init ảnh hưởng đến State Machine như thế nào?

Can_Init() là một transition quan trọng trong lifecycle của driver.

Lưu ý rằng READY trong sơ đồ chỉ là cách gọi mang tính khái niệm, không nhất thiết là tên enum/state chính thức trong implementation.

12. DeInit và State Machine

Can_DeInit() thực hiện transition ngược lại ở lifecycle của driver: từ trạng thái đã initialize về trạng thái chưa initialize. 

INITIALIZED
     |
     | Communication stopped / safe state
     v
Can_DeInit()
     |
     v
UNINIT

DeInit thường được thực hiện trong các lifecycle transition như shutdown, reconfiguration hoặc các tình huống đặc biệt được hệ thống cho phép.

14. State Machine và Can_Write()

Một API truyền dữ liệu như Can_Write() cần được gọi trong context phù hợp. 

Can_Write()
    |
    +-- Driver initialized?
    |       |
    |       +-- NO  -> API usage không hợp lệ
    |       |
    |       +-- YES
    |
    +-- Controller / HTH hợp lệ?
    |       |
    |       +-- NO  -> lỗi
    |       |

            |
            v
        CAN Hardware

Vì vậy khi debug một vấn đề truyền CAN, không nên chỉ kiểm tra Can_Write(). Cần kiểm tra cả state của driver, controller, HTH và configuration.

16. State Machine và Interrupt

Interrupt cũng liên quan đến state của module. Ví dụ, sau khi initialization, interrupt configuration có thể được thiết lập để xử lý các sự kiện CAN. 

CAN Event
    |
    v

    |
    v

    |
    +--> Tx event
    +--> Rx event
    +--> Error event
    |
    v
Upper Layer Notification

Khi driver đã DeInit, hệ thống phải đảm bảo không còn kỳ vọng driver xử lý communication event như trong trạng thái hoạt động.

17. State Machine và DET

DET có thể giúp phát hiện những lỗi liên quan đến việc sử dụng API không đúng state trong development phase, tùy vào implementation và configuration.

Tình huống Vấn đề
API gọi trước Can_Init() Driver chưa được initialize.
API gọi sau Can_DeInit() Driver đã trở về trạng thái chưa initialize.
Controller mode request không phù hợp Transition có thể không hợp lệ.
Configuration không hợp lệ State transition có thể thất bại hoặc bị từ chối.
DET chủ yếu hỗ trợ phát hiện lỗi trong quá trình phát triển và kiểm thử. Không nên hiểu rằng mọi state transition lỗi đều tự động trở thành một DEM event.

18. State Machine và DEM

DEM tập trung vào diagnostic event và lỗi runtime được hệ thống định nghĩa. Vì vậy State Machine và DEM có thể liên quan khi một lỗi state hoặc controller trở thành một điều kiện diagnostic cần theo dõi.

Tuy nhiên, không phải mọi transition sai đều mặc định tạo ra DEM event. Điều này phụ thuộc vào yêu cầu hệ thống và configuration.

22. Những lỗi State Machine thường gặp

Lỗi Nguyên nhân có thể Cách kiểm tra

26. Phân biệt Init, Start, Stop và DeInit

Thao tác Ý nghĩa
Can_Init() Khởi tạo CAN Driver và internal configuration/state.
Start Controller Đưa CAN Controller vào trạng thái hoạt động.
Stop Controller Đưa CAN Controller ra khỏi trạng thái hoạt động.
Can_DeInit() Kết thúc lifecycle của CAN Driver, đưa driver về trạng thái chưa initialize.
Memory trick:
Init = chuẩn bị Driver
Start = cho Controller hoạt động
Stop = dừng Controller
DeInit = kết thúc lifecycle của Driver

28. Góc nhìn phỏng vấn

Câu hỏi: What is a State Machine in an AUTOSAR CAN Driver?

Một câu trả lời phù hợp cho Fresher:

State Machine is a way to manage the different states of the CAN Driver and CAN Controller and define how they transition between states based on events or requests. For example, the CAN Driver should be initialized before the controller is used for communication, and the controller can be switched between stopped and started states depending on the system operation.
Câu hỏi: What is the difference between Can_Init() and starting the CAN Controller?

Có thể trả lời:

Can_Init() initializes the CAN Driver and its configuration, while starting the CAN Controller changes the controller's operational mode so that it can participate in CAN communication. They are related but represent different lifecycle and operational concepts.
Câu hỏi: How would you debug a CAN communication issue related to state?

Có thể trả lời theo thứ tự: 

Check Can_Init()
      ↓
Check Driver State
      ↓
Check Controller State
      ↓
Check State Transition Request
      ↓
Check Configuration
      ↓
Check DET / Diagnostic Information
      ↓
Check CAN Hardware / Bus
