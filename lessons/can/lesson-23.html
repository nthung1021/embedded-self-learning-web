Bài 23: Bật và Tắt Interrupts

Trong một CAN Controller, nhiều sự kiện có thể xảy ra bất đồng bộ với luồng thực thi chính của CPU, chẳng hạn như CAN frame đã được nhận, transmission hoàn tất hoặc CAN error xảy ra. Interrupt cho phép CAN hardware thông báo cho CPU khi những sự kiện này xảy ra.

Enable and Disable Interrupts là việc kiểm soát xem một nguồn interrupt có được phép gửi yêu cầu đến CPU hay không. Trong AUTOSAR CAN Driver, interrupt configuration cần phối hợp với CAN Controller, Interrupt Controller, OS và cơ chế xử lý của driver.

1. Interrupt là gì?

Interrupt là cơ chế cho phép hardware hoặc một peripheral thông báo cho CPU rằng một sự kiện cần được xử lý. 

CPU đang thực hiện task
        │
        │
        ▼
   CAN Controller
        │
        │ Event xảy ra
        ▼
     Interrupt
        │
        ▼
       CPU
        │
        ▼
 Interrupt Service Routine
        │
        ▼
   Xử lý CAN Event

Thay vì CPU phải liên tục kiểm tra CAN Controller, hardware có thể tạo interrupt khi một sự kiện cụ thể xảy ra.

2. Tại sao CAN cần Interrupt?

CAN communication diễn ra độc lập với thời điểm CPU đang thực hiện application hoặc một task khác.

Ví dụ, CPU đang xử lý một task: 

CPU
 │
 ├── Task A
 │
 ├── Task B
 │
 └── Task C

Trong lúc đó:

CAN Controller
      │
      ▼
Receive CAN Frame
      │
      ▼
CAN Interrupt
      │
      ▼
CPU xử lý CAN event

Interrupt giúp hệ thống phản ứng với CAN event mà không cần CPU liên tục polling trạng thái hardware.

3. Interrupt và Polling

Hai cách phổ biến để software phát hiện event từ CAN Controller là interrupt và polling.

Interrupt Polling
Hardware chủ động thông báo CPU. Software chủ động kiểm tra hardware.
Phản ứng nhanh với event. Có thể phụ thuộc chu kỳ polling.
Giảm việc CPU phải kiểm tra liên tục. Có thể đơn giản hơn trong một số thiết kế.
Cần cấu hình interrupt. Cần periodic task/main function.

4. CAN Interrupt Sources

CAN Controller có thể cung cấp nhiều nguồn interrupt khác nhau tùy hardware. Các nhóm thường gặp gồm:

  • Receive interrupt.
  • Transmit interrupt.
  • Error interrupt.
  • Bus status/state change interrupt.
  • Wake-up interrupt.
  • FIFO hoặc message buffer related interrupt.
                 CAN Controller
                       │
       ┌───────────────┼───────────────┐
       │               │               │
       ▼               ▼               ▼
   Receive          Transmit          Error
  Interrupt        Interrupt        Interrupt
       │               │               │
       └───────────────┼───────────────┘
                       ▼
              Interrupt Controller
                       │
                       ▼
                       CPU
Tên interrupt và cách phân chia interrupt source phụ thuộc CAN IP của MCU. Không nên giả định mọi MCU có cùng các interrupt flag hoặc cùng cấu trúc vector.

5. Enable Interrupt là gì?

Enable Interrupt nghĩa là cho phép một nguồn interrupt được truyền từ peripheral đến CPU hoặc đến tầng interrupt controller theo kiến trúc của MCU. 

CAN Event
   │
   ▼

   │
   ▼
Interrupt Enable = 1
   │
   ▼
Interrupt Controller
   │
   ▼
CPU
   │
   ▼
ISR

Khi interrupt source được enable và event tương ứng xảy ra, CPU có thể nhận interrupt request.

6. Disable Interrupt là gì?

Disable Interrupt nghĩa là tạm thời hoặc có chủ đích ngăn một nguồn interrupt tạo yêu cầu xử lý tới CPU. 

CAN Event
   │
   ▼
Interrupt Flag
   │
   ▼
Interrupt Enable = 0
   │
   X
   │
   ▼
CPU không nhận interrupt từ source này
Disable một interrupt source không nhất thiết có nghĩa là event hardware không xảy ra. Event/flag có thể vẫn được hardware ghi nhận tùy thiết kế peripheral. Cách flag được giữ, clear hoặc xử lý phụ thuộc CAN Controller.

7. Interrupt Enable và Interrupt Flag khác nhau

Đây là điểm rất quan trọng khi làm việc với peripheral registers. Enable bit và status/flag bit không phải cùng một thứ.

Khái niệm Ý nghĩa
Interrupt Flag Cho biết một event đã xảy ra hoặc đang pending theo thiết kế hardware.
Interrupt Enable Cho phép source đó tạo interrupt request.
Interrupt Priority Quyết định mức ưu tiên xử lý khi MCU có nhiều interrupt.

17. Critical Section

Một số đoạn code cần được bảo vệ để tránh bị interrupt làm gián đoạn giữa chừng. Đoạn code như vậy thường được gọi là critical section.

Mục đích là bảo vệ dữ liệu hoặc thao tác cần tính nhất quán.

18. Tại sao phải Disable Interrupt trong Critical Section?

Giả sử một biến dùng chung được cập nhật bởi task và ISR: 

Task:
sharedCounter = sharedCounter + 1

ISR:
sharedCounter = sharedCounter + 1

Nếu hai phần thực thi truy cập dữ liệu không được bảo vệ đúng cách, có thể xảy ra race condition hoặc dữ liệu không nhất quán. 

Task
 │
 │ read sharedCounter
 │
 ├───────────────┐
 │               │
 │          Interrupt
 │               │
 │               ▼
 │              ISR
 │               │
 │               ▼
 │          modify data
 │               │
 └───────────────┘
       tiếp tục

Một critical section phù hợp có thể ngăn interruption ở thời điểm nhạy cảm.

19. Không nên Disable Interrupt quá lâu

Disable interrupt quá lâu có thể gây ra latency cho các event khác. 

Disable Interrupt
      │
      ├── 10 µs
      │      → có thể chấp nhận tùy hệ thống
      │
      ├── 100 µs
      │      → cần đánh giá timing
      │
      └── quá lâu
             → Event latency
             → Missed deadline
             → System timing problem
Không có một con số thời gian "đúng" cho mọi ECU. Thời gian critical section phải được xác định dựa trên timing requirements và interrupt latency của hệ thống.

20. Enable/Disable toàn bộ Interrupt vs một Source

Cần phân biệt giữa việc disable một interrupt source và việc disable interrupt ở mức CPU/global hoặc một nhóm interrupt.

Phạm vi Ý nghĩa
Disable CAN RX interrupt Chỉ ngăn receive interrupt source đó.
Disable CAN error interrupt Chỉ ngăn error interrupt source đó.
Disable CPU/global interrupts Có thể ảnh hưởng đến nhiều interrupt source khác.
Trong driver code, cần biết chính xác API hoặc register đang tác động lên interrupt source nào. Không nên gọi một API "Disable Interrupt" và mặc định rằng nó chỉ ảnh hưởng CAN.

33. Common Mistakes

Sai lầm Vấn đề
Disable tất cả interrupt quá lâu Có thể gây latency và bỏ lỡ deadline.
Nhầm flag với enable bit Không biết event đã xảy ra hay interrupt có được phép hay không.
Chỉ kiểm tra CAN Driver Có thể bỏ sót Interrupt Controller hoặc vector.
ISR xử lý quá nhiều việc Tăng interrupt latency và ảnh hưởng task khác.
Disable interrupt mà không biết phạm vi Có thể vô tình ảnh hưởng source khác.
Cho rằng Sleep disable tất cả interrupt Có thể làm mất wake-up mechanism.

34. Góc nhìn phỏng vấn

Với vị trí Junior Automotive Embedded Software Engineer, một số câu hỏi thường gặp có thể là:

  • What is an interrupt?
  • What is the difference between interrupt and polling?
  • What is the difference between an interrupt flag and an interrupt enable bit?
  • Why do we need to disable interrupts in a critical section?
  • Why should an ISR be short?
  • What happens if CAN RX interrupt is not triggered?
  • How would you debug a CAN interrupt issue?
  • What is the role of the Interrupt Controller?
  • How does CAN Driver interact with an interrupt?
  • Can you disable all interrupts during CAN communication?
Câu trả lời ngắn nên nhớ: An interrupt allows the CAN Controller to notify the CPU when an event occurs, such as reception, transmission completion or an error. Enabling an interrupt allows a specific interrupt source to request CPU service, while disabling it prevents that source from generating an interrupt request. In a critical section, interrupts may be temporarily restricted to protect shared data, but they should be disabled for the shortest practical time.

36. Tóm tắt

Interrupt là cơ chế quan trọng giúp CAN Controller thông báo các event cho CPU. Trong CAN Driver, interrupt có thể được sử dụng cho reception, transmission, error handling và các event khác tùy hardware/configuration. 

CAN Controller
      │
      ├── RX Event
      ├── TX Event
      ├── Error Event
      └── Status Event
             │
             ▼
      Interrupt Flag
             │
             ▼
      Interrupt Enable
             │
             ▼
   Interrupt Controller
             │
             ▼
            CPU
             │
             ▼
            ISR
             │
             ▼
        CAN Driver
             │
             ▼
           CanIf
             │
             ▼
       Upper Layers
Điểm quan trọng nhất: Khi debug CAN interrupt, hãy kiểm tra theo chuỗi Event → Flag → Interrupt Enable → Interrupt Controller → Vector → ISR → CAN Driver → Upper Layer. Nếu xác định được điểm mà chuỗi này bị ngắt, việc tìm root cause sẽ dễ dàng hơn rất nhiều.
