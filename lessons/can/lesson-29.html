Bài 29: Topology, Mapping và Communication

Mục tiêu bài học: Hiểu cách các ECU được kết nối trong một CAN network, phân biệt Topology, Mapping và Communication, hiểu mối quan hệ giữa CAN Controller, CAN Channel, CAN Network, PDU, CAN ID và các AUTOSAR module, đồng thời biết cách kiểm tra mapping khi debug một hệ thống CAN.

1. Ba khái niệm cần phân biệt

Khi làm việc với CAN trong automotive, ba khái niệm thường xuất hiện cùng nhau: Topology, Mapping và Communication.

Communication Các ECU thực sự trao đổi dữ liệu với nhau như thế nào?

2. CAN Network là gì?

Một CAN Network là tập hợp các CAN node cùng kết nối vào một CAN bus và sử dụng các quy tắc CAN để trao đổi message. 

             CAN Network

     +--------- CAN Bus ---------+
     |             |             |
     v             v             v
   ECU A         ECU B         ECU C
     |             |             |
 CAN Controller CAN Controller CAN Controller

Mỗi ECU có thể có một hoặc nhiều CAN Controller tùy thiết kế phần cứng. Các controller này có thể kết nối tới các CAN network/channel khác nhau.

3. CAN Node là gì?

CAN Node là một thiết bị tham gia vào CAN network. Trong automotive, CAN node thường là một ECU hoặc một phần của ECU có khả năng giao tiếp với CAN bus.

Một node thường bao gồm:

  • MCU.
  • CAN Controller.
  • CAN Transceiver.
  • CAN Driver.
  • Các AUTOSAR BSW module liên quan.
  • Application software.

|  AUTOSAR BSW                                           |
|       ↓                                               |
|  CAN Driver                                            |
|       ↓                                               |
|  CAN Controller                                        |
|       ↓                                               |
|  CAN Transceiver                                       |
+-------------------------------------------------------+
                        |
                        v
                    CAN Bus

4. CAN Topology là gì?

Topology mô tả cách các node được kết nối vật lý hoặc logic trong một network.

Với CAN bus truyền thống, các node cùng chia sẻ một bus. 

ECU A --------+
             |
ECU B --------+--------- CAN Bus
             |
ECU C --------+
             |
ECU D --------+

Đây là điểm khác biệt quan trọng so với mô hình point-to-point: CAN bus cho phép nhiều node cùng kết nối vào một môi trường truyền chung.

5. Bus Topology

CAN thường được triển khai theo dạng bus topology. Các node kết nối vào một đường bus chung. 

Termination                         Termination
    |                                   |
    +===================================+
    |          CAN Bus                  |
    +===================================+
       |           |           |
      ECU A       ECU B       ECU C
Trong hệ thống thực tế, topology, chiều dài nhánh, vị trí node và termination phải phù hợp với physical-layer requirements của CAN. Không nên hiểu topology đơn giản chỉ là "nối tất cả dây lại với nhau".

6. Termination và Topology

CAN bus thường sử dụng termination ở hai đầu của bus. Termination giúp kiểm soát phản xạ tín hiệu trên đường truyền. 

        120Ω                         120Ω
          |                            |
          +============================+
          |          CAN Bus           |
          +============================+
              |       |       |
             ECU A   ECU B   ECU C

Khi debug communication, termination không đúng có thể gây ra các vấn đề về tín hiệu và dẫn đến communication error hoặc Bus-Off.

7. Một ECU có thể có nhiều CAN Channel

Một ECU không nhất thiết chỉ có một CAN network. Một MCU có thể có nhiều CAN Controller, và mỗi controller có thể được kết nối tới một CAN channel/network khác nhau. 

                 ECU
        +----------------------+
        |                      |
        | CAN Controller 0     |---- CAN Network A
        |                      |
        | CAN Controller 1     |---- CAN Network B
        |                      |
        | CAN Controller 2     |---- CAN Network C
        |                      |
        +----------------------+

Đây là lý do cần phân biệt Controller, Channel và Network.

8. Controller, Channel và Network

Khái niệm Ý nghĩa
CAN Controller Phần hardware xử lý CAN protocol/frame.
CAN Channel Một communication path/logical channel được cấu hình trong hệ thống.
CAN Network Mạng CAN mà nhiều node cùng tham gia.

Tên gọi và cách mapping cụ thể có thể khác nhau giữa MCU, AUTOSAR configuration tool và project.

9. Mapping là gì?

Mapping là quá trình liên kết các đối tượng communication với nhau để xác định dữ liệu đi qua phần cứng và software stack nào.

Ví dụ, một application signal có thể được mapping theo chuỗi:

       ↓

       ↓
CAN Network

11. CAN ID Mapping

CAN ID là một phần quan trọng trong communication mapping. Receiver thường dựa vào CAN ID và filter configuration để xác định frame nào cần được nhận. 

CAN Frame
+--------------------------------+
| CAN ID | DLC | Data | ...      |
+--------------------------------+
    |
    v
CAN Controller
    |
    v
Hardware Filter
    |
    v
Matching CAN ID
    |
    v
Receive Handling

Nếu sender dùng CAN ID 0x100 nhưng receiver được cấu hình để nhận 0x200, communication sẽ không hoạt động như mong đợi.

12. HRH và HTH

Trong AUTOSAR CAN Driver, hai khái niệm thường gặp là HRH (Hardware Receive Handle) và HTH (Hardware Transmit Handle).

Handle Vai trò
HRH Đại diện cho cấu hình/hardware object dùng cho reception.
HTH Đại diện cho cấu hình/hardware object dùng cho transmission.

Cách triển khai cụ thể phụ thuộc CAN Controller và configuration, nhưng ý tưởng quan trọng là CAN Driver cần biết frame được nhận hoặc truyền thông qua hardware object nào.

16. Sender và Receiver

Trong CAN, sender gửi một CAN frame lên bus. Các node khác có thể nhận frame nếu frame phù hợp với filter và communication configuration của chúng. 

                 CAN Bus
                    |
        +-----------+-----------+
        |           |           |
        v           v           v
     ECU A       ECU B       ECU C
    Sender      Receiver    Receiver
                  |
                  |
              CAN ID match

CAN không hoạt động theo kiểu sender phải chỉ định trực tiếp "gửi frame cho ECU B". CAN frame chủ yếu được xác định bằng CAN ID và các node quyết định frame nào chúng quan tâm.

17. CAN ID không phải địa chỉ ECU

Đây là một điểm rất quan trọng. CAN ID không đơn giản là địa chỉ của ECU nhận.

CAN ID xác định message/frame trên bus và tham gia vào arbitration. Receiver sử dụng CAN ID/filter để xác định frame cần xử lý. 

CAN ID = 0x100

32. Debug bằng CAN Analyzer

CAN analyzer là công cụ rất hữu ích để xác định vấn đề nằm ở network hay software.

Nếu CAN analyzer thấy frame:

  • CAN physical communication có khả năng đang hoạt động.
  • Kiểm tra CAN ID.
  • Kiểm tra DLC.
  • Kiểm tra payload.
  • Kiểm tra cycle time.
  • Kiểm tra sender.

Nếu CAN analyzer không thấy frame, cần tập trung vào transmission path từ application xuống CAN Controller và physical bus.

33. Common Mapping Mistakes

Lỗi Hậu quả
Sai CAN ID Receiver không match frame.
Sai Controller mapping Frame đi qua CAN channel không mong muốn.
Sai HRH Reception không được xử lý đúng.
Sai HTH Transmission không sử dụng đúng hardware object.
Sai PDU mapping Data không tới đúng upper layer.
Sai signal mapping Raw data được decode sai.
Sai cycle time Communication timing không đúng yêu cầu.
Sai network mapping ECU giao tiếp nhầm CAN network.

34. Góc nhìn phỏng vấn

Nếu interviewer hỏi: "What is the difference between topology and mapping?", có thể trả lời:

Sample answer: Topology describes how ECUs and CAN networks are physically or logically connected. Mapping describes how communication objects such as signals, PDUs, CAN IDs, hardware objects and controllers are associated with each other. Communication is the actual data exchange that happens through that topology and mapping.

Nếu interviewer hỏi: "How would you debug if a CAN message is visible on the bus but the application does not receive it?", có thể trả lời:

I would first verify the CAN ID and payload on the bus. Then I would check the receiver's CAN controller filter, HRH and CAN Driver notification. After that, I would trace the PDU routing through CanIf and PduR or COM, and finally verify signal mapping and the application reception.

36. Tóm tắt

Topology, Mapping và Communication là ba khái niệm liên kết chặt chẽ khi xây dựng một CAN network trong automotive.

Topology cho biết các ECU và network được kết nối như thế nào. Mapping xác định dữ liệu, PDU, CAN ID, hardware object và controller được liên kết ra sao. Communication là quá trình dữ liệu thực sự được truyền và nhận trên network.

ECU A ───── CAN Network ───── ECU B
                    |
                    v
                 MAPPING
                    |
                    v
Signal → PDU → CAN ID → Controller → HW Object
                    |
                    v
              COMMUNICATION
                    |
                    v
               CAN Frame
                    |
                    v
                Receiver
                    |
                    v
          PDU → Signal → Application
Điểm quan trọng nhất: Khi debug CAN communication, hãy luôn đặt câu hỏi theo thứ tự: ECU có nằm trên đúng network không? → Data có được mapping đúng không? → Frame có thực sự được truyền/nhận trên bus không? → PDU và signal có đi đúng qua AUTOSAR stack không?
