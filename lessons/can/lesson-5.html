Bài 5: ID Tiêu chuẩn và ID mở rộng

Trong CAN, mỗi message được nhận diện bằng một Identifier (ID). ID không phải là địa chỉ của một node cụ thể mà chủ yếu xác định loại message và mức độ ưu tiên của message. CAN hỗ trợ hai dạng Identifier chính: Standard ID 11 bit và Extended ID 29 bit.

Việc hiểu rõ hai loại ID này rất quan trọng vì Identifier không chỉ được sử dụng để lọc message mà còn trực tiếp tham gia vào cơ chế arbitration của CAN.

1. Identifier trong CAN là gì?

Khi một node muốn truyền dữ liệu lên CAN bus, nó không gửi dữ liệu đến một node đích cụ thể như trong nhiều giao thức mạng khác. Thay vào đó, node gửi một message với một Identifier.

Các node khác trên bus sẽ kiểm tra Identifier và quyết định xem message đó có cần được xử lý hay không.

Điểm quan trọng: CAN sử dụng mô hình message-oriented. Vì vậy, ID thường mô tả nội dung hoặc ý nghĩa của message thay vì mô tả địa chỉ của thiết bị nhận.

2. Standard ID – Identifier 11 bit

Standard Identifier, thường được gọi là Standard ID hoặc 11-bit ID, sử dụng 11 bit để biểu diễn Identifier.

Với 11 bit, số lượng giá trị ID có thể biểu diễn là: 

2^11 = 2048 giá trị

Do đó, Standard ID có phạm vi giá trị từ: 

0x000 → 0x7FF

Ví dụ:

CAN ID Ví dụ ý nghĩa
0x100 Engine status
0x200 Vehicle speed
0x300 Temperature information
Các giá trị trên chỉ là ví dụ minh họa. Ý nghĩa thực tế của từng CAN ID phụ thuộc vào thiết kế của hệ thống hoặc specification của dự án.

3. Extended ID – Identifier 29 bit

Khi hệ thống cần nhiều Identifier hơn Standard CAN có thể cung cấp, CAN hỗ trợ Extended Identifier, hay Extended ID.

Extended ID sử dụng tổng cộng 29 bit để biểu diễn Identifier. Vì vậy số lượng giá trị có thể biểu diễn là: 

2^29 = 536,870,912 giá trị

Phạm vi Identifier về mặt bit là: 

0x00000000 → 0x1FFFFFFF

Extended ID cho phép một hệ thống lớn sử dụng không gian Identifier rộng hơn, đặc biệt khi có nhiều loại message hoặc cần một cách tổ chức ID phức tạp hơn.

4. So sánh Standard ID và Extended ID

5. Identifier nằm ở đâu trong CAN Frame?

Identifier nằm ở phần đầu của CAN frame và được truyền trước phần Data. Đây là lý do ID có thể tham gia vào quá trình arbitration trước khi node truyền toàn bộ dữ liệu.

Standard ID và Extended ID có cấu trúc frame khác nhau ở phần Identifier và một số bit điều khiển liên quan. Tuy nhiên, cả hai đều sử dụng Identifier trong quá trình arbitration.

6. ID và cơ chế Arbitration

Một trong những điểm quan trọng nhất của CAN là nhiều node có thể bắt đầu truyền cùng lúc. CAN cần một cơ chế để quyết định node nào được tiếp tục truyền mà không làm hỏng message.

Cơ chế này gọi là bitwise arbitration. CAN sử dụng hai trạng thái:

  • Dominant bit: logic 0.
  • Recessive bit: logic 1.

Khi hai node truyền cùng lúc, node nào phát recessive nhưng đọc được dominant trên bus sẽ nhận ra rằng nó đã thua arbitration và dừng truyền.

Ví dụ arbitration giữa hai Standard ID

Giả sử hai node muốn truyền hai message:

Node CAN ID Binary
Node A 0x100 001 0000 0000
Node B 0x200 010 0000 0000

Các node bắt đầu truyền ID từ bit có trọng số cao nhất. Ở bit đầu tiên: 

Node A: 0  → dominant
Node B: 0  → dominant

Hai node vẫn tiếp tục. Ở bit tiếp theo: 

Node A: 0  → dominant
Node B: 1  → recessive

Bus sẽ giữ trạng thái dominant: 

Bus = 0

Node B đã gửi 1 nhưng đọc thấy 0. Vì vậy Node B biết rằng nó đã thua arbitration và dừng truyền. Node A tiếp tục truyền frame của mình.

Quy tắc quan trọng: Trong CAN, ID có giá trị số nhỏ hơn thường có mức ưu tiên cao hơn, bởi vì các bit 0 ở vị trí cao hơn sẽ thắng các bit 1 tương ứng trong quá trình arbitration.

7. Vì sao ID nhỏ hơn có ưu tiên cao hơn?

Điều này xuất phát trực tiếp từ đặc tính dominant = 0 và recessive = 1.

Có thể hình dung đơn giản như sau:

Node A Node B Bus Kết quả
0 0 0 Tiếp tục
0 1 0 Node B thua
1 0 0 Node A thua
1 1 1 Tiếp tục

Vì vậy, trong quá trình thiết kế hệ thống CAN, việc phân bổ ID không chỉ là đặt một con số bất kỳ. ID còn có thể được sử dụng để thể hiện mức độ ưu tiên truyền thông.

8. Standard ID và Extended ID trong Arbitration

Standard ID và Extended ID đều có thể tham gia arbitration. Tuy nhiên, Extended Frame có thêm các bit liên quan đến việc phân biệt loại Identifier.

Trong trường hợp các frame bắt đầu giống nhau, cấu trúc của CAN Frame sẽ quyết định cách arbitration tiếp tục diễn ra.

Khi phân tích arbitration trong một hệ thống thực tế, không nên chỉ nhìn vào giá trị ID dưới dạng số thập phân. Cần xem xét từng bit được truyền trên bus và thứ tự các trường của frame.

9. ID và Message Filtering

Ngoài arbitration, Identifier còn được sử dụng để lọc message tại CAN controller.

Một ECU có thể không cần xử lý tất cả message xuất hiện trên bus. CAN controller có thể được cấu hình để chỉ nhận những ID phù hợp với nhu cầu của ECU.

Ví dụ, một ECU có thể quan tâm đến: 

0x100  → Engine status
0x200  → Vehicle speed
0x300  → Temperature

Các message có ID khác có thể được controller bỏ qua trước khi chuyển lên phần mềm ứng dụng.

Mask và Filter

Nhiều CAN controller cung cấp cơ chế acceptance filter và mask. Chúng cho phép kiểm tra một hoặc nhiều bit của Identifier thay vì phải kiểm tra từng ID riêng biệt.

Khái niệm Ý nghĩa
Filter Giá trị Identifier mà controller muốn nhận
Mask Xác định những bit nào của Identifier cần được so sánh
Acceptance Message được chấp nhận nếu thỏa điều kiện lọc

10. Khi nào dùng Standard ID và Extended ID?

Tình huống Gợi ý
Hệ thống nhỏ, số lượng message không nhiều Standard ID
Cần giảm overhead của Identifier Standard ID

11. Một số lưu ý khi thiết kế CAN ID

  • Không nên chọn ID hoàn toàn ngẫu nhiên nếu ID còn được sử dụng để phân cấp mức độ ưu tiên của message.
  • Message có yêu cầu thời gian nghiêm ngặt thường cần được xem xét với mức ưu tiên phù hợp.
  • Cần tránh thiết kế quá nhiều message có mức ưu tiên cao, vì chúng có thể làm các message ưu tiên thấp phải chờ lâu.
  • Nên thống nhất quy tắc phân bổ ID giữa các ECU trong cùng một dự án.
  • Phần mềm phải sử dụng đúng loại Identifier: Standard hoặc Extended.

12. Ví dụ cấu hình CAN ID trong C

Ví dụ dưới đây minh họa cách một CAN message có thể được mô tả trong phần mềm. Cấu trúc thực tế phụ thuộc vào CAN driver hoặc MCU đang sử dụng. 

typedef struct
{
    uint32_t id;
    uint8_t  is_extended;
    uint8_t  dlc;
    uint8_t  data[8];
} can_message_t;

can_message_t msg = {
    .id = 0x200,
    .is_extended = 0,
    .dlc = 2,
    .data = {0x12, 0x34}
};

Trong ví dụ này:

  • id = 0x200: Identifier của message.
  • is_extended = 0: sử dụng Standard ID.
  • dlc = 2: message chứa 2 byte dữ liệu.
  • data: nội dung dữ liệu được truyền.
Tên field và cách biểu diễn is_extended có thể khác nhau giữa các CAN driver. Khi làm việc với một MCU cụ thể, cần kiểm tra API và tài liệu của CAN controller đó.

13. Tóm tắt

Standard ID sử dụng Identifier 11 bit, cung cấp 2,048 giá trị và phù hợp với nhiều hệ thống CAN thông thường.

Extended ID sử dụng Identifier 29 bit, cung cấp không gian Identifier lớn hơn rất nhiều và phù hợp với những hệ thống cần nhiều ID hơn.

Identifier không chỉ dùng để nhận diện message mà còn đóng vai trò quan trọng trong arbitration và message filtering. Trong arbitration, bit dominant (0) thắng bit recessive (1), vì vậy message có ID ưu tiên cao sẽ có cơ hội giành quyền truyền trước.
