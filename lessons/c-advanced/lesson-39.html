Bài 39: Null Pointer Protection & Pointer Validation

Pointer là một thành phần quan trọng trong ngôn ngữ C, cho phép chương trình truy cập và thao tác trực tiếp với dữ liệu thông qua địa chỉ bộ nhớ. Trong Embedded Systems, Pointer được sử dụng rộng rãi khi làm việc với Hardware Register, Peripheral Driver, Buffer, Structure và các module phần mềm.

Tuy nhiên, việc sử dụng Pointer không đúng cách có thể dẫn đến những lỗi nghiêm trọng như truy cập vùng nhớ không hợp lệ, ghi dữ liệu sai vị trí hoặc làm chương trình hoạt động không ổn định.

Một trong những trường hợp cần được kiểm soát đầu tiên là Null Pointer. Khi một Pointer không trỏ đến đối tượng hợp lệ nhưng chương trình vẫn cố gắng truy cập dữ liệu thông qua Pointer đó, hành vi của chương trình có thể trở nên không xác định.

Mục tiêu bài học: Hiểu nguyên nhân xuất hiện Null Pointer, cách kiểm tra Pointer trước khi truy cập, cách bảo vệ tham số Pointer trong Function và các nguyên tắc sử dụng Pointer an toàn trong C Embedded.

1. Introduction to Null Pointer

1.1. Null Pointer là gì?

Null Pointer là một Pointer có giá trị bằng Null Pointer Constant, thường được biểu diễn bằng macro NULL trong C. Nó được sử dụng để thể hiện rằng Pointer hiện không trỏ đến một đối tượng hoặc function hợp lệ.

Trong C, Null Pointer có thể được khởi tạo bằng cách sử dụng hằng số NULL hoặc giá trị 0. 

#include <stddef.h>

int main(void)
{
    int *ptr = NULL;

    return 0;
}

Trong ví dụ trên, ptr là một Pointer kiểu int nhưng chưa trỏ đến một đối tượng int hợp lệ.

Việc khởi tạo Pointer bằng NULL giúp thể hiện rõ trạng thái chưa có địa chỉ hợp lệ thay vì để Pointer chứa một giá trị không xác định.

1.2. NULL và Null Pointer có giống nhau không?

Hai khái niệm này có liên quan nhưng cần phân biệt:

  • Null Pointer Constant: Một hằng số được sử dụng để tạo giá trị Null Pointer. Trong C, integer constant expression có giá trị 0 hoặc biểu thức như vậy được ép kiểu void * là các dạng Null Pointer Constant.
  • NULL: Macro được định nghĩa trong các header chuẩn như <stddef.h>. Macro này mở rộng thành một Null Pointer Constant.
  • Null Pointer: Giá trị Pointer được tạo ra từ Null Pointer Constant và không trỏ đến đối tượng hoặc function hợp lệ.

Ví dụ: 

#include <stddef.h>

int *ptr1 = NULL;
int *ptr2 = 0;

Cả hai cách trên đều khởi tạo Pointer thành Null Pointer. Trong code thực tế, sử dụng NULL thường giúp thể hiện ý nghĩa rõ ràng hơn.

1.3. Null Pointer có phải địa chỉ bộ nhớ bằng 0 không?

Đây là một điểm quan trọng khi tìm hiểu Pointer trong C.

Theo chuẩn ngôn ngữ C, Null Pointer là một giá trị Pointer đặc biệt, không nhất thiết phải có biểu diễn bit hoặc địa chỉ vật lý bằng 0.

Trên nhiều kiến trúc MCU phổ biến, Null Pointer thường được biểu diễn bằng giá trị địa chỉ 0. Tuy nhiên, không nên dựa vào giả định này để xây dựng chương trình phụ thuộc vào một kiến trúc cụ thể.

Ví dụ, không nên xem việc so sánh một Pointer với địa chỉ vật lý 0 dưới dạng số nguyên là cách kiểm tra Null Pointer tổng quát. Hãy sử dụng NULL hoặc 0 theo quy tắc của C.

1.4. Phân biệt Null Pointer và Wild Pointer

Null Pointer và Wild Pointer đều là những trạng thái Pointer cần được chú ý, nhưng nguyên nhân và đặc điểm của chúng khác nhau.

Tiêu chí Null Pointer Wild Pointer
Trạng thái Được khởi tạo thành Null Pointer. Pointer chưa được khởi tạo hợp lệ.
Giá trị Có giá trị Null Pointer xác định. Giá trị không xác định nếu là biến tự động chưa được khởi tạo.
Nguyên nhân Chưa có đối tượng được trỏ đến hoặc Pointer được đặt về NULL. Quên khởi tạo Pointer trước khi sử dụng.
Cách phòng tránh Kiểm tra trước khi dereference. Khởi tạo Pointer trước khi sử dụng và quản lý vòng đời rõ ràng.

Ví dụ về Wild Pointer: 

void Example(void)
{
    int *ptr;

    /* ptr has an indeterminate value here */

    /* Do not dereference ptr */
}

Biến Pointer cục bộ ptr chưa được khởi tạo. Vì vậy, không thể giả định nó chứa địa chỉ hợp lệ hoặc Null Pointer.

2. Causes of Null Pointer

2.1. Pointer được khởi tạo bằng NULL

Đây là trường hợp phổ biến và hoàn toàn hợp lệ. Pointer được đặt thành NULL để thể hiện rằng hiện tại chưa có đối tượng nào được liên kết với nó. 

#include <stddef.h>

int main(void)
{
    int *data = NULL;

    if (data == NULL)
    {
        /* No valid object is associated with data */
    }

    return 0;
}

2.2. Function trả về NULL

Một số function có thể trả về Null Pointer khi không tìm thấy dữ liệu hoặc không thể thực hiện thao tác theo yêu cầu.

Ví dụ, function tìm kiếm một phần tử trong danh sách có thể trả về NULL nếu không tìm thấy phần tử phù hợp. 

#include <stddef.h>
#include <stdint.h>

uint8_t deviceList[4] = {10U, 20U, 30U, 40U};

uint8_t *Find_Device(uint8_t id)
{
    uint8_t i;

    for (i = 0U; i < 4U; i++)
    {
        if (deviceList[i] == id)
        {
            return &deviceList[i];
        }
    }

    return NULL;
}

Nếu không tìm thấy phần tử có giá trị tương ứng, function trả về NULL.

Vì vậy, bên gọi function phải kiểm tra kết quả trước khi sử dụng Pointer.

2.3. Pointer được đặt lại thành NULL

Trong quá trình vận hành, một Pointer có thể được đặt lại thành NULL khi không còn được sử dụng. 

#include <stddef.h>

void Example(void)
{
    int value = 100;
    int *ptr = &value;

    /* Use ptr while it is valid */

    ptr = NULL;

    /* ptr no longer refers to value */
}

Việc đặt Pointer thành NULL có thể giúp thể hiện rõ trạng thái không còn liên kết với đối tượng.

Tuy nhiên, thao tác này không làm cho một vùng nhớ đã được giải phóng trở nên hợp lệ, cũng không tự động sửa những Pointer khác đang tham chiếu đến cùng vùng nhớ.

2.4. Dynamic Memory Allocation thất bại

Khi sử dụng các function cấp phát bộ nhớ động như malloc() hoặc calloc(), kết quả có thể là NULL nếu yêu cầu cấp phát không thành công. 

#include <stdlib.h>
#include <stddef.h>

void Example(void)
{
    int *buffer;

    buffer = malloc(10U * sizeof(int));

    if (buffer == NULL)
    {
        /* Allocation failed */
        return;
    }

    /* Use allocated memory */

    free(buffer);
    buffer = NULL;
}

Chương trình cần kiểm tra kết quả cấp phát trước khi truy cập vùng nhớ. Không được giả định rằng malloc() luôn thành công.

Các kỹ thuật quản lý Heap và Dynamic Memory Allocation đã được tìm hiểu trong Bài 6.

2.5. Function hoặc Module không có dữ liệu hợp lệ để trả về

Trong thiết kế phần mềm theo module, một function có thể trả về NULL để biểu thị rằng không có dữ liệu phù hợp.

Ví dụ: 

#include <stddef.h>
#include <stdint.h>

typedef struct
{
    uint8_t id;
    uint16_t value;
} SensorData_t;

SensorData_t *Sensor_GetData(uint8_t sensorId)
{
    /* Search sensor data */

    if (sensorId != 1U)
    {
        return NULL;
    }

    /* Illustrative result */
    return NULL;
}

Trong ví dụ thực tế, function sẽ trả về địa chỉ của dữ liệu nếu tìm thấy. Nếu không có dữ liệu phù hợp, nó trả về NULL.

3. Null Pointer Dereferencing

3.1. Dereferencing Pointer là gì?

Dereferencing là thao tác truy cập đối tượng thông qua Pointer bằng toán tử *. 

int value = 100;
int *ptr = &value;

int result = *ptr;

Trong ví dụ trên, ptr chứa địa chỉ của biến value. Khi sử dụng *ptr, chương trình truy cập giá trị được lưu tại địa chỉ đó.

3.2. Null Pointer Dereferencing là gì?

Null Pointer Dereferencing xảy ra khi chương trình cố gắng truy cập dữ liệu thông qua một Null Pointer. 

#include <stddef.h>

int main(void)
{
    int *ptr = NULL;

    /* Invalid operation */
    *ptr = 100;

    return 0;
}

Trong ví dụ này, ptr là Null Pointer nhưng chương trình vẫn sử dụng toán tử * để ghi dữ liệu.

Đây là hành vi không xác định (Undefined Behavior) theo chuẩn C. Chương trình có thể bị lỗi, dừng hoạt động hoặc thể hiện những hành vi không thể dự đoán.

3.3. Truy cập thành viên Structure thông qua Null Pointer

Không chỉ toán tử *, toán tử -> cũng thực hiện truy cập thành viên thông qua Pointer. 

#include <stddef.h>
#include <stdint.h>

typedef struct
{
    uint8_t id;
    uint16_t value;
} Sensor_t;

void Example(void)
{
    Sensor_t *sensor = NULL;

    /* Invalid operation */
    sensor->value = 500U;
}

Biểu thức sensor->value tương đương với thao tác truy cập thành viên thông qua (*sensor).value.

Vì sensor là Null Pointer, chương trình không được thực hiện thao tác truy cập này.

3.4. Hậu quả của Null Pointer Dereferencing

Một số hậu quả có thể xảy ra khi chương trình dereference Null Pointer:

  • Chương trình gặp lỗi truy cập bộ nhớ.
  • Hệ thống có thể phát sinh exception hoặc fault tùy kiến trúc MCU.
  • Task hoặc chương trình có thể dừng hoạt động.
  • Trạng thái hệ thống có thể không còn được duy trì như thiết kế.
  • Khó xác định nguyên nhân nếu lỗi xảy ra trong một module khác với module tạo Pointer.

Trên các MCU có cơ chế Memory Protection Unit (MPU), việc truy cập một vùng nhớ không được phép có thể tạo ra Memory Fault. Tuy nhiên, hành vi cụ thể phụ thuộc vào kiến trúc và cấu hình phần cứng.

4. Pointer Validation

4.1. Pointer Validation là gì?

Pointer Validation là quá trình kiểm tra các điều kiện liên quan đến Pointer trước khi sử dụng Pointer để truy cập dữ liệu.

Mục tiêu là hạn chế những thao tác truy cập bộ nhớ không hợp lệ và đảm bảo Pointer được sử dụng đúng theo hợp đồng của function hoặc module.

Một số nội dung cần xem xét khi kiểm tra Pointer:

  • Pointer có phải là Null Pointer hay không.
  • Pointer có được khởi tạo trước khi sử dụng hay không.
  • Đối tượng mà Pointer tham chiếu có còn tồn tại hay không.
  • Pointer có được sử dụng đúng kiểu dữ liệu hay không.
  • Pointer có được phép đọc hoặc ghi theo yêu cầu của function hay không.
  • Vùng dữ liệu có đủ kích thước cho thao tác dự kiến hay không.

4.2. Kiểm tra Null Pointer

Đây là bước kiểm tra cơ bản và phổ biến nhất. Có thể sử dụng toán tử so sánh == hoặc != với NULL. 

#include <stddef.h>

void Process_Data(int *data)
{
    if (data == NULL)
    {
        return;
    }

    *data = 100;
}

Nếu data là Null Pointer, function kết thúc ngay lập tức và không thực hiện thao tác truy cập dữ liệu.

4.3. Kiểm tra Pointer trước khi đọc dữ liệu

Khi function cần đọc dữ liệu thông qua Pointer, cần kiểm tra Pointer trước khi sử dụng toán tử dereference. 

#include <stddef.h>
#include <stdint.h>
#include <stdbool.h>

bool Read_Value(const uint16_t *data,
                uint16_t *result)
{
    if ((data == NULL) || (result == NULL))
    {
        return false;
    }

    *result = *data;

    return true;
}

Function trên sử dụng hai Pointer:

  • data: Pointer đến dữ liệu đầu vào chỉ đọc.
  • result: Pointer đến vùng nhớ dùng để lưu kết quả.

Cả hai Pointer đều được kiểm tra trước khi truy cập.

4.4. Kiểm tra Pointer trước khi ghi dữ liệu

Đối với Pointer được sử dụng để ghi dữ liệu, ngoài việc kiểm tra Null Pointer, cần đảm bảo vùng nhớ mà Pointer tham chiếu thực sự cho phép ghi. 

#include <stddef.h>
#include <stdint.h>
#include <stdbool.h>

bool Update_Value(uint16_t *destination,
                  uint16_t newValue)
{
    if (destination == NULL)
    {
        return false;
    }

    *destination = newValue;

    return true;
}

Function chỉ kiểm tra được Pointer có phải Null Pointer hay không. Việc đảm bảo destination trỏ đến một đối tượng uint16_t còn tồn tại và có thể ghi vẫn là trách nhiệm của bên gọi function theo hợp đồng đã thiết kế.

4.5. Pointer Validation không chỉ là kiểm tra NULL

Một điểm rất quan trọng là kiểm tra ptr != NULL không đồng nghĩa với việc Pointer chắc chắn hợp lệ.

Ví dụ: 

int *ptr;

/* Assume ptr contains an arbitrary value */

if (ptr != NULL)
{
    /* This does not prove ptr is valid */
}

Nếu ptr chưa được khởi tạo, việc đọc giá trị của nó đã là một vấn đề. Không thể sử dụng phép so sánh với NULL để biến một Pointer chưa khởi tạo thành Pointer hợp lệ.

Một Pointer khác có thể không bằng NULL nhưng vẫn trỏ đến:

  • Đối tượng đã hết lifetime.
  • Vùng nhớ đã được giải phóng.
  • Địa chỉ không thuộc vùng nhớ hợp lệ.
  • Vùng nhớ không có quyền ghi.
  • Đối tượng không phù hợp với kiểu dữ liệu mà chương trình đang sử dụng.
Kiến thức quan trọng: Trong C tiêu chuẩn, không có một function tổng quát có thể nhận bất kỳ Pointer nào rồi xác nhận chắc chắn rằng địa chỉ đó hợp lệ. Kiểm tra NULL chỉ phát hiện Null Pointer. Tính hợp lệ của Pointer còn phụ thuộc vào nguồn gốc, kiểu dữ liệu, lifetime, kích thước vùng nhớ và quyền truy cập.

5. Function Pointer Parameter Validation

5.1. Tại sao cần kiểm tra Pointer Parameter?

Trong C, Function thường nhận Pointer làm tham số để đọc hoặc cập nhật dữ liệu của bên gọi.

Việc sử dụng Pointer giúp giảm sao chép dữ liệu và cho phép Function thao tác trực tiếp trên đối tượng được truyền vào.

Tuy nhiên, nếu bên gọi truyền Null Pointer hoặc không đáp ứng yêu cầu về vùng nhớ, Function có thể gặp lỗi khi truy cập dữ liệu.

5.2. Kiểm tra Pointer Parameter trong Function

Ví dụ một Function nhận Pointer đến một Structure để cập nhật thông tin: 

#include <stddef.h>
#include <stdint.h>
#include <stdbool.h>

typedef struct
{
    uint8_t id;
    uint16_t value;
} Device_t;

bool Device_Update(Device_t *device,
                   uint16_t newValue)
{
    if (device == NULL)
    {
        return false;
    }

    device->value = newValue;

    return true;
}

Function kiểm tra device trước khi sử dụng toán tử ->.

Đây là một quy tắc nên áp dụng đối với những Function có tham số Pointer có thể nhận giá trị NULL.

5.3. Kiểm tra nhiều Pointer Parameter

Một Function có thể nhận nhiều Pointer khác nhau. Khi đó, cần kiểm tra tất cả những Pointer có thể được sử dụng trước khi thực hiện thao tác truy cập. 

#include <stddef.h>
#include <stdint.h>
#include <stdbool.h>

bool Calculate_Sum(const uint16_t *input1,
                   const uint16_t *input2,
                   uint32_t *result)
{
    if ((input1 == NULL) ||
        (input2 == NULL) ||
        (result == NULL))
    {
        return false;
    }

    *result = (uint32_t)(*input1) + (uint32_t)(*input2);

    return true;
}

Function chỉ thực hiện phép cộng sau khi cả ba Pointer đều vượt qua bước kiểm tra Null Pointer.

5.4. Kiểm tra Pointer-to-Pointer

Đối với Double Pointer, chương trình cần kiểm tra từng cấp Pointer trước khi truy cập cấp tiếp theo. 

#include <stddef.h>
#include <stdint.h>
#include <stdbool.h>

bool Update_Data(uint16_t **data)
{
    if (data == NULL)
    {
        return false;
    }

    if (*data == NULL)
    {
        return false;
    }

    **data = 100U;

    return true;
}

Trong ví dụ trên:

  • data là Pointer đến một Pointer kiểu uint16_t.
  • *data là Pointer cấp thứ hai.
  • **data là giá trị tại đối tượng được Pointer cấp thứ hai tham chiếu.

Function phải kiểm tra data trước khi đọc *data, sau đó kiểm tra *data trước khi truy cập **data.

Lưu ý rằng những phép kiểm tra này vẫn giả định Pointer đã được khởi tạo và vùng nhớ mà chúng tham chiếu đáp ứng hợp đồng của Function.

5.5. Thiết kế API với Pointer có thể NULL và không thể NULL

Khi thiết kế API trong C, nên xác định rõ một tham số Pointer có được phép nhận NULL hay không.

Ví dụ: 

/*
 * device must point to a valid Device_t object.
 * NULL is not accepted.
 */
bool Device_Update(Device_t *device,
                   uint16_t value);

/*
 * output is optional.
 * NULL means the caller does not need the result.
 */
void Device_GetStatus(const Device_t *device,
                      uint8_t *output);

Trong ví dụ thứ hai, nếu thiết kế cho phép output là tham số tùy chọn thì Function có thể xử lý trường hợp này một cách rõ ràng. 

void Device_GetStatus(const Device_t *device,
                      uint8_t *output)
{
    if (device == NULL)
    {
        return;
    }

    if (output != NULL)
    {
        *output = device->id;
    }
}

Cách thiết kế này giúp người sử dụng API hiểu rõ tham số nào bắt buộc và tham số nào có thể bỏ qua.

6. Safe Pointer Usage in C

6.1. Khởi tạo Pointer ngay khi khai báo

Một nguyên tắc quan trọng là không để Pointer ở trạng thái chưa khởi tạo nếu chương trình chưa có địa chỉ hợp lệ để gán. 

#include <stddef.h>

void Example(void)
{
    int *ptr = NULL;

    /* Other operations */

    if (ptr != NULL)
    {
        /* Access only after ptr has been assigned a valid object */
    }
}

Việc khởi tạo bằng NULL giúp thể hiện trạng thái ban đầu rõ ràng và tránh sử dụng nhầm giá trị Pointer chưa xác định.

6.2. Đặt Pointer về NULL khi không còn sử dụng

Sau khi Pointer không còn được sử dụng, có thể đặt nó về NULL để thể hiện rằng nó không còn tham chiếu đến đối tượng nào. 

#include <stddef.h>
#include <stdlib.h>

void Example(void)
{
    int *buffer = malloc(5U * sizeof(int));

    if (buffer == NULL)
    {
        return;
    }

    /* Use buffer */

    free(buffer);
    buffer = NULL;
}

Cách làm này giúp giảm khả năng sử dụng lại Pointer thông qua chính biến Pointer đó sau khi giải phóng bộ nhớ.

Tuy nhiên, nếu có nhiều Pointer cùng tham chiếu đến vùng nhớ, việc đặt một Pointer về NULL không ảnh hưởng đến các Pointer còn lại.

6.3. Không trả về địa chỉ của biến Local

Một lỗi thường gặp là trả về địa chỉ của biến cục bộ có Automatic Storage Duration. 

int *Get_Value(void)
{
    int value = 100;

    return &value; /* Incorrect */
}

Khi Function kết thúc, lifetime của biến local value kết thúc. Pointer được trả về không còn tham chiếu đến một đối tượng còn tồn tại.

Cách sửa phụ thuộc vào yêu cầu thiết kế. Một lựa chọn là để bên gọi cung cấp vùng nhớ đầu ra: 

#include <stddef.h>
#include <stdbool.h>

bool Get_Value(int *output)
{
    if (output == NULL)
    {
        return false;
    }

    *output = 100;

    return true;
}

Một lựa chọn khác là sử dụng vùng nhớ có lifetime phù hợp, chẳng hạn biến static hoặc một đối tượng được quản lý bởi module. Việc lựa chọn cần dựa trên yêu cầu về tính tái nhập và quản lý trạng thái.

6.4. Không sử dụng Pointer sau khi đối tượng hết lifetime

Pointer chỉ có thể được sử dụng để truy cập đối tượng trong thời gian lifetime của đối tượng đó còn hiệu lực.

Ví dụ, một Pointer tham chiếu đến biến local của Function không thể tiếp tục được sử dụng sau khi Function kết thúc.

Tương tự, Pointer trỏ đến vùng nhớ được cấp phát động không được sử dụng để truy cập dữ liệu sau khi vùng nhớ đó đã được giải phóng.

Những lỗi liên quan đến Dangling Pointer và Use-after-free đã được giới thiệu trong Bài 7.

6.5. Không tự ý thay đổi giá trị Pointer bằng địa chỉ không được xác định

Trong Embedded Programming, lập trình viên có thể phải thao tác với địa chỉ bộ nhớ hoặc Hardware Register.

Tuy nhiên, việc gán một giá trị địa chỉ tùy ý cho Pointer không đảm bảo rằng địa chỉ đó có thể được truy cập hợp lệ. 

#include <stdint.h>

void Example(void)
{
    volatile uint32_t *registerPtr;

    /*
     * The address below is illustrative only.
     * Real register addresses must come from the MCU datasheet.
     */
    registerPtr = (volatile uint32_t *)0x40000000U;

    /* Access only when the address and access width are valid
       for the target MCU and peripheral */
}

Trong Embedded Systems, địa chỉ của Hardware Register phải được xác định từ Reference Manual hoặc Datasheet của MCU. Không thể xem mọi địa chỉ số nguyên đều là vùng nhớ có thể truy cập.

7. Null Pointer Protection in Embedded Systems

7.1. Pointer trong Peripheral Driver

Trong Embedded Systems, Driver thường sử dụng Pointer để nhận cấu hình, dữ liệu hoặc đối tượng quản lý Peripheral.

Ví dụ, một UART Driver có thể nhận Pointer đến cấu trúc cấu hình: 

#include <stddef.h>
#include <stdint.h>
#include <stdbool.h>

typedef struct
{
    uint32_t baudRate;
    uint8_t dataBits;
    uint8_t stopBits;
} UART_Config_t;

bool UART_Initialize(const UART_Config_t *config)
{
    if (config == NULL)
    {
        return false;
    }

    if (config->baudRate == 0U)
    {
        return false;
    }

    if ((config->dataBits < 7U) ||
        (config->dataBits > 9U))
    {
        return false;
    }

    /* Initialize UART using validated configuration */

    return true;
}

Driver kiểm tra Pointer cấu hình trước khi truy cập các thành viên của Structure.

Sau đó, Driver tiếp tục kiểm tra một số giá trị cấu hình quan trọng trước khi thực hiện khởi tạo Peripheral.

7.2. Pointer trong Sensor Driver

Một Sensor Driver có thể cung cấp Function để đọc dữ liệu và ghi kết quả vào vùng nhớ do bên gọi cung cấp. 

#include <stddef.h>
#include <stdint.h>
#include <stdbool.h>

typedef enum
{
    SENSOR_OK = 0,
    SENSOR_INVALID_PARAMETER,
    SENSOR_NOT_READY
} SensorStatus_t;

SensorStatus_t Sensor_ReadTemperature(int16_t *temperature)
{
    if (temperature == NULL)
    {
        return SENSOR_INVALID_PARAMETER;
    }

    /* Check sensor readiness */

    /* Read sensor data from hardware */

    *temperature = 25;

    return SENSOR_OK;
}

Function kiểm tra tham số đầu ra trước khi ghi dữ liệu. Nếu bên gọi truyền Null Pointer, Driver trả về trạng thái lỗi thay vì thực hiện thao tác ghi.

7.3. Pointer trong Communication Driver

Communication Driver thường sử dụng Pointer để nhận hoặc truyền dữ liệu. Ví dụ, một Function truyền dữ liệu UART có thể nhận Pointer đến Buffer. 

#include <stddef.h>
#include <stdint.h>
#include <stdbool.h>

bool UART_Transmit(const uint8_t *data,
                   uint16_t length)
{
    if (data == NULL)
    {
        return false;
    }

    if (length == 0U)
    {
        return false;
    }

    /* Transmit data using UART peripheral */

    return true;
}

Function kiểm tra Pointer dữ liệu và độ dài trước khi thực hiện thao tác truyền.

Kiểm tra kích thước Buffer và giới hạn truy cập dữ liệu sẽ được tìm hiểu chi tiết trong Bài 40: Buffer Overflow Prevention.

7.4. Pointer trong Hardware Register Access

Trong Memory-Mapped I/O, Pointer được sử dụng để truy cập địa chỉ của các Peripheral Register. 

#include <stdint.h>

#define GPIO_REGISTER_ADDRESS    (0x40020000U)

#define GPIO_REGISTER \
    (*(volatile uint32_t *)GPIO_REGISTER_ADDRESS)

void GPIO_SetRegister(uint32_t value)
{
    GPIO_REGISTER = value;
}

Trong ví dụ này, GPIO_REGISTER đại diện cho một Hardware Register tại địa chỉ được giả định.

Không nên kiểm tra Pointer của Hardware Register bằng cách so sánh với NULL rồi kết luận rằng địa chỉ đó hợp lệ. Địa chỉ Register phải được xác định từ tài liệu phần cứng và được truy cập đúng quy tắc của MCU.

7.5. Null Pointer Protection trong Automotive Embedded Software

Trong Automotive Embedded Software, các module thường trao đổi dữ liệu thông qua Pointer hoặc những cấu trúc dữ liệu được truyền qua giao diện.

Một số vị trí cần chú ý:

  • Pointer đến cấu trúc cấu hình ECU.
  • Pointer đến dữ liệu Sensor.
  • Pointer đến Buffer nhận hoặc truyền dữ liệu.
  • Pointer đến trạng thái của một Software Component.
  • Pointer được truyền qua API giữa các module.
  • Pointer đến vùng nhớ được quản lý bởi Driver.

Các API cần quy định rõ Pointer nào bắt buộc, Pointer nào tùy chọn, ai chịu trách nhiệm quản lý lifetime và vùng nhớ có được phép ghi hay không.

Liên hệ Automotive: Việc kiểm tra Pointer là một phần của Defensive Programming. Trong dự án thực tế, quy tắc sử dụng Pointer còn phải tuân theo kiến trúc phần mềm, Coding Standard và yêu cầu an toàn của hệ thống.

8. Common Mistakes in Pointer Validation

8.1. Dereference trước khi kiểm tra NULL

Đây là lỗi cơ bản khi sử dụng Pointer. 

void Process(int *ptr)
{
    *ptr = 100;

    if (ptr == NULL)
    {
        return;
    }
}

Việc kiểm tra được thực hiện sau khi Pointer đã bị dereference. Vì vậy, kiểm tra này không bảo vệ được thao tác truy cập phía trên.

Cách khắc phục: Kiểm tra Pointer trước mọi thao tác truy cập dữ liệu.

void Process(int *ptr)
{
    if (ptr == NULL)
    {
        return;
    }

    *ptr = 100;
}

8.2. Cho rằng Pointer khác NULL chắc chắn hợp lệ

Pointer có thể khác NULL nhưng vẫn trỏ đến vùng nhớ không hợp lệ, đối tượng đã hết lifetime hoặc vùng nhớ không có quyền truy cập.

Cách khắc phục: Quản lý nguồn gốc Pointer, lifetime và quyền truy cập theo hợp đồng của Function.

8.3. Sử dụng Pointer chưa được khởi tạo

Một Pointer tự động chưa được khởi tạo không có giá trị xác định. Không được sử dụng nó trước khi gán một giá trị hợp lệ.

Cách khắc phục: Khởi tạo Pointer bằng NULL hoặc địa chỉ của đối tượng hợp lệ.

8.4. Quên kiểm tra kết quả cấp phát bộ nhớ

Nếu chương trình sử dụng kết quả malloc() ngay mà không kiểm tra, nó có thể dereference Null Pointer khi cấp phát thất bại.

Cách khắc phục: Kiểm tra kết quả cấp phát trước khi sử dụng vùng nhớ.

8.5. Trả về địa chỉ của biến local

Địa chỉ của biến local không còn hợp lệ sau khi Function kết thúc nếu biến có Automatic Storage Duration.

Cách khắc phục: Sử dụng vùng nhớ có lifetime phù hợp hoặc để bên gọi cung cấp vùng nhớ đầu ra.

8.6. Chỉ đặt một Pointer về NULL sau khi giải phóng bộ nhớ

Khi nhiều Pointer cùng tham chiếu đến một vùng nhớ, việc đặt một Pointer về NULL không làm thay đổi các Pointer còn lại. 

int *ptr1 = malloc(sizeof(int));
int *ptr2 = ptr1;

if (ptr1 != NULL)
{
    free(ptr1);
    ptr1 = NULL;
}

/*
 * ptr2 still contains the old address.
 * Do not access the released object through ptr2.
 */

ptr2 vẫn chứa giá trị địa chỉ cũ sau khi vùng nhớ được giải phóng. Đây là một tình huống có thể dẫn đến Dangling Pointer.

Cách khắc phục: Thiết kế rõ ownership và trách nhiệm quản lý lifetime của vùng nhớ.

8.7. Giả định NULL luôn có biểu diễn bit bằng 0

Không nên xây dựng logic kiểm tra Pointer dựa trên giả định rằng biểu diễn Null Pointer luôn giống một địa chỉ số nguyên bằng 0.

Cách khắc phục: Sử dụng NULL để biểu diễn và kiểm tra Null Pointer theo chuẩn C.

9. Best Practices for Pointer Safety

9.1. Luôn xác định trạng thái ban đầu của Pointer

Pointer nên được khởi tạo ngay khi khai báo nếu chưa có địa chỉ hợp lệ để gán. 

int *data = NULL;

9.2. Kiểm tra Pointer trước khi dereference

Trước khi sử dụng *ptr hoặc ptr->member, cần đảm bảo Pointer đáp ứng các điều kiện đã được xác định.

9.3. Xác định rõ hợp đồng của Function

Mỗi Function nhận Pointer nên mô tả:

  • Pointer có được phép NULL hay không.
  • Pointer được sử dụng để đọc hay ghi dữ liệu.
  • Kiểu đối tượng mà Pointer phải tham chiếu.
  • Lifetime của đối tượng phải kéo dài trong khoảng thời gian nào.
  • Function có giữ lại Pointer sau khi kết thúc hay không.

9.4. Sử dụng const khi Function chỉ đọc dữ liệu

Nếu Function chỉ cần đọc dữ liệu thông qua Pointer, nên sử dụng const để thể hiện rõ mục đích. 

uint16_t Calculate_Total(const uint16_t *data,
                         uint8_t count)
{
    uint16_t total = 0U;
    uint8_t i;

    if (data == NULL)
    {
        return 0U;
    }

    for (i = 0U; i < count; i++)
    {
        total += data[i];
    }

    return total;
}

const uint16_t *data cho biết Function không được thay đổi các giá trị thông qua Pointer này.

Lưu ý: const không đảm bảo Pointer khác NULL hoặc vùng nhớ được tham chiếu luôn hợp lệ.

9.5. Tránh chia sẻ Pointer không có quy tắc quản lý rõ ràng

Khi nhiều module cùng sử dụng một Pointer, cần xác định rõ module nào sở hữu dữ liệu, module nào chỉ đọc và module nào được phép cập nhật.

Điều này giúp hạn chế những lỗi liên quan đến lifetime, giải phóng bộ nhớ và truy cập dữ liệu không đúng thời điểm.

9.6. Kiểm thử các trường hợp Pointer bất thường

Khi kiểm thử Function nhận Pointer, cần xem xét những trường hợp:

  • Pointer hợp lệ trỏ đến một đối tượng đã khởi tạo.
  • Pointer bằng NULL khi API cho phép trường hợp này được kiểm tra.
  • Nhiều tham số Pointer cùng được truyền vào.
  • Pointer đến đối tượng chỉ đọc.
  • Pointer đến đối tượng có lifetime được quản lý bởi module khác.
  • Pointer-to-Pointer có các cấp được khởi tạo đúng theo hợp đồng.

Không nên cố tình dereference một địa chỉ tùy ý để kiểm thử tính hợp lệ. Các trường hợp như Dangling Pointer hoặc truy cập vùng nhớ không hợp lệ nên được phát hiện thông qua phân tích mã nguồn, công cụ kiểm thử phù hợp hoặc môi trường kiểm thử có kiểm soát.

10. Summary

Null Pointer Protection và Pointer Validation là những kỹ thuật quan trọng trong Defensive Programming. Việc kiểm tra Pointer đúng cách giúp hạn chế lỗi truy cập bộ nhớ và tăng độ tin cậy của chương trình C.

Những kiến thức trọng tâm cần ghi nhớ:

  • Null Pointer: Pointer không trỏ đến đối tượng hoặc function hợp lệ.
  • NULL: Macro biểu diễn Null Pointer Constant trong C.
  • Null Pointer Dereferencing: Truy cập dữ liệu thông qua Null Pointer, dẫn đến Undefined Behavior.
  • Pointer Validation: Kiểm tra các điều kiện cần thiết trước khi sử dụng Pointer.
  • Pointer Parameter Validation: Kiểm tra các tham số Pointer của Function trước khi truy cập.
  • Pointer Lifetime: Đảm bảo đối tượng được tham chiếu vẫn tồn tại trong thời gian sử dụng.
  • Pointer Ownership: Xác định trách nhiệm quản lý và sử dụng vùng nhớ.
  • Safe Pointer Usage: Khởi tạo, kiểm tra và sử dụng Pointer theo đúng hợp đồng của Function.
Kiến thức cốt lõi: Kiểm tra ptr != NULL là bước bảo vệ cơ bản nhưng không đủ để chứng minh Pointer hợp lệ. Lập trình viên cần quản lý cả nguồn gốc, kiểu dữ liệu, lifetime và quyền truy cập của đối tượng được Pointer tham chiếu.
