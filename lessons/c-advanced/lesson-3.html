Bài 3: Memory Layout of a C Program

Khi một chương trình C được biên dịch và thực thi, các thành phần bên trong chương trình cần được tổ chức trong bộ nhớ để CPU có thể truy cập và xử lý. Những thành phần này bao gồm mã lệnh, dữ liệu, biến, vùng nhớ tạm thời và các vùng nhớ được sử dụng trong quá trình thực thi.

Memory Layout of a C Program mô tả cách một chương trình được tổ chức thành các vùng nhớ khác nhau. Trong một mô hình phổ biến, các vùng nhớ này bao gồm Text Segment, Read-only Data Segment, Initialized Data Segment, BSS Segment, Heap và Stack.

Việc hiểu rõ Memory Layout giúp lập trình viên biết dữ liệu được lưu trữ ở đâu, chương trình sử dụng bộ nhớ như thế nào và những vùng nhớ nào có liên quan đến quá trình thực thi của một ứng dụng Embedded.

Trong bài học này, chúng ta sẽ tập trung vào tổng quan Memory Layout và vai trò của từng vùng nhớ. Cơ chế hoạt động chi tiết của Stack, Heap, Dynamic Allocation, Memory Alignment và Linker Script sẽ được trình bày ở các bài học tiếp theo.

1. Memory Layout là gì?

Memory Layout là cách tổ chức và phân bố các thành phần của chương trình trong không gian bộ nhớ (Memory Address Space).

Khi thực thi chương trình, CPU cần truy cập các lệnh để xử lý và dữ liệu để thực hiện các phép toán. Những thành phần này không được lưu trữ một cách tùy ý mà được tổ chức thành các vùng nhớ có chức năng và mục đích riêng.

Ví dụ:

  • Mã lệnh của Function được đặt trong vùng nhớ chứa chương trình.
  • Các hằng số và dữ liệu chỉ đọc thường được tổ chức trong vùng dữ liệu chỉ đọc.
  • Các biến Global đã khởi tạo có thể được đặt trong vùng Initialized Data.
  • Các biến Global chưa khởi tạo hoặc được khởi tạo bằng 0 thường thuộc BSS.
  • Bộ nhớ được cấp phát động thường được quản lý trong Heap.
  • Các biến Local và thông tin phục vụ quá trình gọi hàm thường được quản lý trên Stack.

Mỗi vùng nhớ có cách sử dụng khác nhau. Việc phân chia này giúp hệ thống quản lý chương trình và dữ liệu hiệu quả hơn.

2. Tổng quan các vùng nhớ trong chương trình C

Một mô hình Memory Layout phổ biến của chương trình C bao gồm sáu vùng nhớ chính:

Lưu ý: Đây là sơ đồ khái niệm để giải thích các vùng nhớ, không phải sơ đồ địa chỉ cố định cho mọi hệ thống. Thứ tự thực tế, hướng tăng giảm địa chỉ, vị trí Stack và Heap phụ thuộc vào kiến trúc, Compiler, Linker và cấu hình nền tảng.
Memory Region Chức năng chính
Text Segment Lưu trữ mã lệnh của chương trình.
Read-only Data Lưu các dữ liệu chỉ đọc như hằng số và String Literal.
Initialized Data Lưu các biến Global và Static có giá trị khởi tạo khác 0 hoặc thuộc vùng dữ liệu đã khởi tạo.
BSS Lưu các biến Static và Global chưa khởi tạo hoặc được khởi tạo bằng 0.
Heap Quản lý bộ nhớ được cấp phát động trong quá trình thực thi.
Stack Quản lý dữ liệu phục vụ quá trình gọi hàm và các đối tượng có thời gian lưu trữ tự động trong cách triển khai phổ biến.

3. Text Segment (Code Segment)

Text Segment, còn được gọi là Code Segment, là vùng nhớ chứa các lệnh máy được tạo ra từ quá trình biên dịch chương trình.

Đây là phần chứa mã thực thi của các Function trong chương trình C. CPU sẽ lấy các lệnh từ vùng nhớ này để thực hiện các thao tác theo luồng điều khiển của chương trình.

3.1. Thành phần được lưu trong Text Segment

Text Segment thường chứa:

  • Mã lệnh của Function.
  • Mã lệnh của Function main().
  • Mã lệnh của các Function được lập trình viên định nghĩa.
  • Mã thực thi của những thư viện được liên kết vào chương trình nếu chúng nằm trong Image tương ứng.

Ví dụ: 

int add_numbers(int a, int b)
{
    return a + b;
}

int main(void)
{
    int result = add_numbers(10, 20);

    return 0;
}

Trong ví dụ trên, hai Function add_numbers() và main() đều được Compiler chuyển thành mã máy. Phần mã máy tương ứng thường được đặt trong các Section chứa Code, chẳng hạn như .text.

3.2. Đặc điểm của Text Segment

  • Chứa các lệnh máy được thực thi bởi CPU.
  • Thường được tổ chức với quyền truy cập đọc và thực thi.
  • Trong nhiều hệ thống, không cho phép ghi vào vùng mã lệnh khi chương trình chạy.
  • Có thể được lưu trong Flash hoặc một vùng nhớ chứa mã thực thi tùy nền tảng.

Trên nhiều vi điều khiển, mã chương trình được lưu trong bộ nhớ Flash vì Flash có khả năng giữ dữ liệu khi mất nguồn điện.

Trong Embedded Systems, Text Segment thường được ánh xạ vào Flash. Tuy nhiên, một số hệ thống có thể hỗ trợ thực thi code từ RAM, chẳng hạn khi cần chạy một số đoạn chương trình trong vùng RAM chuyên dụng.

4. Read-only Data Segment (.rodata)

Read-only Data Segment là vùng chứa dữ liệu chỉ đọc được chương trình sử dụng trong quá trình thực thi. Trong nhiều Toolchain, vùng này thường được thể hiện bằng Section có tên .rodata.

Không giống Text Segment chứa mã lệnh, Read-only Data chứa các giá trị dữ liệu không được chương trình sửa đổi thông qua cách sử dụng hợp lệ.

4.1. Các dữ liệu thường được đặt trong .rodata

Một số ví dụ phổ biến bao gồm:

  • Các hằng số được khai báo bằng const có static storage duration.
  • String Literal.
  • Các bảng dữ liệu cố định mà Compiler và Linker đặt trong vùng chỉ đọc.

Ví dụ:

#include <stdio.h>

const int MAX_SENSOR_COUNT = 8;

int main(void)
{
    const float reference_voltage = 3.3f;

    printf("Maximum sensors: %d\n", MAX_SENSOR_COUNT);

    printf("Voltage: %.1f\n", reference_voltage);

    return 0;
}

Trong đoạn chương trình trên, MAX_SENSOR_COUNT là một biến có static storage duration và được khai báo chỉ đọc. Compiler hoặc Linker thường có thể đặt dữ liệu này trong Read-only Data Section.

Còn reference_voltage là một biến Local có automatic storage duration. Việc khai báo const không tự động đồng nghĩa với việc biến này được đặt trong .rodata. Vị trí lưu trữ của nó phụ thuộc vào Compiler và cách chương trình sử dụng biến.

4.2. String Literal

String Literal là những chuỗi ký tự được viết trực tiếp trong mã nguồn C. Ví dụ: 

const char *device_name = "Embedded Controller";

const char *message = "System Ready";

Các String Literal thường được Compiler đặt trong vùng dữ liệu chỉ đọc. Vì vậy, lập trình viên không nên cố gắng thay đổi nội dung của chúng. 

const char *message = "System Ready";

/* Không được phép sửa nội dung String Literal */
/* message[0] = 'X';  // Undefined Behavior */
Lưu ý: Trong C, String Literal có kiểu mảng ký tự nhưng việc sửa đổi nội dung String Literal dẫn đến Undefined Behavior. Sử dụng Pointer-to-const là cách thể hiện rõ ý định không thay đổi nội dung chuỗi.

4.3. Vai trò của .rodata trong Embedded

Trong Embedded Systems, bộ nhớ RAM thường có dung lượng hạn chế. Vì vậy, việc đặt dữ liệu chỉ đọc trong Flash thay vì RAM có thể giúp tiết kiệm dung lượng RAM dành cho các dữ liệu cần thay đổi trong quá trình thực thi.

Ví dụ, một hệ thống có thể sử dụng các bảng tra cứu cố định, thông số hiệu chuẩn mặc định hoặc chuỗi thông báo không thay đổi. Những dữ liệu này có thể được tổ chức trong các vùng nhớ chỉ đọc phù hợp với cấu hình của Compiler và Linker.

5. Initialized Data Segment (.data)

Initialized Data Segment, thường được gọi là Data Segment, là vùng dùng để lưu các biến có static storage duration đã được khởi tạo và cần có giá trị ban đầu trong quá trình thực thi.

Những biến thuộc nhóm này thường bao gồm biến Global và biến Static được khởi tạo bằng các giá trị khác 0.

5.1. Các biến thường thuộc .data

Ví dụ:

#include <stdint.h>

int system_status = 1;

uint32_t device_counter = 100;

static int error_code = 5;

int main(void)
{
    return 0;
}

Trong ví dụ trên:

  • system_status là biến Global được khởi tạo bằng 1.
  • device_counter là biến Global được khởi tạo bằng 100.
  • error_code là biến Static ở cấp File được khởi tạo bằng 5.

Các biến này có static storage duration và thường được đưa vào Initialized Data Segment.

5.2. Đặc điểm của .data

  • Lưu các biến cần giữ giá trị khởi tạo khi chương trình bắt đầu thực thi.
  • Thông thường có thể thay đổi trong quá trình chương trình chạy.
  • Chiếm dung lượng trong RAM khi hệ thống sử dụng cấu trúc Data Segment thông thường.
  • Giá trị khởi tạo ban đầu thường được lưu trong Load Image nằm trong Flash hoặc bộ nhớ không mất dữ liệu.

5.3. Cách .data hoạt động trong Embedded

Trên nhiều vi điều khiển, chương trình được lưu trong Flash nhưng các biến thuộc Data Segment lại cần được truy cập và thay đổi trong RAM.

Vì vậy, quá trình khởi động thường cần thực hiện việc sao chép giá trị khởi tạo từ vùng lưu trữ ban đầu trong Flash sang vùng RAM được sử dụng khi chương trình chạy.

Ví dụ, nếu một biến có giá trị khởi tạo là 100, giá trị ban đầu này sẽ được lưu trong Image được Linker bố trí. Khi hệ thống khởi động, Startup Code sẽ đưa giá trị đó vào vị trí RAM tương ứng.

Sau khi khởi tạo xong, chương trình có thể đọc và thay đổi biến trong RAM theo logic ứng dụng.

Cơ chế Load Address trong Flash và Run Address trong RAM là một khái niệm quan trọng trong Embedded. Phần này sẽ được tìm hiểu sâu hơn ở Bài 9: Linker Script, Memory Map & Startup Code.

6. BSS Segment (.bss)

BSS Segment là vùng nhớ thường dùng để lưu các biến có static storage duration chưa được khởi tạo tường minh hoặc được khởi tạo bằng giá trị 0.

Tên BSS bắt nguồn từ thuật ngữ Block Started by Symbol. Trong nhiều Toolchain hiện đại, vùng nhớ này thường được biểu diễn bằng Section có tên .bss.

6.1. Các biến thường thuộc .bss

Ví dụ:

#include <stdint.h>

int global_counter;

int system_status = 0;

static uint32_t sensor_value;

static int error_count = 0;

int main(void)
{
    return 0;
}

Trong ví dụ trên, các biến:

  • global_counter chưa được khởi tạo tường minh.
  • system_status được khởi tạo bằng 0.
  • sensor_value chưa được khởi tạo tường minh.
  • error_count được khởi tạo bằng 0.

Theo quy tắc của C, các biến có static storage duration sẽ được khởi tạo mặc định bằng 0 nếu không có giá trị khởi tạo tường minh. Vì vậy, chúng thường được tổ chức trong BSS Segment.

6.2. Đặc điểm của .bss

  • Chứa các biến Global và Static thuộc nhóm chưa khởi tạo hoặc được khởi tạo bằng 0.
  • Các biến trong vùng này thường chiếm dung lượng RAM khi chương trình chạy.
  • Vùng nhớ thường được Startup Code thiết lập về 0 trước khi gọi main().
  • Trong ELF, Section .bss thường có kích thước bộ nhớ khi chạy nhưng không cần lưu toàn bộ byte 0 trong file Image.

6.3. Vì sao BSS không cần lưu các giá trị 0 trong Flash?

Hãy xem xét một hệ thống có hàng trăm biến Global cần được khởi tạo bằng 0. Nếu toàn bộ các byte 0 này đều phải được lưu trữ tường minh trong file chương trình, kích thước Image có thể tăng lên không cần thiết.

Thay vì lưu tất cả các byte 0, hệ thống có thể chỉ lưu thông tin về kích thước và vị trí của vùng BSS. Sau đó, Startup Code sẽ tự động ghi giá trị 0 vào vùng RAM tương ứng trong quá trình khởi động. 

/* Ví dụ minh họa BSS */

uint8_t sensor_buffer[256];

int system_state;

static int error_counter;

/*
 * Các biến trên có static storage duration.
 * Nếu được bố trí trong .bss:
 * - Vùng nhớ được dành riêng trong RAM.
 * - Startup Code khởi tạo vùng nhớ bằng 0.
 */
Không nên nhầm lẫn biến Global chưa khởi tạo với biến Local chưa khởi tạo. Biến Global và Static có static storage duration được khởi tạo mặc định bằng 0. Trong khi đó, biến Local thông thường có automatic storage duration không tự động nhận giá trị 0.

7. Heap Segment

Heap là vùng nhớ thường được sử dụng để cấp phát bộ nhớ động trong quá trình chương trình đang chạy.

Khác với các vùng nhớ dành cho biến Global và Static đã được xác định trong quá trình Build, Heap cho phép chương trình yêu cầu thêm bộ nhớ khi cần thiết.

7.1. Các đối tượng thường được lưu trong Heap

Trong C, lập trình viên có thể sử dụng các hàm thuộc thư viện chuẩn để yêu cầu cấp phát bộ nhớ động. 

#include <stdlib.h>

int main(void)
{
    int *data = malloc(10 * sizeof(int));

    if (data == NULL)
    {
        return 1;
    }

    free(data);

    return 0;
}

Trong ví dụ trên:

  • Biến Pointer data có thời gian lưu trữ tự động vì nó là biến Local thông thường.
  • Vùng nhớ được yêu cầu thông qua malloc() là vùng nhớ được cấp phát động.
  • Địa chỉ của vùng nhớ được trả về và lưu vào Pointer data.
  • free() thông báo rằng chương trình không còn cần vùng nhớ đã cấp phát.

7.2. Vai trò của Heap

Heap hữu ích trong những trường hợp kích thước dữ liệu chưa xác định tại thời điểm biên dịch hoặc cần thay đổi trong quá trình thực thi.

Một số ứng dụng có thể sử dụng Heap để:

  • Cấp phát Buffer có kích thước thay đổi.
  • Tạo các cấu trúc dữ liệu có kích thước linh hoạt.
  • Lưu trữ dữ liệu được nhận từ thiết bị ngoại vi.
  • Tạo các đối tượng chỉ cần tồn tại trong một khoảng thời gian nhất định.

7.3. Heap trong Embedded Systems

Mặc dù Heap cung cấp khả năng cấp phát bộ nhớ linh hoạt, việc sử dụng nó trong Embedded Systems cần được cân nhắc cẩn thận.

Một số vi điều khiển có dung lượng RAM nhỏ, do đó việc sử dụng Heap không hợp lý có thể khiến hệ thống thiếu bộ nhớ hoặc gặp hiện tượng Memory Fragmentation.

Ngoài ra, thời gian thực hiện cấp phát và giải phóng bộ nhớ có thể ảnh hưởng đến tính xác định của hệ thống.

Trong các dự án Embedded, không phải lúc nào cũng nên sử dụng Dynamic Memory Allocation. Một số dự án ưu tiên cấp phát tĩnh hoặc sử dụng các Buffer có kích thước cố định để kiểm soát tài nguyên tốt hơn. Chủ đề này sẽ được trình bày chi tiết ở Bài 6.

8. Stack Segment

Stack là vùng nhớ thường được sử dụng để lưu trữ dữ liệu phục vụ quá trình thực thi các Function.

Khi một Function được gọi, hệ thống cần quản lý các thông tin liên quan đến quá trình gọi hàm, chẳng hạn như dữ liệu Local, thông tin trả về và những giá trị cần thiết khác theo quy ước gọi hàm của kiến trúc.

8.1. Các dữ liệu thường liên quan đến Stack

  • Biến Local có automatic storage duration.
  • Các giá trị tạm thời và dữ liệu phục vụ Function Call.
  • Địa chỉ quay trở lại sau khi Function hoàn thành, nếu được lưu trên Stack theo ABI.
  • Một số tham số hàm và dữ liệu trung gian tùy theo Compiler và Calling Convention.

Ví dụ:

void calculate_sum(void)
{
    int a = 10;
    int b = 20;

    int result = a + b;
}

int main(void)
{
    calculate_sum();

    return 0;
}

Trong ví dụ trên, các biến Local như a, b và result có automatic storage duration. Trong một cách triển khai phổ biến, chúng có thể được lưu trong Stack Frame của Function calculate_sum().

8.2. Stack Frame

Stack Frame là vùng dữ liệu phục vụ cho một lần gọi Function. Khi chương trình gọi một Function, Stack Frame tương ứng có thể được tạo ra để quản lý dữ liệu của lần gọi đó.

Ví dụ, khi Function main() gọi calculate_sum(), hệ thống sẽ quản lý dữ liệu của hai Function theo quy ước gọi hàm. Sau khi Function con hoàn thành, tài nguyên liên quan đến lần gọi đó sẽ được giải phóng hoặc tái sử dụng.

8.3. Đặc điểm của Stack

  • Thường được quản lý tự động theo vòng đời của các lần gọi Function.
  • Có tốc độ cấp phát và thu hồi thông thường rất nhanh.
  • Có giới hạn dung lượng được cấu hình cho từng chương trình hoặc Task.
  • Nếu sử dụng vượt quá giới hạn, hệ thống có thể gặp Stack Overflow.

Trong Embedded Systems, Stack cần được quan tâm đặc biệt vì một số MCU có dung lượng RAM hạn chế và vùng Stack có thể được cấu hình với kích thước cố định.

9. So sánh sáu vùng nhớ chính

Sau khi tìm hiểu từng vùng nhớ, có thể tổng hợp các đặc điểm quan trọng trong bảng sau:

Vùng nhớ Dữ liệu Vị trí thường gặp trong Embedded
.text Mã máy của chương trình. Flash
.rodata Hằng số, String Literal. Flash / Read-only Memory
.data Biến Global và Static đã khởi tạo. RAM khi chạy, giá trị ban đầu nằm trong Load Image.
.bss Biến Global và Static chưa khởi tạo hoặc khởi tạo bằng 0. RAM
Heap Bộ nhớ được cấp phát động. RAM
Stack Function Call Data và các dữ liệu có automatic storage duration theo cách triển khai phổ biến. RAM

10. Ví dụ tổng hợp: Xác định vị trí các biến trong Memory Layout

Để hiểu rõ hơn cách các biến được tổ chức trong bộ nhớ, hãy xem chương trình C sau: 

#include <stdint.h>
#include <stdlib.h>

/* Initialized Data */
int system_status = 1;

static int error_count = 5;

/* BSS */
int global_counter;

static uint32_t sensor_value;

/* Read-only Data (typical implementation) */
const int MAX_DEVICES = 10;

const char device_name[] = "Embedded MCU";

/* Text Segment */
void update_status(void)
{
    system_status = 2;
}

int main(void)
{
    /* Automatic local variables */
    int local_value = 100;

    uint32_t local_counter = 0;

    /* Dynamic memory allocation */
    int *dynamic_data = malloc(5 * sizeof(int));

    if (dynamic_data == NULL)
    {
        return 1;
    }

    dynamic_data[0] = local_value;

    update_status();

    free(dynamic_data);

    return 0;
}

Chương trình trên có nhiều loại biến và dữ liệu khác nhau. Dựa vào đặc điểm khai báo, chúng ta có thể xác định cách chúng thường được tổ chức trong Memory Layout như sau:

Biến / Thành phần Đặc điểm Vùng nhớ thường gặp
update_status() Mã thực thi của Function. .text
main() Mã thực thi của Function. .text
system_status Global, khởi tạo bằng 1. .data
error_count Static, khởi tạo bằng 5. .data
global_counter Global, chưa khởi tạo. .bss
sensor_value Static, chưa khởi tạo. .bss
MAX_DEVICES Const có static storage duration. .rodata (thường gặp)
device_name Mảng ký tự const có static storage duration. .rodata (thường gặp)
local_value Local automatic variable. Stack hoặc được Compiler tối ưu hóa
local_counter Local automatic variable. Stack hoặc được Compiler tối ưu hóa
dynamic_data Biến Pointer Local. Stack hoặc Register tùy Compiler
Vùng nhớ malloc Được cấp phát động. Heap (theo cách triển khai thông thường)
Điểm quan trọng: Vị trí của biến Pointer không nhất thiết giống vị trí của vùng nhớ mà Pointer trỏ đến. Trong ví dụ trên, biến dynamic_data là một biến Local, nhưng vùng nhớ được cấp phát bằng malloc() là vùng nhớ động. Hai đối tượng này có thể nằm ở hai vùng nhớ khác nhau.

11. Memory Layout trong Embedded Systems

Trong các chương trình chạy trên máy tính, hệ điều hành thường quản lý không gian địa chỉ và cấp phát tài nguyên cho mỗi tiến trình. Tuy nhiên, với các hệ thống Embedded Bare-metal, Firmware thường hoạt động trực tiếp trên bộ nhớ vật lý của vi điều khiển.

Điều này khiến cho việc tổ chức Memory Layout có liên hệ chặt chẽ với cấu trúc phần cứng của MCU.

11.1. Flash Memory và RAM

Hai loại bộ nhớ quan trọng trong nhiều vi điều khiển là Flash và RAM.

Tiêu chí Flash RAM
Khả năng lưu dữ liệu khi mất nguồn Có. Thông thường không.
Mục đích chính Lưu Firmware và dữ liệu cố định. Lưu dữ liệu khi chương trình đang chạy.
Các vùng dữ liệu thường gặp .text, .rodata và giá trị khởi tạo ban đầu của .data. .data, .bss, Heap và Stack.
Khả năng ghi Thường cần quy trình ghi và xóa theo đặc tính Flash. Có thể đọc và ghi thường xuyên.

Ví dụ, một vi điều khiển có:

  • Flash: 512 KB.
  • RAM: 128 KB.

Khi chương trình được Build, mã lệnh và dữ liệu chỉ đọc có thể được lưu trong Flash. Trong khi đó, những dữ liệu thay đổi trong lúc chạy cần có không gian lưu trữ thích hợp trong RAM.

11.2. Tổng quan Memory Mapping

Memory Mapping là quá trình ánh xạ các thành phần chương trình vào các địa chỉ bộ nhớ cụ thể theo cấu hình hệ thống.

Một cấu hình phổ biến trên MCU có thể tổ chức bộ nhớ theo cách minh họa sau:

Trong sơ đồ trên:

  • Flash: lưu mã chương trình, dữ liệu chỉ đọc và giá trị khởi tạo ban đầu của Data Segment.
  • RAM: chứa những vùng dữ liệu cần được sử dụng khi chương trình chạy.
  • .data: được sao chép từ Load Image sang vùng RAM tương ứng khi khởi động.
  • .bss: được khởi tạo bằng 0 trong quá trình Startup.
  • Heap và Stack: sử dụng phần RAM được cấu hình dành cho các hoạt động trong thời gian chạy.
Đây chỉ là một cách phân chia bộ nhớ phổ biến để minh họa. Vị trí thực tế của các Section phụ thuộc vào Memory Map của MCU, cấu hình Linker và các vùng nhớ được thiết kế cho dự án.

12. Vai trò của Startup Code trong Memory Initialization

Trước khi chương trình Embedded bắt đầu thực thi Function main(), hệ thống thường phải thực hiện một số công việc khởi tạo cần thiết.

Một trong những nhiệm vụ quan trọng của Startup Code là thiết lập các vùng dữ liệu trong RAM theo yêu cầu của chương trình.

12.1. Khởi tạo Data Segment

Giá trị khởi tạo ban đầu của các biến thuộc Initialized Data thường được lưu trong vùng Load Image. Startup Code sao chép những giá trị này đến vùng RAM tương ứng.

12.2. Khởi tạo BSS Segment

Các biến trong BSS cần nhận giá trị ban đầu bằng 0. Startup Code thường thực hiện việc ghi 0 vào toàn bộ vùng nhớ được dành cho BSS.

12.3. Thiết lập Stack

Hệ thống cần thiết lập Stack Pointer để CPU có thể quản lý quá trình gọi hàm và các dữ liệu liên quan.

Địa chỉ Stack ban đầu thường được xác định bởi cấu hình bộ nhớ và cơ chế khởi động của kiến trúc vi điều khiển.

12.4. Chuyển đến main()

Sau khi hoàn thành các công việc khởi tạo cần thiết, quá trình khởi động sẽ chuyển quyền điều khiển đến chương trình chính.

Quy trình này giúp bảo đảm các biến có static storage duration được đưa về trạng thái ban đầu đúng theo quy định trước khi chương trình chính chạy.

Startup Code thường được cung cấp bởi Toolchain, nhà cung cấp MCU hoặc được cấu hình trong dự án. Cách triển khai cụ thể sẽ được tìm hiểu ở Bài 9.

13. Các điểm cần chú ý khi phân tích Memory Layout

Khi tìm hiểu Memory Layout của chương trình C, cần lưu ý rằng các tên như Text, Data, BSS, Heap và Stack là những khái niệm phổ biến trong cách triển khai hệ thống, chứ không phải tất cả đều là các vùng được C Standard quy định bắt buộc.

Chuẩn ngôn ngữ C quy định các khái niệm về storage duration, object và cách chương trình hoạt động. Việc ánh xạ các đối tượng vào những Section cụ thể là trách nhiệm của Compiler, Linker và nền tảng thực thi.

13.1. Không phải mọi biến Local đều chắc chắn nằm trên Stack

Biến Local thông thường có automatic storage duration. Tuy nhiên, Compiler có thể tối ưu hóa và lưu giá trị của biến trong CPU Register hoặc loại bỏ biến nếu không cần thiết.

Vì vậy, không nên cho rằng mọi biến được khai báo bên trong Function đều luôn chiếm một vị trí cụ thể trên Stack.

13.2. Không phải mọi biến const đều nằm trong .rodata

Từ khóa const thể hiện rằng đối tượng không được sửa đổi thông qua cách truy cập hợp lệ tương ứng. Tuy nhiên, vị trí lưu trữ của đối tượng vẫn phụ thuộc vào Storage Duration, Compiler và cấu hình nền tảng.

13.3. Section Name có thể khác nhau

Những tên như .text, .data và .bss phổ biến trong các Toolchain sử dụng định dạng ELF. Tuy nhiên, các Compiler và hệ thống khác có thể sử dụng tên Section hoặc cơ chế tổ chức khác.

13.4. Flash và RAM không phải lúc nào cũng là cách phân chia duy nhất

Một hệ thống Embedded có thể chứa nhiều loại bộ nhớ như SRAM, Flash, EEPROM, External RAM hoặc các vùng nhớ chuyên dụng. Một số MCU còn có nhiều Bank RAM với chức năng và đặc tính riêng.

Do đó, cần dựa vào Datasheet, Reference Manual và cấu hình dự án để hiểu chính xác Memory Layout của Target MCU.

14. Tóm tắt các khái niệm quan trọng

Thuật ngữ Ý nghĩa

Read-only Data Vùng chứa các dữ liệu chỉ đọc.
Initialized Data Vùng chứa các biến Global và Static đã khởi tạo.
BSS Vùng chứa các biến Global và Static chưa khởi tạo hoặc được khởi tạo bằng 0.
Heap Vùng nhớ phục vụ Dynamic Memory Allocation.
Stack Vùng nhớ phục vụ Function Call và các dữ liệu có automatic storage duration theo cách triển khai thông thường.

RAM Bộ nhớ làm việc được sử dụng trong quá trình thực thi.

Tóm tắt

Memory Layout of a C Program mô tả cách chương trình C được tổ chức thành các vùng nhớ có chức năng khác nhau.

Sáu vùng nhớ thường gặp gồm Text Segment chứa mã lệnh, Read-only Data chứa dữ liệu chỉ đọc, Initialized Data chứa các biến đã khởi tạo, BSS chứa các biến chưa khởi tạo hoặc được khởi tạo bằng 0, Heap phục vụ cấp phát bộ nhớ động và Stack phục vụ quá trình thực thi Function.

Trong Embedded Systems, các vùng nhớ này thường được ánh xạ vào Flash và RAM theo cấu hình của hệ thống. Các giá trị khởi tạo của Data Segment thường được sao chép từ Flash sang RAM, trong khi BSS được khởi tạo bằng 0 trước khi chương trình chính chạy.

Hiểu được Memory Layout giúp lập trình viên xác định cách chương trình sử dụng bộ nhớ và là cơ sở để tiếp tục nghiên cứu Stack, Heap, Dynamic Memory Allocation và Memory Management trong các bài tiếp theo.
