Bài 5: Variable Scope, Lifetime & Storage Duration

Trong ngôn ngữ C, mỗi biến được khai báo đều có những đặc điểm liên quan đến phạm vi truy cập, thời gian tồn tại và cách bộ nhớ được quản lý. Những đặc điểm này ảnh hưởng trực tiếp đến cách một chương trình tổ chức dữ liệu và cách các Function tương tác với nhau.

Variable Scope, Lifetime & Storage Duration là ba khái niệm quan trọng giúp lập trình viên hiểu một biến có thể được truy cập ở đâu, tồn tại trong bao lâu và được quản lý như thế nào trong quá trình thực thi.

Ngoài ra, C còn cung cấp các từ khóa như auto, static và extern để xác định hoặc điều chỉnh cách khai báo và liên kết các Identifier. Việc sử dụng đúng những từ khóa này giúp mã nguồn dễ quản lý hơn, hạn chế phụ thuộc giữa các Module và tránh các lỗi liên quan đến dữ liệu.

Trong bài học này, chúng ta sẽ tập trung vào Scope, Lifetime, Storage Duration, Storage Class Specifier và Linkage. Những nội dung chuyên sâu về quản lý biến Global giữa các Module và Encapsulation sẽ được mở rộng ở Bài 29 và Bài 30.

1. Tổng quan về Scope, Lifetime và Storage Duration

Khi một biến được khai báo trong chương trình C, lập trình viên thường cần trả lời ba câu hỏi:

  • Biến này có thể được truy cập ở những vị trí nào trong mã nguồn?
  • Biến này tồn tại trong bao lâu khi chương trình thực thi?
  • Hệ thống quản lý bộ nhớ dành cho biến này theo cách nào?

Ba câu hỏi trên tương ứng với ba khái niệm Scope, Lifetime và Storage Duration.

Khái niệm Ý nghĩa Câu hỏi chính
Scope Phạm vi trong mã nguồn mà một Identifier có thể được sử dụng để tham chiếu. Biến có thể được truy cập ở đâu?
Lifetime Khoảng thời gian mà một đối tượng tồn tại trong chương trình. Đối tượng tồn tại trong bao lâu?
Storage Duration Đặc tính quy định thời gian lưu trữ của một đối tượng. Bộ nhớ của đối tượng được duy trì theo cơ chế nào?

Ba khái niệm này có liên quan nhưng không đồng nghĩa với nhau. Một biến có phạm vi truy cập chỉ nằm trong một Function nhưng vẫn có thể tồn tại trong suốt thời gian chương trình chạy. Ngược lại, một biến có phạm vi truy cập rộng không có nghĩa là chương trình có thể truy cập nó tại mọi thời điểm.

Điểm quan trọng: Scope liên quan đến khả năng nhìn thấy Identifier trong mã nguồn, còn Lifetime và Storage Duration liên quan đến thời gian tồn tại của đối tượng.

2. Variable Scope là gì?

Scope là vùng trong mã nguồn mà một Identifier (chẳng hạn như tên biến, tên Function hoặc tên Typedef) có thể được sử dụng để tham chiếu đến đối tượng hoặc khai báo tương ứng.

Trong C, Scope được xác định dựa trên vị trí khai báo Identifier và cấu trúc chương trình. Một Identifier không nhất thiết phải được truy cập từ mọi vị trí trong toàn bộ chương trình.

Có bốn loại Scope chính trong ngôn ngữ C:

  • Block Scope.
  • File Scope.
  • Function Prototype Scope.
  • Function Scope.

2.1. Block Scope

Block Scope là phạm vi của một Identifier được khai báo bên trong một Block. Block thường được xác định bởi cặp dấu ngoặc nhọn { }.

Biến Local được khai báo bên trong Function thường có Block Scope. Những biến này có thể được sử dụng trong Block chứa chúng và các Block lồng bên trong, tùy theo quy tắc Visibility và Shadowing.

Ví dụ:

#include <stdio.h>

void process_data(void)
{
    int sensor_value = 100;

    if (sensor_value > 50)
    {
        int threshold = 50;

        printf("Sensor: %d\n", sensor_value);

        printf("Threshold: %d\n", threshold);
    }

    /* Có thể truy cập sensor_value */
    printf("Value: %d\n", sensor_value);

    /* Không thể truy cập threshold tại đây */
}

int main(void)
{
    process_data();

    return 0;
}

Trong ví dụ trên:

  • sensor_value được khai báo trong Block của Function process_data().
  • threshold được khai báo trong Block của câu lệnh if.
  • threshold chỉ có thể được sử dụng bên trong Block chứa nó.
  • sensor_value có thể được sử dụng trong cả Block của Function và các Block lồng bên trong.

2.2. Nested Block Scope

Một Block có thể chứa nhiều Block khác. Khi đó, những Identifier được khai báo ở Block bên ngoài có thể được sử dụng trong Block bên trong nếu không bị một khai báo khác che khuất. 

void example(void)
{
    int value = 10;

    {
        int result = value + 5;

        {
            int final_value = result * 2;

            /* Có thể truy cập:
             * value
             * result
             * final_value
             */
        }

        /* Có thể truy cập:
         * value
         * result
         *
         * Không thể truy cập final_value
         */
    }

    /* Chỉ còn truy cập value */
}

Ví dụ trên cho thấy Block Scope được tổ chức theo cấu trúc lồng nhau. Identifier được khai báo trong Block bên ngoài có thể được tham chiếu bên trong Block con, nhưng Identifier được khai báo trong Block con không thể được sử dụng bên ngoài Block đó.

2.3. File Scope

File Scope là phạm vi của một Identifier được khai báo bên ngoài tất cả Function và các Block. Những khai báo này thường được đặt ở đầu Source File hoặc giữa các Function.

Biến được khai báo ở cấp File thường được gọi là Global Variable trong quá trình phát triển C. Function được định nghĩa ở cấp File cũng có File Scope. 

#include <stdint.h>

/* File Scope */
int system_status = 1;

uint32_t sensor_counter = 0;

void update_sensor(void)
{
    sensor_counter++;
}

int main(void)
{
    update_sensor();

    return 0;
}

Trong ví dụ trên, các Identifier: system_status, sensor_counter, update_sensor và main đều được khai báo ở File Scope.

Các biến system_status và sensor_counter có thể được sử dụng trong các Function thuộc cùng phạm vi nhìn thấy của File. Tuy nhiên, việc truy cập chúng từ các Source File khác còn phụ thuộc vào Linkage.

2.4. Function Prototype Scope

Function Prototype Scope là phạm vi của tên tham số được khai báo bên trong Function Prototype. Tên tham số chỉ có ý nghĩa trong phần khai báo Function Prototype đó. 

int calculate_sum(int a, int b);

void process_sensor(uint16_t sensor_value);

/*
 * Các tên a, b và sensor_value
 * trong Function Prototype không thể được sử dụng
 * như những biến bên ngoài Function.
 */

Trong ví dụ trên, các tên: a, b và sensor_value chỉ tồn tại trong phạm vi của từng Function Prototype.

Có thể khai báo lại cùng những tên này trong phần triển khai Function mà không gây xung đột với Prototype.

2.5. Function Scope

Function Scope là loại Scope đặc biệt dành cho các nhãn được khai báo bằng cú pháp Label trong Function. Khác với Block Scope, nhãn có thể được tham chiếu từ những vị trí khác trong cùng Function. 

void process_data(void)
{
    int status = 0;

    if (status == 0)
    {
        goto error_handler;
    }

    return;

error_handler:

    /* Xử lý lỗi tại đây */
    return;
}

Trong ví dụ trên, nhãn error_handler có Function Scope. Nó được sử dụng bởi câu lệnh goto trong cùng Function.

Function Scope chủ yếu áp dụng cho Label, không phải cho toàn bộ biến được khai báo bên trong Function. Các biến Local thông thường vẫn có Block Scope.

3. Scope và Shadowing

Trong C, một Identifier được khai báo ở Block bên trong có thể sử dụng cùng tên với Identifier ở Block bên ngoài. Khi đó, khai báo bên trong sẽ che khuất (Shadow) khai báo bên ngoài trong phạm vi tương ứng.

Hiện tượng này được gọi là Variable Shadowing.

3.1. Ví dụ về Shadowing

#include <stdio.h>

int sensor_value = 100;

void process_sensor(void)
{
    int sensor_value = 50;

    printf("Local: %d\n", sensor_value);
}

int main(void)
{
    printf("Global: %d\n", sensor_value);

    process_sensor();

    printf("Global: %d\n", sensor_value);

    return 0;
}

Kết quả: 

Global: 100
Local: 50
Global: 100

Trong ví dụ trên:

  • Biến Global sensor_value có giá trị 100.
  • Biến Local sensor_value bên trong process_sensor() có giá trị 50.
  • Trong phạm vi Function, tên sensor_value tham chiếu đến biến Local.
  • Biến Global vẫn giữ nguyên giá trị 100.

3.2. Tác động của Shadowing

Shadowing là một đặc điểm hợp lệ của C, tuy nhiên sử dụng quá nhiều Identifier trùng tên có thể khiến mã nguồn khó đọc và gây nhầm lẫn khi bảo trì.

Trong Embedded Software, việc nhầm lẫn giữa biến Local và biến Global có thể làm cho lập trình viên khó xác định chính xác dữ liệu nào đang được đọc hoặc thay đổi.

Vì vậy, nên đặt tên biến rõ ràng và tránh Shadowing không cần thiết, đặc biệt đối với những biến liên quan đến trạng thái hệ thống, cảm biến và các Module điều khiển.

4. Lifetime là gì?

Lifetime là khoảng thời gian mà một đối tượng thực sự tồn tại trong chương trình. Trong thời gian này, đối tượng có thể được sử dụng theo những quy tắc của ngôn ngữ C.

Lifetime thường bắt đầu khi vùng lưu trữ dành cho đối tượng được thiết lập theo quy tắc tương ứng và kết thúc khi Storage Duration của đối tượng kết thúc hoặc khi vùng nhớ cấp phát động được giải phóng.

Lifetime không đồng nghĩa với Scope. Một biến có thể không còn được truy cập trực tiếp bằng tên ở một vị trí trong mã nguồn nhưng đối tượng tương ứng vẫn còn tồn tại trong bộ nhớ.

4.1. Lifetime của Local Variable

Một biến Local thông thường có Automatic Storage Duration. Đối tượng thường được tạo khi chương trình đi vào Block chứa khai báo và Lifetime kết thúc khi quá trình thực thi rời khỏi Block đó. 

void process_sensor(void)
{
    int sensor_value = 100;

    /* sensor_value tồn tại tại đây */

    sensor_value++;

} /* Lifetime của sensor_value kết thúc */

Khi Function process_sensor() kết thúc, biến sensor_value không còn tồn tại dưới dạng đối tượng có Automatic Storage Duration. Vùng Stack tương ứng có thể được tái sử dụng cho những hoạt động khác.

4.2. Lifetime của Global Variable

Biến Global có Static Storage Duration. Điều này có nghĩa đối tượng tồn tại trong toàn bộ thời gian thực thi chương trình. 

int system_status = 0;

void update_status(void)
{
    system_status = 1;
}

void reset_status(void)
{
    system_status = 0;
}

int main(void)
{
    update_status();

    reset_status();

    return 0;
}

Biến system_status được khai báo ở File Scope và tồn tại trong suốt thời gian chương trình hoạt động. Những Function có thể nhìn thấy khai báo này đều có thể sử dụng nó.

4.3. Lifetime của Static Local Variable

Một biến được khai báo bằng static bên trong Function có một đặc điểm đáng chú ý: mặc dù có Block Scope nhưng lại có Static Storage Duration. 

#include <stdio.h>

void update_counter(void)
{
    static int counter = 0;

    counter++;

    printf("Counter: %d\n", counter);
}

int main(void)
{
    update_counter();
    update_counter();
    update_counter();

    return 0;
}

Kết quả: 

Counter: 1
Counter: 2
Counter: 3

Giải thích:

  • counter chỉ có thể được truy cập trực tiếp bên trong Function update_counter().
  • Biến được khởi tạo một lần với giá trị 0.
  • Giá trị được giữ lại giữa các lần gọi Function.
  • Lifetime của đối tượng kéo dài trong toàn bộ thời gian thực thi chương trình.
Đây là ví dụ điển hình cho thấy Scope và Lifetime là hai khái niệm khác nhau. Biến counter có Block Scope nhưng Static Storage Duration.

5. Storage Duration là gì?

Storage Duration là khái niệm mô tả thời gian mà bộ nhớ dành cho một đối tượng được duy trì trong chương trình. Đây là một đặc điểm quan trọng khi phân tích cách C quản lý các biến và dữ liệu.

Trong C, có bốn loại Storage Duration chính:

  • Automatic Storage Duration.
  • Static Storage Duration.
  • Thread Storage Duration.
  • Allocated Storage Duration.
Storage Duration Thời gian tồn tại Ví dụ
Automatic Trong khoảng thời gian thực thi Block tương ứng. Biến Local thông thường.
Static Toàn bộ thời gian thực thi chương trình. Global Variable, Static Variable.
Thread Trong thời gian tồn tại của Thread tương ứng. Biến khai báo bằng _Thread_local trong C11.
Allocated Từ khi cấp phát thành công cho đến khi giải phóng. Đối tượng được tạo bởi malloc().

5.1. Automatic Storage Duration

Automatic Storage Duration thường được áp dụng cho các biến Local được khai báo bên trong Block mà không sử dụng Storage Class Specifier làm thay đổi thời gian lưu trữ. 

void calculate_average(void)
{
    int sum = 100;

    int count = 10;

    int average = sum / count;

    /* Sử dụng average */
}

int main(void)
{
    calculate_average();

    return 0;
}

Các biến sum, count và average có Automatic Storage Duration.

Khi chương trình thực thi Function calculate_average(), những đối tượng này được tạo theo cơ chế thực thi tương ứng. Khi Function kết thúc, Lifetime của chúng cũng kết thúc.

5.2. Static Storage Duration

Static Storage Duration có nghĩa bộ nhớ dành cho đối tượng được duy trì trong toàn bộ thời gian thực thi chương trình.

Những đối tượng thường có Static Storage Duration bao gồm:

  • Global Variable.
  • Static Global Variable.
  • Static Local Variable.
  • Các Function-level hoặc File-level Static Object tương ứng.
/* Static Storage Duration */
int system_status = 1;

static int error_count = 0;

void update_counter(void)
{
    static int call_count = 0;

    call_count++;
}

int main(void)
{
    update_counter();

    return 0;
}

Cả ba đối tượng system_status, error_count và call_count đều có Static Storage Duration.

Tuy nhiên, Scope và Linkage của chúng khác nhau. Đây là nội dung sẽ được phân tích khi tìm hiểu từ khóa static.

5.3. Thread Storage Duration

Thread Storage Duration được giới thiệu trong C11. Một đối tượng thuộc loại này tồn tại trong suốt thời gian Thread tương ứng tồn tại.

Có thể sử dụng từ khóa _Thread_local để khai báo đối tượng có Thread Storage Duration. 

/* C11 */

#include <threads.h>

_Thread_local int thread_counter = 0;

void process_task(void)
{
    thread_counter++;

    /* Mỗi Thread có đối tượng thread_counter riêng */
}

Khác với Global Variable thông thường, một đối tượng có Thread Storage Duration được tạo riêng cho mỗi Thread theo cơ chế của nền tảng hỗ trợ.

Thread Storage Duration không phải nội dung thường xuyên cần sử dụng trong các ứng dụng MCU Bare-metal đơn giản. Tuy nhiên, khái niệm này hữu ích khi tìm hiểu các hệ thống có hỗ trợ nhiều Thread hoặc môi trường chạy tương thích C11.

5.4. Allocated Storage Duration

Allocated Storage Duration được áp dụng cho các đối tượng được cấp phát bộ nhớ trong Runtime. Đối tượng tồn tại từ khi vùng nhớ được cấp phát thành công cho đến khi được giải phóng. 

#include <stdlib.h>

int main(void)
{
    int *data = malloc(5 * sizeof(int));

    if (data == NULL)
    {
        return 1;
    }

    data[0] = 100;

    /* Đối tượng được cấp phát vẫn tồn tại tại đây */

    free(data);

    /* Lifetime của đối tượng đã được cấp phát kết thúc */

    return 0;
}

Trong ví dụ này, đối tượng được cấp phát thông qua malloc() có Allocated Storage Duration. Vòng đời của nó không phụ thuộc trực tiếp vào việc Function chứa lời gọi malloc() kết thúc hay chưa.

Các vấn đề liên quan đến cấp phát, giải phóng và kiểm soát vòng đời của đối tượng được cấp phát sẽ được tìm hiểu sâu hơn trong Bài 6 và Bài 7.

6. Storage Class Specifier trong C

Storage Class Specifier là những từ khóa được sử dụng trong khai báo để chỉ định một số đặc tính liên quan đến Identifier và cách đối tượng được quản lý.

Trong phạm vi bài học này, chúng ta tập trung vào ba từ khóa quan trọng: auto, static và extern.

Keyword Vai trò chính
auto Khai báo đối tượng có Automatic Storage Duration ở Block Scope.
static Điều chỉnh Storage Duration hoặc Linkage tùy vị trí khai báo.
extern Khai báo một Identifier có External Linkage hoặc liên kết với khai báo có Linkage tương ứng.
Một điểm cần lưu ý: static và extern không chỉ đơn giản xác định biến được lưu ở Stack hay Heap. Chúng liên quan đến những đặc tính như Storage Duration và Linkage. Vị trí bộ nhớ vật lý cụ thể vẫn phụ thuộc vào Compiler và nền tảng.

7. auto Keyword

auto là một Storage Class Specifier được sử dụng để khai báo biến có Automatic Storage Duration tại Block Scope.

Trong các phiên bản C phổ biến như C99, C11 và C17, những biến Local thông thường đã có Automatic Storage Duration mặc định. Vì vậy, việc ghi thêm từ khóa auto thường không làm thay đổi hành vi của chương trình.

7.1. Cách sử dụng auto

void process_sensor(void)
{
    auto int sensor_value = 100;

    int threshold = 50;

    /* Cả hai biến đều có Automatic Storage Duration */
}

Trong ví dụ trên:

  • sensor_value được khai báo với từ khóa auto.
  • threshold được khai báo mà không sử dụng Storage Class Specifier.
  • Cả hai biến đều có Automatic Storage Duration.
  • Cả hai biến đều có Block Scope.

7.2. So sánh khai báo auto và khai báo thông thường

void example(void)
{
    auto int value_a = 10;

    int value_b = 20;

    /*
     * value_a và value_b có cùng
     * Automatic Storage Duration.
     */
}

Trong C, từ khóa auto không có nghĩa là biến sẽ được cấp phát động trên Heap. Nó chỉ biểu thị Automatic Storage Duration trong ngữ cảnh khai báo tương ứng.

Không nhầm lẫn auto trong C với từ khóa auto của C++ thường được sử dụng để suy luận kiểu dữ liệu. Trong các phiên bản C trước C23, auto là Storage Class Specifier.

8. static Keyword

static là một từ khóa đặc biệt trong C vì ý nghĩa của nó thay đổi tùy thuộc vào vị trí khai báo.

Có hai trường hợp quan trọng:

  • Static được khai báo bên trong Function hoặc Block.
  • Static được khai báo ở File Scope.

Cả hai trường hợp đều có liên quan đến Static Storage Duration, nhưng Linkage và Scope có thể khác nhau.

8.1. Static Local Variable

Khi khai báo biến bằng static bên trong Function, biến đó có Static Storage Duration nhưng vẫn giữ Block Scope. 

#include <stdio.h>

void count_calls(void)
{
    static int call_count = 0;

    call_count++;

    printf("Call count: %d\n", call_count);
}

int main(void)
{
    count_calls();
    count_calls();
    count_calls();

    return 0;
}

Kết quả: 

Call count: 1
Call count: 2
Call count: 3

Nếu không có từ khóa static, biến call_count sẽ được tạo mới theo mỗi lần Function được thực thi và bắt đầu từ giá trị khởi tạo 0.

Tuy nhiên, khi sử dụng static, đối tượng chỉ được khởi tạo một lần và giữ lại giá trị giữa các lần gọi Function.

8.2. Static Variable trong Block Scope

Static Local Variable không nhất thiết phải được khai báo trực tiếp ở cấp Function. Nó có thể được khai báo trong bất kỳ Block phù hợp nào. 

void process_data(void)
{
    if (1)
    {
        static int event_count = 0;

        event_count++;

        /* event_count chỉ được sử dụng trong Block này */
    }

    /* Không thể truy cập event_count tại đây */
}

Trong ví dụ trên:

  • event_count có Block Scope.
  • event_count có Static Storage Duration.
  • Đối tượng tồn tại trong toàn bộ thời gian thực thi chương trình.
  • Identifier chỉ có thể được sử dụng trong Block khai báo.

8.3. Static Global Variable

Khi khai báo một biến bằng static ở File Scope, biến đó có Static Storage Duration và Internal Linkage. 

#include <stdint.h>

/* Internal Linkage */
static uint32_t internal_counter = 0;

void update_counter(void)
{
    internal_counter++;
}

int main(void)
{
    update_counter();

    return 0;
}

Biến internal_counter:

  • Được khai báo ở File Scope.
  • Có Static Storage Duration.
  • Có Internal Linkage.
  • Có thể được sử dụng trong các Function thuộc cùng Translation Unit nếu khai báo được nhìn thấy.
  • Không được tham chiếu trực tiếp thông qua External Linkage từ một Source File khác.

8.4. Static Function

Từ khóa static cũng có thể được sử dụng với Function được khai báo ở File Scope. Khi đó, Function có Internal Linkage. 

#include <stdio.h>

/* Chỉ có Internal Linkage */
static void print_status(void)
{
    printf("System Ready\n");
}

void initialize_system(void)
{
    print_status();
}

int main(void)
{
    initialize_system();

    return 0;
}

Function print_status() chỉ được tham chiếu trong cùng Translation Unit. Các Source File khác không thể liên kết đến Function này thông qua External Linkage.

Đây là kỹ thuật hữu ích khi muốn giới hạn các Function nội bộ và tránh để lộ những thành phần không cần thiết ra bên ngoài Module.

Static Local Variable và Static Global Variable có cùng Static Storage Duration, nhưng khác nhau về Scope và Linkage: Static Local có Block Scope và No Linkage; Static Global có File Scope và Internal Linkage.

9. extern Keyword

extern là từ khóa thường được sử dụng khi một Source File cần tham chiếu đến biến hoặc Function được khai báo hoặc định nghĩa trong một Source File khác.

Khai báo extern cho phép Compiler và Linker biết rằng Identifier được tham chiếu có một định nghĩa tương ứng ở một vị trí khác trong chương trình.

9.1. Khai báo extern với biến Global

Xét ví dụ có hai Source File: main.c và sensor.c.

File sensor.c:

#include <stdint.h>

/* Definition */
uint32_t sensor_value = 100;

File main.c:

#include <stdint.h>

/* Declaration */
extern uint32_t sensor_value;

int main(void)
{
    uint32_t value = sensor_value;

    return 0;
}

Trong trường hợp này:

  • sensor_value được định nghĩa trong sensor.c.
  • main.c khai báo extern để tham chiếu đến biến đó.
  • Hai Source File có thể được biên dịch thành các Object File riêng biệt.
  • Linker sẽ liên kết tham chiếu trong main.o với định nghĩa trong sensor.o.

9.2. extern trong Header File

Trong một dự án C có nhiều Module, cách phổ biến là đặt khai báo extern vào Header File để các Source File khác có thể sử dụng.

File sensor.h:

#ifndef SENSOR_H
#define SENSOR_H

#include <stdint.h>

/* External declaration */
extern uint32_t sensor_value;

void Sensor_Update(void);

#endif

File sensor.c:

#include "sensor.h"

/* Definition */
uint32_t sensor_value = 0;

void Sensor_Update(void)
{
    sensor_value++;
}

File main.c:

#include "sensor.h"

int main(void)
{
    Sensor_Update();

    uint32_t value = sensor_value;

    return 0;
}

Trong ví dụ này, sensor.h cung cấp các khai báo để Module khác sử dụng. Phần định nghĩa thực tế của biến sensor_value chỉ được đặt trong sensor.c.

Một nguyên tắc quan trọng khi tổ chức chương trình nhiều Module: nên có một nơi định nghĩa biến Global và những nơi khác chỉ khai báo bằng extern thông qua Header File. Cách này giúp tránh lỗi Multiple Definition khi Linking.

9.3. extern với Function

Function được định nghĩa ở File Scope và không sử dụng static thường có External Linkage. Vì vậy, một Source File khác có thể gọi Function thông qua khai báo Prototype.

File math_utils.h:

#ifndef MATH_UTILS_H
#define MATH_UTILS_H

int calculate_sum(int a, int b);

#endif

File math_utils.c:

#include "math_utils.h"

int calculate_sum(int a, int b)
{
    return a + b;
}

File main.c:

#include "math_utils.h"

int main(void)
{
    int result = calculate_sum(10, 20);

    return 0;
}

Trong ví dụ này, Function calculate_sum() có thể được sử dụng từ nhiều Source File thông qua External Linkage. Không bắt buộc phải viết từ khóa extern trước Function Prototype vì khai báo Function ở File Scope mặc định có External Linkage nếu không bị giới hạn bằng static.

9.4. extern không đồng nghĩa với cấp phát bộ nhớ mới

Một điểm quan trọng cần nhớ là extern thường được sử dụng để khai báo một Identifier đã có định nghĩa ở nơi khác, chứ không phải để tạo một đối tượng mới cho mỗi Source File. 

/* sensor.c */

/* Định nghĩa đối tượng */
int sensor_status = 1;
/* main.c */

/* Khai báo tham chiếu đến đối tượng */
extern int sensor_status;

Ở ví dụ trên, chỉ có một định nghĩa của sensor_status. Khai báo extern trong main.c cho phép Source File đó tham chiếu đến cùng đối tượng.

10. External Linkage và Internal Linkage

Ngoài Scope và Storage Duration, một khái niệm khác cần hiểu khi làm việc với nhiều Source File là Linkage.

Linkage mô tả mối quan hệ giữa các khai báo của cùng một Identifier trong những phạm vi khác nhau của chương trình. Đây là cơ chế giúp các Module có thể tham chiếu đến cùng một biến hoặc Function.

Trong C, có ba loại Linkage chính:

  • External Linkage.
  • Internal Linkage.
  • No Linkage.

10.1. External Linkage

External Linkage cho phép các khai báo tương ứng của cùng một Identifier ở những Translation Unit khác nhau tham chiếu đến cùng một thực thể theo quy tắc của C.

Các biến và Function được khai báo ở File Scope thường có External Linkage nếu không được giới hạn bằng static hoặc một quy tắc khác. 

/* sensor.c */

int sensor_value = 100;

void update_sensor(void)
{
    sensor_value++;
}
/* main.c */

extern int sensor_value;

void update_sensor(void);

int main(void)
{
    update_sensor();

    return 0;
}

Trong ví dụ trên, sensor_value và update_sensor() có thể được sử dụng từ main.c thông qua External Linkage.

10.2. Internal Linkage

Internal Linkage giới hạn việc liên kết một Identifier trong phạm vi Translation Unit tương ứng.

Đối với các biến và Function được khai báo ở File Scope, từ khóa static thường được sử dụng để tạo Internal Linkage. 

/* sensor.c */

static int sensor_error_count = 0;

static void reset_sensor_error(void)
{
    sensor_error_count = 0;
}

void Sensor_Init(void)
{
    reset_sensor_error();
}

Trong ví dụ trên:

  • sensor_error_count chỉ có Internal Linkage.
  • reset_sensor_error() chỉ có Internal Linkage.
  • Hai Identifier trên được sử dụng bên trong Translation Unit của sensor.c.
  • Source File khác không thể tham chiếu trực tiếp đến chúng bằng External Linkage.

10.3. No Linkage

No Linkage có nghĩa một Identifier không được liên kết với những khai báo khác thành cùng một thực thể thông qua Linkage.

Ví dụ, biến Local thông thường và Static Local Variable đều có No Linkage. 

void process_sensor(void)
{
    int local_value = 100;

    static int call_count = 0;

    call_count++;

    /* Cả local_value và call_count đều có No Linkage */
}

Mặc dù call_count có Static Storage Duration, Identifier của nó vẫn có No Linkage vì được khai báo ở Block Scope.

10.4. So sánh các loại Linkage

Linkage Phạm vi liên kết Ví dụ phổ biến
External Có thể được tham chiếu từ các Translation Unit khác. Global Variable và Function thông thường ở File Scope.
Internal Chỉ liên kết trong cùng Translation Unit. File-scope Variable hoặc Function khai báo bằng static.
No Linkage Không liên kết với các khai báo khác. Local Variable và Static Local Variable.
Linkage áp dụng cho Identifier, không phải là một Storage Duration. Một đối tượng có Static Storage Duration không đồng nghĩa với việc Identifier của nó có External Linkage.

11. Phân biệt Scope, Lifetime, Storage Duration và Linkage

Đây là nội dung quan trọng nhất của bài học. Bốn khái niệm này có mối liên hệ với nhau nhưng không nên sử dụng thay thế cho nhau.

Ví dụ khai báo Scope Storage Duration Linkage
int value; trong Function Block Automatic No Linkage
static int value; trong Function Block Static No Linkage
int value = 10; ở File Scope File Static External
static int value; ở File Scope File Static Internal
extern int value; ở File Scope File Static đối với đối tượng được tham chiếu Thông thường External
malloc() Object Không áp dụng Scope theo cách khai báo Identifier thông thường Allocated Không có Linkage riêng của đối tượng được cấp phát

Để hiểu rõ hơn, hãy xét hai trường hợp:

11.1. Một biến có Block Scope nhưng Static Storage Duration

void update_counter(void)
{
    static int counter = 0;

    counter++;
}

Biến counter:

  • Chỉ truy cập được trong Block chứa khai báo.
  • Không bị tạo lại mỗi khi Function được gọi.
  • Tồn tại trong toàn bộ thời gian thực thi chương trình.
  • Có No Linkage.

11.2. Một biến có File Scope và Static Storage Duration

static int system_status = 1;

void update_status(void)
{
    system_status = 2;
}

Biến system_status:

  • Có File Scope.
  • Có Static Storage Duration.
  • Có Internal Linkage.
  • Có thể được sử dụng trong các Function phù hợp thuộc cùng Translation Unit.

Hai ví dụ này cho thấy từ khóa static không có cùng ý nghĩa về Linkage ở mọi vị trí khai báo.

12. Bảng tổng hợp các từ khóa auto, static và extern

Để thuận tiện khi lập trình, có thể tổng hợp đặc điểm của các từ khóa đã học như sau:

Keyword Vị trí khai báo Storage Duration Linkage
auto Block Scope Automatic No Linkage (đối với biến Local thông thường)
static Block Scope Static No Linkage
static File Scope Static Internal
extern File Scope Thường là Static đối với đối tượng được khai báo Thông thường External
extern Block Scope Phụ thuộc đối tượng được tham chiếu Theo Linkage của khai báo tương ứng
Bảng trên mô tả những trường hợp khai báo phổ biến. Đối với extern, quy tắc Linkage còn phụ thuộc vào những khai báo trước đó của cùng Identifier. Khi làm việc với dự án nhiều Source File, nên kiểm tra toàn bộ các khai báo liên quan thay vì chỉ nhìn vào một dòng code riêng lẻ.

13. Ứng dụng trong Embedded Systems

Việc hiểu Scope, Lifetime, Storage Duration và Linkage rất quan trọng khi phát triển Embedded Software. Những khái niệm này ảnh hưởng đến cách tổ chức dữ liệu, mức sử dụng bộ nhớ và sự phụ thuộc giữa các Module.

13.1. Quản lý biến Global trong Firmware

Trong Embedded Systems, một số dữ liệu như trạng thái hệ thống, bộ đếm lỗi và giá trị cảm biến có thể cần được truy cập từ nhiều Function. 

#include <stdint.h>

/* Global State */
uint8_t system_state = 0;

void System_Update(void)
{
    system_state = 1;
}

void System_Reset(void)
{
    system_state = 0;
}

int main(void)
{
    System_Update();

    System_Reset();

    return 0;
}

Cách khai báo này cho phép nhiều Function cùng truy cập dữ liệu. Tuy nhiên, việc sử dụng quá nhiều biến Global có thể tạo ra sự phụ thuộc lớn giữa các phần của chương trình.

Đối với dự án có nhiều Module, nên quản lý rõ ràng các biến dùng chung và hạn chế việc truy cập trực tiếp đến dữ liệu nội bộ của Module khác.

13.2. Sử dụng Static để quản lý trạng thái nội bộ

Khi một Module cần giữ lại trạng thái giữa các lần gọi Function nhưng không muốn công khai biến đó ra bên ngoài, Static Local Variable có thể là một lựa chọn phù hợp. 

#include <stdint.h>

void Sensor_Process(void)
{
    static uint32_t sample_count = 0;

    sample_count++;

    /* Xử lý mẫu dữ liệu */
}

Biến sample_count được giữ lại giữa các lần gọi Function, nhưng các Function khác không thể truy cập trực tiếp bằng Identifier này.

13.3. Sử dụng static để giới hạn Function nội bộ

Trong một Driver, không phải tất cả Function đều cần được sử dụng bởi các Module bên ngoài. Những Function chỉ phục vụ xử lý nội bộ có thể được khai báo bằng static. 

#include <stdint.h>

static void Sensor_ValidateData(uint16_t value)
{
    /* Kiểm tra dữ liệu nội bộ */
}

void Sensor_Read(void)
{
    uint16_t value = 100;

    Sensor_ValidateData(value);
}

Function Sensor_ValidateData() chỉ có Internal Linkage. Những Source File khác không thể liên kết trực tiếp với Function này.

13.4. Chia sẻ dữ liệu giữa các Module bằng extern

Khi một Module cần cung cấp dữ liệu cho những Module khác, có thể sử dụng Header File để khai báo giao diện truy cập. 

/* system_status.h */

#ifndef SYSTEM_STATUS_H
#define SYSTEM_STATUS_H

#include <stdint.h>

extern uint8_t system_status;

#endif
/* system_status.c */

#include "system_status.h"

/* Chỉ định nghĩa một lần */
uint8_t system_status = 0;
/* main.c */

#include "system_status.h"

int main(void)
{
    system_status = 1;

    return 0;
}

Cách tổ chức trên cho phép các Source File sử dụng cùng một đối tượng thông qua External Linkage. Tuy nhiên, trong một kiến trúc phần mềm có tính Encapsulation cao, có thể ưu tiên cung cấp Function để đọc và cập nhật trạng thái thay vì công khai biến Global trực tiếp.

14. Common Mistakes khi sử dụng Scope và Storage Duration

Một số lỗi thường gặp khi làm việc với các biến trong C xuất phát từ việc không phân biệt rõ Scope, Lifetime và Storage Duration.

14.1. Nhầm lẫn Local Variable và Static Local Variable

void process_data(void)
{
    int counter = 0;

    counter++;

    /* Counter luôn bắt đầu từ 0 mỗi lần gọi */
}

Nếu lập trình viên muốn lưu lại giá trị của counter qua các lần gọi Function nhưng không sử dụng static, kết quả sẽ không đáp ứng mục đích đó.

14.2. Trả về địa chỉ của Local Variable

int* get_sensor_value(void)
{
    int sensor_value = 100;

    return &sensor_value;
}

Đây là cách viết không hợp lệ về mặt sử dụng đối tượng sau khi Function kết thúc. Biến sensor_value có Automatic Storage Duration, nên Lifetime của nó kết thúc khi Function hoàn thành.

Pointer được trả về không còn trỏ đến một đối tượng còn tồn tại. Việc sử dụng Pointer này sau đó gây ra Undefined Behavior.

Cần bảo đảm Lifetime của đối tượng dài ít nhất bằng khoảng thời gian mà chương trình cần sử dụng đối tượng thông qua Pointer.

14.3. Khai báo trùng Global Variable

Một lỗi thường gặp trong dự án nhiều Source File là định nghĩa cùng một biến Global ở nhiều nơi. 

/* main.c */
int system_status = 1;
/* sensor.c */
int system_status = 1;

Nếu cả hai file được đưa vào cùng chương trình, Linker có thể báo lỗi Multiple Definition vì có hai định nghĩa External Linkage của cùng Identifier.

Cách tổ chức phù hợp hơn: 

/* system_status.c */
int system_status = 1;
/* system_status.h */
#ifndef SYSTEM_STATUS_H
#define SYSTEM_STATUS_H

extern int system_status;

#endif

14.4. Lạm dụng Global Variable

Việc khai báo quá nhiều biến Global có thể làm tăng sự phụ thuộc giữa các Module và khiến việc xác định nơi thay đổi dữ liệu trở nên khó khăn.

Nên cân nhắc sử dụng Static Local Variable, Function Interface hoặc các cấu trúc dữ liệu được quản lý bởi từng Module để hạn chế việc truy cập trực tiếp đến trạng thái dùng chung.

14.5. Nhầm lẫn Static Storage Duration và Internal Linkage

Không phải cứ một biến có Static Storage Duration thì nó đều có Internal Linkage. 

/* File Scope */
int global_value;

/* Static Storage Duration + External Linkage */

/* File Scope */
static int private_value;

/* Static Storage Duration + Internal Linkage */

void process(void)
{
    /* Block Scope */
    static int call_count;

    /* Static Storage Duration + No Linkage */
}

Đây là ba trường hợp khác nhau dù cả ba đối tượng đều có Static Storage Duration.

15. Best Practices khi quản lý biến trong C Embedded

Khi phát triển Firmware, lập trình viên nên áp dụng một số nguyên tắc sau để quản lý dữ liệu rõ ràng và giảm sự phụ thuộc giữa các Module:

  • Scope Management: ưu tiên khai báo biến ở phạm vi nhỏ nhất đáp ứng yêu cầu của chương trình.
  • Static Local Variable: sử dụng khi cần lưu trạng thái qua nhiều lần gọi Function nhưng không cần công khai Identifier.
  • Internal Linkage: sử dụng static cho các biến và Function chỉ phục vụ nội bộ một Translation Unit.
  • External Linkage: chỉ công khai những Function hoặc dữ liệu thực sự cần được sử dụng bởi Module khác.
  • extern Declaration: đặt các khai báo dùng chung trong Header File và chỉ định nghĩa đối tượng tại một Source File phù hợp.
  • Lifetime Management: không truy cập một đối tượng sau khi Lifetime của nó đã kết thúc.
  • Global Variable Management: tránh tạo quá nhiều trạng thái Global không cần thiết.
  • Code Readability: tránh Shadowing không cần thiết và sử dụng tên biến có ý nghĩa rõ ràng.

Tóm tắt

Scope, Lifetime và Storage Duration là ba khái niệm quan trọng giúp lập trình viên hiểu cách biến và đối tượng được quản lý trong C.

Scope xác định phạm vi mà Identifier có thể được sử dụng trong mã nguồn. Các loại Scope chính bao gồm Block Scope, File Scope, Function Prototype Scope và Function Scope.

Lifetime là khoảng thời gian một đối tượng thực sự tồn tại trong chương trình. Trong khi đó, Storage Duration mô tả cơ chế duy trì vùng nhớ của đối tượng. C có bốn loại Storage Duration chính: Automatic, Static, Thread và Allocated.

Các từ khóa auto, static và extern giúp điều chỉnh những đặc tính liên quan đến việc khai báo và liên kết Identifier. Đặc biệt, static có ý nghĩa khác nhau tùy thuộc vào vị trí khai báo: Static Local có Block Scope, Static Storage Duration và No Linkage; Static Global có File Scope, Static Storage Duration và Internal Linkage.

External Linkage cho phép các Source File khác tham chiếu đến cùng một biến hoặc Function thông qua những khai báo tương ứng. Ngược lại, Internal Linkage giới hạn việc liên kết trong một Translation Unit.

Hiểu rõ những khái niệm này giúp lập trình viên quản lý biến hiệu quả, tổ chức các Module tốt hơn, hạn chế lỗi liên quan đến Lifetime và xây dựng phần mềm Embedded có cấu trúc rõ ràng, dễ bảo trì.
